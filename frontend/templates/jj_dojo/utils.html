Shared utilities

The small helpers in src/utils/: a map and a set that compare keys by value, the exhaustiveness checks, disposal of a list of disposables, and relative timestamps.

In short: JavaScript's Map and Set compare object keys by identity, so two equal vscode.Uris are different keys. HashMap and HashSet key on toString() instead. dispose disposes everything in an array and empties it. check.ts and time.ts just re-export the commit graph's own copies, which give compile-time exhaustive switch checks and Mercurial-style "5 minutes ago" strings. Only HashMap and dispose are imported anywhere outside the directory at this pin.

2. HashMap

A thin wrapper over Map<string, [Key, Value]>. Every operation calls key.toString() and uses the result as the real key. The original key object is stored next to the value so keys() and entries() can hand it back (source). Two keys are "equal" exactly when their strings are.

3. HashSet

A HashMap<Key, void> with set-shaped methods: add, has, delete, clear, size(), keys(), and [Symbol.iterator], so it can be used directly in for … of. The constructor adds each element of an optional iterable (source). It has no values, entries or forEach.

4. check: exhaustiveness helpers

Re-exported unchanged from the commit graph (source). Each helper takes a value whose type should already have been narrowed to never (or to an explicitly allowed type). Adding a new enum or union member then turns every unhandled switch into a compile error.

5. dispose

dispose(disposables) calls dispose() on each element in order, then sets the array's length to 0 so the same array can be reused or disposed again harmlessly (source). If one dispose() throws, the loop stops: the remaining elements aren't disposed and the array isn't emptied.

6. time: relative timestamps

age(unixSeconds) deliberately mirrors Mercurial's age template filter, so the graph reads like hg xl (source). The graph webview shows it through jj-time-ago-text (graph-webview).

  1. The exact same second is now.
  2. More than 30 years in the future is in the distant future. More than two years in the past is Date.toDateString(), for example Tue Mar 03 2020.
  3. Otherwise it picks the largest unit that fits at least twice: years of 365 days, months of 30 days, weeks, days, hours, minutes, seconds (table). So 90 seconds is 90 seconds ago, and 13 days is 13 days ago, not 1 week ago. A future date gets … from now.

8. Loose ends at this pin

  • Unused exports. HashSet and the check and time re-exports have no importers.
  • toString is not checked. Every object has one, so the type system accepts a key whose toString is the default [object Object]. All such keys would collapse into one entry. vscode.Uri, the only key type used, has a real one.
  • ValueIterator.next() at the end. It reads next.value[1] without the ?. that KeyIterator has, so calling next() by hand past the last value throws a TypeError (source). for … of isn't affected.
  • Shared tuples. entries() yields the stored [key, value] arrays, so a caller that mutates one changes the map without updating its string key.
  • HashSet's iterator comment still calls it "the ImmutableSet" (source).

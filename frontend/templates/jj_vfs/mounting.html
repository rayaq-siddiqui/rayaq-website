Starting and mounting

Everything jjfsd does before the first kernel request and after the last one lives in one 81-line file: parse two arguments, load the repository once, hand the file system to fuser, then wait for a signal.

In short: jjfsd <MOUNTPOINT> <WORKSPACE_ROOT> sets up logging, builds a read-only mount configuration named jjfs, starts a tokio runtime, loads the workspace and the repository at its current operation, and wraps it in the only path mapper there is. It mounts with fuser::spawn_mount, which serves requests on a background thread, and blocks the main thread until SIGINT, SIGTERM or SIGHUP. Returning from main drops the session handle, and that drop is what unmounts. Every failure is a panic, and the repository is never reloaded: the mount shows the repo as it was when it started.

This page covers src/main.rs, the crate's only binary. What it builds is described in the namespace, the virtual file layer and the FUSE adapter.

Arguments

The arguments are positional and read straight from std::env::args(); there is no argument-parsing crate and no flags. With fewer than two, it prints Usage: <program> <MOUNTPOINT> <WORKSPACE_ROOT> to stderr and exits with status 1. Extra arguments are ignored. The mount point stays a &String; the workspace root becomes a Path (main.rs). Neither is checked here: a missing directory surfaces later as a workspace or mount panic.

Logging

tracing_subscriber's formatting subscriber writes to stdout. Its filter comes from the RUST_LOG environment variable, which EnvFilter::builder() reads by default; the default directive is INFO, and from_env_lossy skips directives it can't parse instead of failing (main.rs). The FUSE methods carry #[tracing::instrument(level = "debug", …)] (for example fuse.rs), so RUST_LOG=debug logs every kernel request. The two println! lines, "Mounting JjVfs at …" and "Received …, unmounting...", bypass tracing.

JjFuse also asks for two capabilities in its init callback, FUSE_PARALLEL_DIROPS and FUSE_ASYNC_READ, ignoring whether the kernel grants them (fuse.rs).

The tokio runtime

Runtime::new() builds tokio's default multi-threaded runtime (the crate enables rt-multi-thread, signal, macros and time). rt.enter() makes it the current runtime for the main thread for as long as _guard lives, which is all of main. The runtime is used three ways: to block on loading the repo, to block on the signal wait, and, through the Handle cloned into JjFuse, to run every FUSE request (main.rs, fuse.rs; see the async bridge).

If the operation log has divergent heads, load_at_head merges them in a transaction and writes the merged operation to the op store without publishing it as a new head (repo.rs). That's the only way mounting can write to the repository. jjfsd never snapshots the working copy, so files edited in a workspace but not yet snapshotted by a jj command don't appear in its @ commit.

The resulting Arc<ReadonlyRepo> goes into AllCommitsPathMapper::new, the only PathMapper implementation in the crate, and that into PathMappedVfs::new. There is no option to choose another mapper; changing the layout means changing this line (main.rs).

spawn_mount

spawn_mount runs Session::new and then Session::spawn (lib.rs). Session::new mounts (session.rs). On Linux, without fuser's libfuse features, which this crate doesn't enable, fuser uses its pure-Rust mount code (build.rs): it tries the mount system call first and, on EPERM (the usual case for a non-root user), runs the setuid fusermount3 or fusermount helper (fuse_pure.rs, L493). spawn then starts a thread named fuser-bg that runs the request loop, and returns a BackgroundSession holding that thread's handle and the mount (session.rs, L560). main keeps it in _session; the underscore keeps it alive (a bare _ would drop it at once).

Threads after mounting

Signals and unmounting

wait_for_shutdown installs tokio handlers for SIGINT, SIGTERM and SIGHUP and waits in tokio::select! for the first, printing which one arrived (main.rs). It is #[cfg(unix)] with no other definition, so the binary only builds on Unix. When it returns, so does main, and locals drop in reverse order: _session first, while the runtime is still alive.

Dropping the BackgroundSession drops its Mount, whose Drop unmounts (mod.rs). The pure-Rust unmount skips a mount that is already gone, calls umount, and on EPERM falls back to fusermount -u; a failure is only logged as a warning (fuse_pure.rs). main doesn't call umount_and_join, so the fuser-bg thread isn't joined; the process just exits.

Without AutoUnmount, nothing unmounts if the process dies without running destructors, as with SIGKILL or any signal other than the three handled. The mount point is then left for the user to clear with fusermount -u.

Limitations

  • The repository is loaded once. New commits and operations after the mount starts never appear; see the namespace's snapshot.
  • Only jj-lib's default config is used, so user and repo settings are ignored.
  • Every error is a panic with a fixed message; there are no exit codes beyond the usage error's 1.
  • The layout, mount options, thread count and access mode are all fixed in code; there are no flags.
  • Unix only, and no automatic unmount if the process is killed.
  • main itself has no test. test_vfs_mount repeats its middle steps, mounting with the same options (named jjfs_test) over a temporary repo and reading through the mount, then unmounts by dropping the session; it needs FUSE on the machine running the tests (vfs_integration.rs).

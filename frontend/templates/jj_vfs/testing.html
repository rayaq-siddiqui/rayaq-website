Tests and CI

Thirty unit tests, two integration tests and four CI jobs. Most of the tests run against a real jj repository that is built in a temporary directory for each test.

In short: setup_test_repo creates a real jj workspace in a temporary directory. It writes one commit with two files and a symlink, makes that commit the working-copy commit, and reloads the repository the same way jjfsd does. The unit tests use that repository to check the path mapper, the commits/ and workspaces/ listings, and commit trees. The inode map and PathMappedVfs are tested with hand-built data instead. One integration test reads the commit through the virtual file layer. The other mounts the commit for real through FUSE and reads it with std::fs. Nothing tests src/fuse.rs or src/main.rs directly. CI runs rustfmt, clippy, cargo check and cargo test on pull requests and merge-queue groups. It does not run on pushes.

Run everything with cargo test --all-targets --all-features, the command CI uses. At the pinned commit, on a Linux machine that has FUSE, it reports 30 unit tests and 2 integration tests passing. The library target has 30 tests, the binary has none, and vfs_integration has 2. What the tests exercise is described in inodes, the virtual file layer, the namespace, commit trees and mounting.

The throwaway repository

src/test_helpers.rs has two functions. The library pulls it in only for tests, through #[cfg(test)] pub mod test_helpers; in lib.rs. The integration test cannot reach a cfg(test) module of the library, so it compiles the same file a second time with #[path = "../src/test_helpers.rs"]. A TODO there suggests a test-helpers Cargo feature as the cleaner fix. tempfile is a dev-dependency only.

What each test reaches

Arrows show which code each test reaches. The mapper, the two listings and the commit-tree tests all run on the repository from setup_test_repo. The InodeMap and PathMappedVfs unit tests use hand-built data, and InodeMap is used only by JjFuse. That makes the mounted test the only one that runs every layer together.

Integration tests

tests/vfs_integration.rs uses the crate as an outside user would. Both tests build the repository with setup_test_repo and wrap it in AllCommitsPathMapper and PathMappedVfs, the same stack main builds.

test_vfs_mount A real mount. fuser::spawn_mount runs JjFuse on a temporary directory with RO and FSName("jjfs_test"), using the multi-threaded test runtime's handle. It polls up to 20 × 50 ms for commits/<hex> to appear. Then it checks that std::fs reads file1.txt in full, that a 5-byte read_exact returns "hello", that dir/file2.txt reads correctly, and that symlink is a symlink pointing to file1.txt. Dropping the session at the end unmounts. L92

The mounted test is the only place where JjFuse, InodeMap and fuser's mount path run together. A comment says the partial read guards against returning more data than was requested, which FUSE rejects. The test needs /dev/fuse and permission to mount. Without them, spawn_mount fails and the test panics, because the test is not skipped when FUSE is missing.

CI workflow

.github/workflows/ci.yml runs on pull_request and merge_group only, so a direct push to the default branch is not checked. Runs for the same PR or merge group cancel each other, and the workflow token gets permissions: {}. Every action is pinned by commit SHA, and checkout uses persist-credentials: false.

rustfmt settings

rustfmt.toml sets edition = "2024" and max_width = 100. It also sets wrap_comments, format_strings, error_on_line_overflow, group_imports = "StdExternalCrate" and imports_granularity = "Item". Those five are unstable rustfmt options, which is why the format job uses nightly. imports_granularity = "Item" gives every imported item its own use line, as at the top of test_helpers.rs.

Limitations

  • src/fuse.rs has no unit tests. Its handlers (attribute building, inode allocation, read offsets, error-to-errno mapping) are exercised only through the one mounted test, and only on its success path.
  • src/main.rs, static_directory.rs, jj_error.rs and virtual_file.rs have no tests of their own.
  • The fixture has no conflicts, executable files, submodules or extra workspaces, so the paths for those cases (see commit trees) are untested.
  • test_all_commit_trees_mapper_invalid_commit_id tests an unknown top-level name, not an invalid id under commits/.
  • CI does not run on pushes, and whether the mounted test can mount on GitHub's runners is unverified.

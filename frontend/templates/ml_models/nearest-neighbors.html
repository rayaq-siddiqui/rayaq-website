Nearest neighbors

The simplest learner there is: keep every training point, and answer a question about a new point by looking at the training points closest to it. This page covers the k-NN vote and its weights, the choice of distance and of k, why distances stop meaning much in high dimensions, and how KD trees and ball trees find neighbors without measuring against every point.

Problem

Most models compress the training set into parameters: a line, a tree, a network. That compression is an assumption about the shape of the answer. Sometimes we would rather not assume a shape at all and just say "points that look alike should get alike labels". Nearest neighbors does exactly that. It needs a way to say what "look alike" means (a distance), a rule to turn nearby labels into a prediction, and a way to find nearby points fast once the training set has millions of rows.

Intuition

To label a new point, find the k training points closest to it and let them vote. With k = 1 the prediction copies the single closest point, so the decision boundary bends around every training example, noise included. Larger k averages over a wider neighborhood, giving smoother boundaries but blurring small regions of the other class. This is the bias-variance tradeoff with one knob. Training is free (store the data); all the work happens at prediction time.

Mechanics

Distance

Almost everything uses the Minkowski distance with exponent p:

dp(a, b) = (Σj |aj − bj|p)1/p

p = 2 is Euclidean distance (scikit-learn's default, metric="minkowski", p=2), p = 1 is Manhattan distance, and p → ∞ is Chebyshev distance, the largest single-coordinate gap. For p ≥ 1 these are true metrics (the triangle inequality holds), which is what lets trees prune. Each coordinate contributes on its own scale, so a feature measured in thousands swamps one measured in fractions. That is why k-NN almost always sits behind standardization. For text and embeddings, cosine distance on normalized vectors is more common. It ranks neighbors the same way as Euclidean distance on unit vectors (see vectors and dot products).

Vote and weights

Given the k nearest training points with labels yi and distances di, a classifier returns the label with the largest total weight, and a regressor returns the weighted mean:

ŷ = argmaxc Σi wi·[yi = c]     ŷ = Σi wi yi / Σi wi

With weights="uniform", every wi = 1. With weights="distance", scikit-learn's _get_weights sets wi = 1/di. If the query lands exactly on one or more training points, those points get weight 1 and the rest get 0, which avoids dividing by zero. predict_proba returns each class's share of the total weight. When two labels tie on uniform votes, predict takes the mode, which picks the class that sorts first. The docstring also warns that when neighbors k and k+1 are equally far away but have different labels, the result depends on the order of the training data.

Finding the neighbors

Brute force measures the query against all n training points: O(n·d) per query, and trivially parallel. Trees spend O(n log n) once, at fit time, so that most queries can skip most of the data.

  • A KD tree splits the node's points at the median of the dimension with the largest spread (find_node_split_dim, then partition_node_indices), and stores each node's bounding box. Nodes live in a flat array, and node i's children are 2i+1 and 2i+2.
  • A ball tree uses the same splitting, but each node stores a centroid and a radius, the largest distance from the centroid to any of the node's points. Its lower bound, max(0, d(q, centroid) − radius), works for any true metric, not just axis-aligned ones.

Before building, the tree fixes its depth: n_levels = int(log2(max(1, (n − 1) / leaf_size)) + 1) and n_nodes = 2**n_levels − 1. Splitting at the median then leaves every leaf with between leaf_size and 2·leaf_size points. The query is depth-first with a max-heap of the best k distances so far. A node whose lower bound already exceeds the k-th best distance is trimmed with all its points. A leaf is scanned point by point. Otherwise the query visits the nearer child first, so the heap tightens early and prunes more. Internally the KD tree compares "reduced" distances (squared Euclidean, which keeps the same order) to skip square roots.

The left half splits on y at 4 and the right half at 7, so each leaf box shown here is the tight box around its own four points, which is what init_node stores and min_rdist measures against.

Choosing k. Leave-one-out error on the 16 points: predict each point from the other 15.

k = 1 overfits: two points near the boundary copy a neighbor from the other class. Errors are lowest at 3 and 5. At k = 15 every point is wrong. With one point held out, its own class has 7 left and the other class has 8, so the vote always goes to the other class. A large k turns k-NN into "predict the majority of the rest". In practice, pick k with cross-validation, and prefer odd k for two classes to avoid ties.

Implementation

from sklearn.model_selection import GridSearchCV
from sklearn.neighbors import KNeighborsClassifier, KDTree
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

# Scale first: every feature contributes to the distance on its own scale.
model = make_pipeline(StandardScaler(), KNeighborsClassifier())
search = GridSearchCV(
    model,
    {"kneighborsclassifier__n_neighbors": [1, 3, 5, 7, 9, 15],
     "kneighborsclassifier__weights": ["uniform", "distance"]},
    cv=5,
)
search.fit(X_train, y_train)
proba = search.predict_proba(X_test)        # (m, n_classes), vote shares

# The tree on its own, for retrieval.
tree = KDTree(X_train, leaf_size=30)
dist, ind = tree.query(X_test[:3], k=5)     # each (3, 5), nearest first

Fitting the scaler inside the pipeline keeps the test folds out of the means and variances (see data leakage). The tree is pure Cython with no learned parameters. Its only choices are the metric and leaf_size, which trades tree depth against per-leaf brute force. Larger leaf_size means a shallower tree and more scanning, smaller means more pruning overhead. Results are identical either way.

Tradeoffs

  • No training, slow prediction. Fit is cheap, but the model is the data: memory grows with n, and each query costs anywhere from O(log n) (a tree in low dimension) to O(n·d) (brute force).
  • Flexible boundaries. k-NN can draw any shape of class region and adapts as data is added, but small k memorizes noise (overfitting) and large k washes out minority regions.
  • Everything rides on the distance. Unscaled or irrelevant features distort neighborhoods. k-NN has no built-in feature selection, so one noisy column hurts every prediction.
  • Exact trees fade with dimension. As distances concentrate, box and ball bounds stop ruling nodes out, which is why "auto" switches to brute force above 15 features. Embedding search at hundreds of dimensions and millions of vectors uses approximate indexes instead. They trade a little recall for orders of magnitude in speed.
  • Calibration. predict_proba can only take values j/k with uniform weights, so with k = 5 every probability is a multiple of 0.2.
Why does k-NN need feature scaling while a decision tree does not?

A tree compares one feature at a time against a threshold, so rescaling a feature just moves the threshold. k-NN adds all features into one distance, so a feature with a larger numeric range dominates that sum.

Why can a KD tree prune when k = 1 but not when k = 5 in the worked example?

A node is trimmed only when its box is farther away than the current k-th best distance. With k = 1 that distance is 1.02, and three leaf boxes lie beyond it. With k = 5 it is 2.33, which reaches into every box, so every leaf must be scanned.

What does weights="distance" predict for a query that exactly matches a training point?

The matching point (or points) gets weight 1 and every other neighbor gets weight 0, so the prediction is that point's label or target, not an average.

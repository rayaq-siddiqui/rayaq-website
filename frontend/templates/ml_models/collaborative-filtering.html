Collaborative filtering

Recommend from behaviour alone: people who agreed with you before will probably agree again. This page builds the user–item matrix, predicts missing ratings from similar users, then factorizes the matrix into user and item vectors trained only on the ratings that exist. It works through a five-user example by hand, explains implicit feedback and cold start, and shows why scikit-learn's NMF, which treats missing entries as zeros, is the wrong tool for ratings.

Problem

A shop, a music app or a film site has millions of users and items and a log of who interacted with what: star ratings, plays, purchases, clicks. Arrange it as a matrix R with one row per user and one column per item. Nearly every cell is empty, because each user has touched a tiny fraction of the catalogue. The job is to fill in the empty cells well enough to rank, for each user, the items they haven't seen.

We often know nothing about the items' content, or don't trust it, and we have no labelled features about users. Collaborative filtering (CF) uses only the matrix: if two users rated the same items the same way, each is a good guide to what the other will like. Intuition

There are two families of CF, and they make the same bet in different ways:

  • Neighbourhood methods keep the matrix as it is. To predict {{ names[ben.user] }}'s rating of {{ titles[ben.item] }}, find the users most similar to {{ names[ben.user] }} (by how they rated the films both have seen) and average what they gave {{ titles[ben.item] }}. Item-based neighbourhoods do the same over columns: films that were rated alike are recommended alike.
  • Latent factor models (matrix factorization) assume the matrix is close to low rank: a few hidden dimensions, such as "likes heists" and "likes horror", explain most of the ratings. Each user gets a short vector pu, each item a vector qi, and the predicted rating is their dot product. These vectors are embeddings learned from nothing but the matrix.

The crucial detail in both is that empty cells are unknown, not zero. A user who hasn't rated a film hasn't said they hate it. Fitting the factors only on observed cells is what lets the model predict the rest.

Mechanics

Neighbourhoods

Users rate on different scales: one person's 3 is another's 4. So centre each user's ratings on their own mean r̄u first, then measure similarity with the cosine of the centred vectors over the items both rated (this is Pearson correlation restricted to co-rated items):

s(u, v) = Σi ∈ Iuv (rui − r̄u)(rvi − r̄v) / ( ‖ru − r̄u‖ · ‖rv − r̄v‖ )

The prediction starts from the user's own mean and adds the similarity-weighted deviations of the k most similar users who rated the item:

r̂ui = r̄u + Σv ∈ Nk(u, i) s(u, v)(rvi − r̄v) / Σv |s(u, v)|

This needs no training, explains itself ("because Ana and Eli liked it"), and updates the moment a new rating arrives. It costs a similarity per pair of users, which is why large systems use item-item neighbourhoods (items are fewer and their similarities change slowly) and precompute them.

Matrix factorization and its loss

Give each user a vector pu ∈ ℝk and each item qi ∈ ℝk. With Ω the set of observed (user, item) pairs, minimize

L = Σ(u,i) ∈ Ω (rui − μ − bu − bi − pu · qi)² + λ (‖pu‖² + ‖qi‖² + bu² + bi²)

μ is the global mean, bu and bi are a user's and an item's offsets from it (a generous rater, a beloved film), and the dot product carries the interaction: how this user feels about this item beyond those offsets. The L2 term λ is not optional. There are (users + items) · k parameters, often as many as there are ratings, so without it the factors simply memorize Ω.

Two ways to minimize it:

  • SGD. For each observed rating, compute the error e = r − r̂ and step pu += η(e qi − λpu), qi += η(e pu − λqi). Simple, and what a PyTorch model with an embedding table does.
  • Alternating least squares (ALS). The loss is not convex in (P, Q) together, but with Q fixed it is an independent ridge regression for every user: pu = (QuTQu + λI)−1 QuT ru, where Qu holds only the items user u rated. Then fix P and solve every item the same way. Each half-step can only lower L, the solves are embarrassingly parallel, and there is no learning rate.

Implicit feedback

Most real signals are not ratings but events: plays, views, purchases. There are no negatives, only "did" and "didn't (yet)". Hu, Koren and Volinsky turn each count rui into a binary preference pui = [rui > 0] and a confidence cui = 1 + α rui, then fit over all cells:

L = Σu, i cui (pui − xu · yi)² + λ (Σ‖xu‖² + Σ‖yi‖²)

Here zeros are in the loss, deliberately, but with confidence 1, while anything the user actually did weighs 1 + α times its count. Summing over every cell looks impossible at scale; the trick is that YTCuY = YTY + YT(Cu − I)Y, where YTY is shared by all users and Cu − I is non-zero only on the items user u touched. Each ALS solve still costs only that user's interactions.

Cold start

A new user or a new item has no row or column to learn from, so neither family can say anything personal about it. The usual fallbacks: show new users popular or highly rated items (μ + bi), ask a few onboarding questions, or switch to content features (genre, text, image embeddings) that exist from day one. Hybrid models, such as two-tower models with ID and content features in each tower, blend the two as interactions accumulate.

Non-negative matrix factorization

NMF factors a non-negative matrix X ≈ WH with W, H ≥ 0, which makes the factors additive parts (topics, tastes) that are easy to read. scikit-learn's NMF minimizes 0.5‖X − WH‖²Fro plus L1/L2 penalties scaled by the matrix's dimensions. Its multiplicative update for the Frobenius loss is H ← H ⊙ (WTX) / (WTWH), and the mirror image for W. Each factor stays non-negative because it is only ever multiplied by a non-negative ratio.

The catch for recommendation: X is a whole matrix, sparse or dense, and every cell is in the loss. An unrated film is a stored or implicit zero, so NMF treats "hasn't seen it" as "rated it 0" and drags those predictions toward zero. That is fine for counts where absence really means zero, such as word counts in documents, and wrong for explicit ratings.

Implementation

Matrix factorization with biases in PyTorch: two nn.Embedding tables trained on (user, item, rating) triples, so only observed cells are ever in the loss. With sparse=True each step's gradient touches only the batch's rows, which needs one of the optimizers the docstring lists, such as SparseAdam: 

import torch
from torch import nn

class MF(nn.Module):
    def __init__(self, n_users, n_items, k=64):
        super().__init__()
        self.p = nn.Embedding(n_users, k, sparse=True)
        self.q = nn.Embedding(n_items, k, sparse=True)
        self.bu = nn.Embedding(n_users, 1, sparse=True)
        self.bi = nn.Embedding(n_items, 1, sparse=True)
        for e in (self.p, self.q):
            nn.init.normal_(e.weight, std=0.01)   # default N(0, 1) is far too large
        for e in (self.bu, self.bi):
            nn.init.zeros_(e.weight)
        self.mu = nn.Parameter(torch.zeros(()))

    def forward(self, u, i):
        return (self.mu + self.bu(u).squeeze(-1) + self.bi(i).squeeze(-1)
                + (self.p(u) * self.q(i)).sum(-1))

model = MF(n_users, n_items)
model.mu.data.fill_(ratings.mean())
sparse = [model.p.weight, model.q.weight, model.bu.weight, model.bi.weight]
opt_sparse = torch.optim.SparseAdam(sparse, lr=1e-2)
opt_dense = torch.optim.Adam([model.mu], lr=1e-2)
lam = 1e-4

for u, i, r in loader:                     # observed triples only
    pred = model(u, i)
    reg = lam * (model.p(u).pow(2).sum() + model.q(i).pow(2).sum())
    loss = (pred - r).pow(2).mean() + reg / len(r)
    opt_sparse.zero_grad(); opt_dense.zero_grad()
    loss.backward()
    opt_sparse.step(); opt_dense.step()

The L2 term is applied to the rows in the batch, not via weight_decay, which would shrink every row on every step (and SparseAdam doesn't support it). For implicit data, use an ALS library built on the confidence trick, or train with sampled negatives as in two-tower models.

If you reach for scikit-learn, remember what NMF fits: a scipy.sparse rating matrix is accepted, but its missing entries are zeros in the loss. That suits counts (topics in a document-term matrix) and not explicit ratings. 

from sklearn.decomposition import NMF

nmf = NMF(n_components=2, init="nndsvda", solver="mu", max_iter=300)
W = nmf.fit_transform(play_counts)   # [users, k]: zeros here mean "zero plays", which is true
H = nmf.components_                  # [k, items]

Tradeoffs

  • Neighbourhoods vs factors. Neighbourhoods are explainable, training-free and instantly fresh, but noisy when users share few items, and quadratic in users or items. Factors generalize across the sparsity (two users need not share a single item to end up close in factor space) and serve as a fast dot product, but must be retrained or folded in for new data.
  • ALS vs SGD. ALS has no learning rate, parallelizes per row and handles the all-cells implicit loss exactly. SGD is simpler, fits any differentiable model (side features, deep towers) and streams over huge logs.
  • Rank k and λ. Larger k fits more taste dimensions and overfits faster; λ trades the two and must be tuned on held-out ratings, split by time if you can, since the future is what you'll predict.
  • RMSE vs ranking. Predicting stars well is not the same as ranking the top 10 well. Many systems train on implicit data and evaluate with ranking metrics, and add a learning-to-rank stage on top.
  • Popularity and feedback loops. CF recommends what similar people consumed, which over time amplifies what is already popular and starves new items; cold-start content features and some exploration counter it.
  • NMF. Non-negative parts are interpretable, but the default scikit-learn implementation's zeros-are-observed loss makes it a poor fit for explicit ratings.
Why centre each user's ratings before computing similarity?

A harsh rater's 3 can mean what a generous rater's 4 means. Centring compares how each user deviates from their own habit, not their raw scale.

Why can each ALS half-step be solved in closed form?

With the item vectors fixed, the loss for one user is a sum of squared errors linear in that user's vector plus an L2 term: a ridge regression on the items they rated.

In the example, why does NMF predict {{ n(ben.nmf, 2) }} for a rating whose truth is {{ ben.truth }}?

The blank cell was filled with 0 and is in NMF's loss, so the factorization is pulled toward reproducing that 0.

How does the implicit-feedback loss avoid touching every cell for every user?

YᵀCuY = YᵀY + Yᵀ(Cu − I)Y: YᵀY is computed once per sweep, and the correction only involves the items the user interacted with.

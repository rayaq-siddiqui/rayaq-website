Comparing models: confidence intervals and significance tests

Model A scores {{ pct(ex.acc_a) }} on a test set and model B scores {{ pct(ex.acc_b) }}. Is A better, or did it get a luckier test set? This page puts error bars on a single score, shows why comparing two models on the same rows is far more sensitive than comparing two separate scores, works McNemar's test, a paired bootstrap and a sign-flip permutation test on one example, corrects the t-test for overlapping cross-validation folds, and handles comparing many variants at once.

Problem

Every number on the classification metrics page is computed from a finite test set, so it is an estimate with sampling error. Draw another {{ ex.n }} rows from the same distribution and the accuracy moves by a few points even though the model has not changed. A {{ pct(ex.acc_a - ex.acc_b, 0) }} gap between two models can be that noise.

The questions this page answers are practical. How wide is the error bar on one score? When two models are scored on the same rows, which test should you use, and why does the obvious one throw away most of the information? Can you run a t-test on cross-validation folds? What happens when you compare ten variants and keep the best? And how many test rows do you need before a one-point gain is detectable at all?

Intuition

Two models scored on the same test set mostly agree. Both get the easy rows right and both get the hardest rows wrong; those rows say nothing about which model is better. All of the evidence is in the rows where they disagree. In this page's example, {{ tb.both + tb.neither }} of {{ ex.n }} rows are agreements and only {{ ex.discordant }} are disagreements: A alone is right on {{ tb.a_only }}, B alone on {{ tb.b_only }}.

If the two models were equally good, each disagreement would be a fair coin: as likely to favour A as B. So the comparison reduces to asking whether {{ tb.a_only }} heads in {{ ex.discordant }} flips is a surprising result for a fair coin. It is (p ≈ {{ n(ex.mcnemar_exact, 4) }}). Comparing the two accuracies as if they came from separate test sets instead treats all the shared easy and hard rows as independent noise, inflates the standard error by {{ n(ex.unpaired.se / ex.paired.se, 1) }}×, and finds nothing (p ≈ {{ n(ex.unpaired.p, 2) }}).

Mechanics

Error bars on one score

Accuracy on n independent test rows is a mean of 0/1 outcomes, so the number correct is Binomial(n, p) and the standard error of the accuracy is √(p(1 − p)/n) (the variance of a Bernoulli mean, from expectation and variance). The textbook (Wald) 95% interval is p̂ ± 1.96 · √(p̂(1 − p̂)/n). It is fine when np̂ and n(1 − p̂) are both large, but near 0 or 1 it is too narrow and can leave [0, 1]: with 1 error in 20 rows it gives a negative lower bound for the error rate. The Wilson interval inverts the score test instead:

centre = (p̂ + z²/2n) / (1 + z²/n), half-width = z · √(p̂(1 − p̂)/n + z²/4n²) / (1 + z²/n)

It always stays inside [0, 1], pulls the centre slightly towards ½, and has close to nominal coverage even for small n. The half-width shrinks like 1/√n, so quartering the error bar needs sixteen times the rows. The uncertainty page gets the same kind of interval by resampling for metrics with no closed form.

Paired versus unpaired

Write di = 1[A right on row i] − 1[B right on row i], which is +1 on the b rows where only A is right, −1 on the c rows where only B is right, and 0 elsewhere. The accuracy difference is the mean of d, and its standard error comes from the variance of d:

Var(acc A − acc B) = Var(A)/n + Var(B)/n − 2 Cov(A, B)/n

The unpaired formula drops the covariance term, which is the right thing only for two separate test sets. On one shared test set the models' errors are strongly positively correlated, so the covariance term is large and the paired standard error is much smaller. Pairing is free: it uses the same predictions, just without throwing away which row each one came from. Never compare two models on different test sets, or on differently shuffled splits, if you can avoid it.

McNemar's test

Under the null hypothesis that A and B have the same accuracy, a disagreement is equally likely to go either way, so given b + c disagreements, b ~ Binomial(b + c, ½). The exact McNemar test is the two-sided binomial test:

p = min(1, 2 · Σi ≤ min(b, c) C(b + c, i) / 2b+c)

The classic large-sample version uses the statistic (|b − c| − 1)² / (b + c), compared with χ² with one degree of freedom; the −1 is a continuity correction. Use the exact test when b + c is below about 25, and it is never wrong to use it. The agreement counts appear nowhere: a million rows that both models get right change neither the statistic nor the p-value, only the size of the effect you report.

The paired bootstrap

McNemar answers "is there a difference?" but a decision usually needs "how big, give or take?" Resample the test rows with replacement, recompute both models' metrics on the same resampled rows, and record the difference. The 2.5th and 97.5th percentiles of those differences are a 95% percentile interval. Resampling rows, not each model separately, is what keeps it paired. This works for any metric, including F1, AUC and BLEU, where there is no tidy binomial, and it is how most published "± CI" figures on a single benchmark are made. Resample whatever unit is independent: whole documents, users or conversations rather than tokens or turns.

Permutation tests, and what scikit-learn's tests

A paired permutation test asks: if the model labels were exchangeable on every row, how often would a random relabelling produce a difference as large as the observed one? Swapping A and B on a row flips the sign of di, so the test draws random signs for every row and recomputes |Σ d|. Rows with d = 0 are unchanged by a flip, so only the b + c discordant rows matter, and the permutation distribution of their sum is exactly the Binomial(b + c, ½) of the exact McNemar test. For accuracy the two tests are the same test; for other metrics the sign-flip version still works and McNemar does not apply.

scikit-learn's permutation_test_score is a different test. It shuffles y, refits the estimator under cross-validation for each shuffle, and reports (#{permuted scores ≥ observed} + 1) / (n_permutations + 1). That tests one model against chance, "does this model find any real dependence between X and y?", not one model against another.

Comparing cross-validation scores

With k-fold cross-validation both models get k scores on the same folds, so the natural move is a paired t-test on the k per-fold differences, with standard error s/√k. That is wrong, and anti-conservative. Each pair of training sets shares (k − 2)/(k − 1) of its rows, so the fold differences are positively correlated, and s/√k underestimates the real variability of the mean. Nadeau and Bengio's corrected resampled t-test replaces 1/k with 1/k + ntest/ntrain:

t = mean(d) / √((1/k + ntest/ntrain) · s²), with k − 1 degrees of freedom

For 10-fold CV, ntest/ntrain = 1/9, so the variance term more than doubles and the standard error grows by about {{ n(cv.inflation, 2) }}×. The same correction applies to repeated CV (r × k folds, with 1/(rk) + ntest/ntrain). Dietterich's 5 × 2 cv test is an older alternative: five repetitions of 2-fold CV, a variance estimate from each repetition, and a t-statistic with 5 degrees of freedom. Both are approximations; the point of both is that k fold scores are not k independent measurements.

For comparing algorithms across many datasets, use a Wilcoxon signed-rank test on per-dataset differences, or the Friedman test with a post-hoc test for more than two algorithms (Demšar).

Many comparisons

Test m variants at α = 0.05 each and, even if none is better, the chance that at least one looks significant is 1 − 0.95m: 40% for m = 10. Two standard fixes control that family-wise error rate:

  • Bonferroni. Reject only when p ≤ α/m. Simple, valid under any dependence, and conservative.
  • Holm. Sort the p-values from smallest; compare the i-th smallest with α/(m − i + 1) and stop at the first one that fails. It controls the same error rate under the same assumptions and rejects everything Bonferroni rejects, and sometimes more, so there is no reason to prefer Bonferroni.

The same arithmetic is why a leaderboard winner picked from dozens of hyperparameter runs overstates its true score, and why the test set should be touched once: every look you take and act on is another comparison.

How many test rows?

For a paired accuracy comparison, the standard error of the difference is roughly √(pdisc/n), where pdisc = (b + c)/n is the disagreement rate. To detect a true difference δ with a two-sided level α and power 1 − β you need

n ≈ ((z1−α/2 + z1−β) / δ)² · pdisc

With α = 0.05 and 80% power the constant is (1.96 + 0.84)² ≈ 7.85. Two similar models that disagree on 10% of rows need about 2,000 rows to detect a 2-point difference, and 8,000 for 1 point. Halving δ quadruples n. Run this before building a test set, not after.

from sklearn.model_selection import StratifiedKFold, cross_val_score

right_a = model_a.predict(X_test) == y_test
right_b = model_b.predict(X_test) == y_test

# McNemar, exact: only the discordant rows matter
b = int(np.sum(right_a & ~right_b))
c = int(np.sum(~right_a & right_b))
p_mcnemar = binomtest(b, b + c, 0.5).pvalue

# Paired bootstrap CI for the accuracy difference (same rows for both models)
rng = np.random.default_rng(0)
d = right_a.astype(float) - right_b.astype(float)
idx = rng.integers(0, len(d), size=(2000, len(d)))
diffs = d[idx].mean(axis=1)
ci = np.percentile(diffs, [2.5, 97.5])

# Corrected resampled t-test on paired CV folds
cv = StratifiedKFold(n_splits=10, shuffle=True, random_state=0)
fold_d = cross_val_score(model_a, X, y, cv=cv) - cross_val_score(model_b, X, y, cv=cv)
k = len(fold_d)
t_stat = fold_d.mean() / np.sqrt((1 / k + 1 / (k - 1)) * fold_d.var(ddof=1))
p_cv = 2 * student_t.sf(abs(t_stat), df=k - 1)

The fixed random_state on the splitter is what makes the two cross_val_score calls use identical folds; with shuffle=True and no seed the folds differ and the differences are no longer paired. For 10-fold CV, ntest/ntrain = 1/(k − 1), which is where the 1/(k − 1) comes from.

Tradeoffs

  • Exact versus approximate. Exact McNemar is valid at any size and costs nothing; the χ² form is a large-sample shortcut. The paired bootstrap is approximate and can undercover with few rows or heavily skewed metrics, but it gives an interval, which a p-value does not.
  • Significant is not important. With a million test rows a 0.05-point difference is significant and useless. Report the difference with its interval, then decide whether the low end of the interval is worth the cost of the switch.
  • The unit of independence. Every method here assumes independent rows. Tokens within a document, frames within a video and queries from one user are not; resample or permute at the level of the independent unit, or the intervals will be too narrow.
  • Test-set reuse. A test set used to pick among many models is no longer an unbiased estimate of the winner. Use validation data for selection and look at the test set once, or correct for every look.
  • Test-set error versus algorithm comparison. McNemar and the bootstrap compare two fitted models on this test set. Whether algorithm A beats algorithm B on new training data of this kind is a different question with extra variance from training, which is what the cross-validation tests try (imperfectly) to capture; Bengio and Grandvalet showed no unbiased estimator of k-fold CV variance exists.
Two models disagree on 8 rows: A is right on 7 of them, B on 1. Is that significant at 5%?

Exact McNemar: p = 2 · (C(8,0) + C(8,1)) / 2⁸ = 2 · 9/256 ≈ {{ n(9 / 128, 3) }}. No, despite the 7-to-1 split.

Adding 10,000 rows that both models get right: what happens to McNemar's p-value?

Nothing. It depends only on b and c. The accuracy difference shrinks because n grew, but the evidence about which model is better has not changed.

Why is a paired t-test on 10 CV folds anti-conservative?

The folds' training sets overlap by 8/9, so the per-fold differences are positively correlated and s²/k understates the variance of their mean. The corrected test adds ntest/ntrain to 1/k.

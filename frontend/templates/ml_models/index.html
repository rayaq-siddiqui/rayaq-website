Machine learning, from the math up

A reference for learning, and relearning, any part of machine learning: the math under it, how to split and score data, the classical models, neural networks, the Transformer and the language models built from it, generative models, retrieval, and the systems that train and serve them. Every code link points at the exact lines of one pinned release of PyTorch, scikit-learn or XGBoost.

Every model answers the same question: given examples of inputs and the outputs we want, which function maps one to the other, and how do we find it? A model fixes the shape of that function, a loss scores how wrong it is, an optimizer adjusts it, and an evaluation on data it never saw says whether it learned anything. The pages below take that one idea from a straight line through a cloud of points to a model with billions of parameters.

Each page follows the same order: the problem the idea solves, the intuition in plain language, the mechanics with shapes and formulas, a worked example with real numbers, the implementation linked line by line to library source, its tradeoffs, and its connections to what comes before and after. Each page is marked intro, core or advanced by where it starts, but every page goes all the way down. Start with the learning path if this is all new, or jump to any area.

The map

Three building blocks (top) make up the encoder-decoder Transformer of 2017 (middle). Every model family below it keeps those blocks and changes what goes in, what comes out, or which part is kept. All of them are trained by the same loop (bottom). Each box links to its page, or to the pinned PyTorch source while the page is being written.

Shared vocabulary

Every page uses the same names. A model reads a batch of token IDs (integers that index a vocabulary), looks each one up in an embedding table to get a vector of width d_model, passes those vectors through N layers, and ends with one score per vocabulary entry, the logits. Inside a layer, attention splits d_model into heads slices of width d_head = d_model / heads.

ComponentShape/ParamsMeaningSource
Token IDs [batch, seq], integers Which vocabulary entry sits at each position. seq is the sequence length. input to nn.Embedding
Embedding weight [vocab, d_model]; out [batch, seq, d_model] A lookup table: row i is the learned vector for token i. Embedding.weight
Linear weight [out, in] + bias [out] y = x·Wᵀ + b over the last dimension. Most of a transformer's parameters live in these. nn.Linear
Multi-head attention in_proj_weight [3·d_model, d_model] + out_proj: 4·d_model² + 4·d_model with bias Mixes information between positions. The packed weight holds the query, key and value projections; head_dim = embed_dim // num_heads. MultiheadAttention.__init__
LayerNorm weight + bias, each [d_model]: 2·d_model Rescales each position's vector to zero mean and unit variance, then applies a learned scale and shift. LayerNorm.__init__
Logits [batch, seq, vocab] Unnormalized scores for the next token (or the masked token) at each position; softmax turns them into probabilities. input to CrossEntropyLoss

PyTorch's own transformer modules default to batch_first=False, so nn.Transformer expects [seq, batch, d_model] unless you pass batch_first=True (constructor defaults). These pages write shapes batch-first, and say so whenever the PyTorch default matters.

Random forests

One deep decision tree memorizes its training set and changes a lot when the data changes. A random forest grows hundreds of them on resampled data, gives each split only a random handful of features, and averages the votes. This page derives why that works, and covers out-of-bag error, the two kinds of feature importance, and extremely randomized trees.

Problem

A fully grown decision tree has low bias: it can carve the feature space into as many boxes as there are training points. It pays for that with high variance. Move a few training points and the first split can change, and with it everything below. In the example on this page one such tree scores {{ f(ex.single.train_accuracy, 2) }} on its training data and {{ f(ex.single.test_accuracy) }} on fresh data.

The bias–variance decomposition says the expected error is bias² plus variance plus noise. If we could average many trees, each fit to a different sample from the same distribution, the bias would stay the same and the variance would shrink. We only have one training set, so we need a way to make many different trees from it, and those trees need to disagree with each other for the average to help.

Intuition

Ask one expert and you get their quirks along with their knowledge. Ask a hundred experts who trained on overlapping but different material, and whose quirks point in different directions, and the quirks cancel while the shared knowledge adds up. But if all hundred studied the same textbook, they share the same quirks, and averaging removes little.

A random forest manufactures that diversity in two ways. Bagging (bootstrap aggregating) trains each tree on a bootstrap sample: n rows drawn with replacement from the n training rows. Feature subsampling lets each split consider only a random subset of the features, so a single strong feature cannot dominate the top of every tree. The rows each tree never saw give a free validation set, the out-of-bag sample.

Two sources of randomness, rows per tree and features per split, then one average.

Mechanics

Why averaging reduces variance

Treat the prediction of tree b at a point x as a random variable Tb (random over the training set and the tree's own resampling). The trees are identically distributed, each with variance σ², and any two have correlation ρ, because they were grown from the same training set. The variance of their average is

Var(1/B · Σb Tb) = (1/B²)[B σ² + B(B − 1) ρ σ²] = ρ σ² + (1 − ρ) σ² / B

The second term vanishes as B grows; the first does not. More trees can only bring the variance down to ρσ², so the way to go further is to make ρ smaller without raising σ² or the bias too much. That is exactly what feature subsampling does. Adding trees never makes the expected error worse; past a point it just stops helping, so n_estimators is a compute budget, not a knob that overfits.

Bagging

A bootstrap sample draws n row indices uniformly with replacement. A given row is missed by one draw with probability 1 − 1/n, so by all of them with probability

(1 − 1/n)n → e−1 ≈ 0.368     (n = 100: {{ f(bootstrap_oob_fraction(100), 4) }})

Each tree therefore sees about 63% of the distinct rows, some of them several times. scikit-learn does not copy the rows: _parallel_build_trees turns the drawn indices into counts with np.bincount and passes them to the tree as sample_weight, which gives the same splits. max_samples draws fewer rows per tree. The general BaggingClassifier wraps any estimator and can also subsample features once per estimator (random subspaces) instead of once per split.

Feature subsampling

At every node, the splitter shuffles the features and evaluates them one at a time until it has visited max_features of them, then keeps the best split found. If every feature drawn so far is constant in that node it keeps drawing, so a split is found whenever one exists. Defaults at {{ pins.sklearn.tag }}:

  • RandomForestClassifier: max_features="sqrt", √p features per split, with bootstrap=True and n_estimators=100.
  • RandomForestRegressor: max_features=1.0, all features, which makes it plain bagged trees. The docstring notes that Breiman suggested p/3 and that Geurts et al. later found using all features works as well empirically.
  • max_features=None (or p) on a classifier turns feature subsampling off and gives bagging.

Smaller max_features lowers ρ but each tree gets weaker (σ² and bias rise), so it is the forest's main tuning knob. The trees are grown to full depth by default (max_depth=None, min_samples_leaf=1): low bias, and averaging is left to deal with the variance.

Prediction

scikit-learn's classifier averages the trees' class probabilities (each leaf's class fractions) and predicts the argmax, a "soft" vote. Breiman's paper used a majority vote of hard labels; with fully grown trees whose leaves are mostly pure the two rarely differ. The regressor averages the trees' predictions.

Out-of-bag error

For each training row, average only the trees whose bootstrap sample did not contain it, about 37% of them, and score that prediction. Each row is predicted by models that never saw it, so the out-of-bag (OOB) score estimates test performance without a held-out set or cross-validation. scikit-learn computes it with oob_score=True; it regenerates each tree's unsampled indices from the tree's saved random state, averages their predict_proba, and stores oob_score_ (accuracy by default) and oob_decision_function_. It requires bootstrap=True, and warns when some rows were in every tree's sample.

Feature importance

  • Impurity importance (feature_importances_, "Gini importance"): for each split, the node's weighted impurity minus its children's, summed per feature, normalized per tree, averaged over trees and normalized to sum to 1. It is free, but it is measured on training data, and a feature with many distinct values offers many thresholds to overfit with. The scikit-learn docstring warns about exactly this and points to permutation importance.
  • Permutation importance (sklearn.inspection.permutation_importance): score the fitted model on a dataset (preferably held out), shuffle one column, score again; the importance is the drop, averaged over n_repeats=5 shuffles by default. It works for any model and measures what the model relies on for these predictions. Two correlated features can share the credit, so each looks less important than it is.

Extremely randomized trees

Geurts, Ernst and Wehenkel (2006) push randomization further. For each of the max_features candidate features, the splitter draws one threshold uniformly between that feature's minimum and maximum in the node, and keeps the best of these random splits. ExtraTreesClassifier also defaults to bootstrap=False, so every tree sees the whole training set and the randomness comes only from the splits. Training is faster (no sorting to find thresholds), ρ falls further, and each tree is a bit worse; in practice extra trees and random forests are often close, and which wins depends on the data.

Trees in a forest have pairwise correlation 0.3 and variance 0.2 each. What is the variance of an average of 100 of them, and of infinitely many?

0.3 × 0.2 + 0.7 × 0.2 / 100 = 0.0614; the limit is ρσ² = 0.06. Going from 100 trees to infinitely many removes only 0.0014.

Implementation

from sklearn.ensemble import RandomForestClassifier, ExtraTreesClassifier
from sklearn.inspection import permutation_importance

forest = RandomForestClassifier(
    n_estimators=500,        # more trees: slower, never worse in expectation
    max_features="sqrt",     # the main knob: smaller = less correlated trees
    min_samples_leaf=1,      # raise it for smoother probabilities and smaller trees
    oob_score=True,          # free generalization estimate (needs bootstrap=True)
    n_jobs=-1, random_state=0,
).fit(X_train, y_train)

forest.oob_score_                      # accuracy on out-of-bag rows
forest.oob_decision_function_          # (n_samples, n_classes) OOB probabilities
forest.feature_importances_            # impurity-based, from training data

result = permutation_importance(forest, X_val, y_val, n_repeats=10, random_state=0)
result.importances_mean, result.importances_std

extra = ExtraTreesClassifier(n_estimators=500, random_state=0).fit(X_train, y_train)

Trees are independent, so n_jobs=-1 fits them in parallel across cores. The forest keeps every tree in memory; on large data, fully grown trees have about as many leaves as rows, so min_samples_leaf, max_depth or max_samples are the levers for model size.

Tradeoffs

  • Strong default. Random forests need little tuning and no feature scaling, and (at {{ pins.sklearn.tag }}) handle missing values natively. They are a standard first baseline on tabular data.
  • Versus gradient boosting. A forest averages deep, independent trees to reduce variance; gradient boosting adds shallow trees one after another to reduce bias. Tuned boosting usually wins on accuracy, but needs more tuning and can overfit with too many rounds, which a forest cannot.
  • No extrapolation. Each tree predicts an average of training targets, so a regression forest's output is bounded by the training targets' range. Trends outside the training range are lost.
  • Size and latency. Hundreds of deep trees can take hundreds of megabytes and many node lookups per prediction, where a linear model takes one dot product.
  • Probabilities. Averaged leaf fractions are smoother than a single tree's, but they tend to avoid the extremes 0 and 1; calibrate them if you need real probabilities.
  • Interpretability. One tree can be read; a forest cannot. Use permutation importance on held-out data rather than impurity importance, and keep in mind that correlated features split the credit.
  • OOB caveats. The OOB score uses fewer trees per row than the full forest, so it is slightly pessimistic for small forests, and it is not available without bootstrap (the extra-trees default).
Why does a random forest with max_features = p (all features) usually do worse than with √p, even though each tree is better?

With all features, every tree tends to pick the same strong features near the root, so the trees are highly correlated and averaging removes little variance: the ρσ² floor stays high. Subsampling features decorrelates them.

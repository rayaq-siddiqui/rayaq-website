State-space models

A state-space model reads a sequence through a fixed-size state, like an RNN, but its update is linear, so the same layer can also be run as one long convolution and trained in parallel. S4 made that work for long sequences with a carefully structured state matrix; Mamba made the update depend on the input, so the model can choose what to remember. This page discretizes the equations three ways, checks that the recurrence and the convolution give the same {{ e.u|length }} outputs, runs a selective scan that holds a value a fixed step cannot, scans it in {{ ex.scan.depth }} parallel steps, and compares memory with a KV cache. Every number is computed and every library link is pinned.

Problem

A Transformer compares every token with every earlier token. Training on a sequence of length L costs time proportional to L², and generating each new token reads a KV cache that grows by one entry per token. At 8,000 tokens that is manageable; at half a million it dominates both memory and time. An RNN has the opposite profile: a fixed-size state and constant cost per token at inference, but training must step through time one position at a time, and gradients fade over long distances.

State-space models (SSMs) aim for both: constant-size state and linear cost at inference, and parallel training over the whole sequence. The price is a linear recurrence, which on its own cannot decide what to keep. The history of the family is how to make that recurrence remember long and, in Mamba, how to let it choose.

Intuition

Picture a set of leaky buckets, the state. Each time step some input pours in, every bucket leaks a fixed fraction, and the output is a weighted reading of the levels. Because the leaking and pouring are linear, an input at time 0 contributes to the output at time t by a fixed amount that depends only on the gap t. So you can compute the output either by simulating the buckets step by step (a recurrence) or by sliding one fixed filter over the input (a convolution). Training uses the convolution, which is parallel; generation uses the recurrence, which needs only the current levels.

The leak rate is controlled by a step size Δ. A large Δ means the state is mostly replaced by the new input; a tiny Δ means the input is ignored and the state carries on unchanged. Mamba's idea is to let each token pick its own Δ: an important token takes a large step and is written in, filler takes a tiny step and is skipped. The filter is then different at every position, so the convolution view is lost, and an associative scan recovers the parallelism.

The duality holds only for a linear, time-invariant (LTI) system. Selection breaks the time invariance, which is why Mamba needs a scan instead of a convolution.

Mechanics

The continuous system

An SSM maps a one-dimensional input signal u(t) to an output y(t) through an N-dimensional state h(t):

h′(t) = A h(t) + B u(t),   y(t) = C h(t) (+ D u(t), a skip term)

A is N × N, B is N × 1 and C is 1 × N. A model with D channels runs D independent copies, one per channel, usually with N between 4 and 64. The eigenvalues of A must have negative real parts, or the state blows up.

Discretization

Tokens arrive at discrete steps, so the equation is turned into a recurrence ht = Ā ht−1 + B̄ ut with a step size Δ. Three rules are common:

  • Euler: Ā = I + ΔA, B̄ = ΔB. Cheap, but unstable once Δ is large: for scalar a = −1, |1 − Δ| > 1 when Δ > 2.
  • Bilinear (Tustin): Ā = (I − ΔA/2)⁻¹(I + ΔA/2), B̄ = (I − ΔA/2)⁻¹ΔB. Stable for every Δ whenever A is. S4 uses it.
  • Zero-order hold (ZOH): assumes the input is constant over each step, giving Ā = exp(ΔA) and B̄ = A⁻¹(exp(ΔA) − I)B. Exact for piecewise-constant input. S4D and Mamba use it; for a diagonal A both are elementwise.

At small Δ all three agree (bilinear is closer to exact than Euler at Δ = 0.1). At Δ = 1 Euler forgets everything in one step; at Δ = 2.5 its factor of −1.5 makes the state grow and flip sign, while bilinear stays below 1 in magnitude and ZOH is exact by construction.

Recurrence and convolution

Unroll the recurrence from h−1 = 0: yt = Σk=0..t CĀkB̄ ut−k. That is a causal convolution with kernel Kk = CĀkB̄. In training, the whole sequence is known, so the kernel is computed once per layer and applied with an FFT in O(L log L) or as a Conv1d. In generation, the recurrence advances the N-dimensional state by one token at constant cost. The kernel is the system's impulse response: feed a single 1 followed by zeros through the recurrence and the outputs are K.

S4: a structured state matrix

A random A forgets quickly and its powers are expensive. S4 (Gu, Goel and Ré, 2021) starts from HiPPO-LegS, a matrix derived so that the state holds the coefficients of a Legendre-polynomial approximation of the whole input history so far:

Ank = −√((2n+1)(2k+1)) for n > k,   −(n+1) for n = k,   0 above the diagonal;   Bn = √(2n+1)

This A is not diagonalizable in a numerically useful way, but it is normal plus low rank (NPLR): adding ppT with pn = √(n + ½) gives −½I plus a skew-symmetric matrix, which is normal and so unitarily diagonalizable. S4 uses that split and the Woodbury identity to compute the length-L kernel in nearly linear time instead of raising Ā to L powers. Later work found simpler choices nearly as good: S4D (Gu et al., 2022) keeps only a diagonal A, initialized from the diagonal part of the NPLR form or with real values −(n+1), and the kernel becomes a Vandermonde product.

Mamba: selection

An LTI system applies the same filter to every input. It cannot do something as simple as "remember the last value that was flagged and ignore everything else", because which inputs matter depends on their content. Mamba (Gu and Dao, 2023) makes Δ, B and C functions of the current token:

Δt = softplus(WΔxt + b),   Bt = WBxt,   Ct = WCxt,   Āt = exp(ΔtA)

softplus keeps Δ positive. A large Δt drives Āt towards 0 and writes the token in; a Δt near 0 leaves Āt ≈ 1 and B̄t ≈ 0, so the token is skipped. This is a gate, the same idea as an LSTM's forget gate, but the recurrence stays linear in h. A stays fixed and diagonal (S4D-real initialization), stored as log(−A). Each channel of the expanded inner dimension has its own A and Δ, and all channels share Bt and Ct.

A Mamba block wraps the selective SSM: a linear projection to twice the expanded width, a depthwise causal convolution of width 4 and a silu on one half, the SSM, multiplication by silu of the other half, and a projection back. Blocks are stacked with residual connections and normalization, with no attention and no MLP.

The parallel scan

With per-token Āt there is no single kernel. But the update ht = atht−1 + bt composes: applying (a1, b1) then (a2, b2) is the single step (a1a2, a2b1 + b2). That combine is associative, so a prefix scan computes every ht in log₂L parallel rounds, the same trick as a parallel prefix sum (cumsum, or cumprod for the a half). Mamba's CUDA kernel goes further: it keeps the expanded state (L × D × N) in on-chip SRAM, never writes it to GPU memory, and recomputes it in the backward pass, the same IO-aware idea as FlashAttention (see GPU execution). Mamba-2 (Dao and Gu, 2024) restricts A to a scalar times the identity per head, which turns the scan into blocks of matrix multiplication that use tensor cores, and shows the result is a form of masked linear attention.

Why can S4 be trained with a convolution but Mamba cannot?

The convolution kernel CĀkB̄ assumes the same Ā, B̄ and C at every step. In Mamba they depend on each token, so the contribution of us to yt is CtĀt…Ās+1B̄s, which changes with both s and t, not only with their gap. The associative scan replaces the convolution.

Implementation

From primitives: an S4-style LTI layer computed both as a kernel and as a convolution, and a Mamba-style selective SSM as a plain loop. The kernel uses torch.einsum, and the convolution uses F.conv1d with left padding so no output sees the future. 

import torch
import torch.nn.functional as F

def discretize_bilinear(A, B, dt):
    I = torch.eye(A.shape[0], dtype=A.dtype)
    left = torch.linalg.inv(I - dt / 2 * A)
    return left @ (I + dt / 2 * A), left @ (dt * B)

def ssm_kernel(A_bar, B_bar, C, L):
    powers = [torch.eye(A_bar.shape[0], dtype=A_bar.dtype)]
    for _ in range(L - 1):
        powers.append(A_bar @ powers[-1])
    return torch.einsum("n,lnm,m->l", C, torch.stack(powers), B_bar)   # K[l] = C A^l B

def ssm_conv(u, K):                                   # u: (batch, L)
    L = u.shape[-1]
    x = F.pad(u.unsqueeze(1), (L - 1, 0))             # causal: pad the left only
    return F.conv1d(x, K.flip(-1).view(1, 1, L)).squeeze(1)  # conv1d correlates, so flip

def selective_scan(x, delta, A, B, C):
    # x, delta: (batch, L, D); A: (D, N); B, C: (batch, L, N)
    h = x.new_zeros(x.shape[0], x.shape[2], A.shape[1])
    ys = []
    for t in range(x.shape[1]):
        dA = torch.exp(delta[:, t, :, None] * A)          # ZOH for diagonal A
        dB = (dA - 1) / A * B[:, t, None, :]
        h = dA * h + dB * x[:, t, :, None]
        ys.append(torch.einsum("bdn,bn->bd", h, C[:, t]))
    return torch.stack(ys, dim=1)

class SelectiveSSM(torch.nn.Module):
    def __init__(self, d, n=16):
        super().__init__()
        self.A_log = torch.nn.Parameter(torch.log(torch.arange(1, n + 1).float()).repeat(d, 1))
        self.to_delta = torch.nn.Linear(d, d)
        self.to_B = torch.nn.Linear(d, n, bias=False)
        self.to_C = torch.nn.Linear(d, n, bias=False)
        self.D = torch.nn.Parameter(torch.ones(d))

    def forward(self, x):                             # x: (batch, L, d)
        A = -torch.exp(self.A_log)                    # S4D-real: -1, -2, ..., -n
        delta = F.softplus(self.to_delta(x))
        return selective_scan(x, delta, A, self.to_B(x), self.to_C(x)) + self.D * x

The snippet has not been run against PyTorch here; it uses only the calls linked above, and the helpers behind this page compute the same recurrence, kernel and selective scan in plain Python. The loop is O(L) sequential steps: fine for checking, far too slow for training. The official Mamba package replaces it with a fused CUDA scan, and its reference implementation uses the simpler B̄ = ΔB rather than the exact ZOH form for B.

A Mamba model and a Transformer of the same size both answer questions about a 100-page document. Which is more likely to quote a specific number from page 3 exactly, and why?

The Transformer. Its KV cache keeps every token, so attention can look the number up directly. The SSM compressed the whole document into a fixed state of a few megabytes and only kept the number if selection decided, when it read page 3, that it was worth storing. This recall gap is the main reason many recent large models mix SSM layers with a few attention layers.

Why must Δ be positive, and what happens at the two extremes?

With A negative, Ā = exp(ΔA) lies in (0, 1) only when Δ > 0; a negative Δ would make the state grow. As Δ → 0, Ā → 1 and B̄ → 0: the state is kept and the token ignored. As Δ → ∞, Ā → 0 and B̄ → −B/A: the state is reset to the current token. Softplus keeps Δ positive and smooth between these.

SSMs are linear RNNs with gates like an LSTM's, and they compete with the Transformer and its attention. The memory comparison is with the KV cache, and the per-token cost matters for latency and throughput. The convolution view is a one-dimensional CNN with a kernel as long as the sequence.

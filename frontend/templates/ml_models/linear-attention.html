Linear attention and the delta rule

Remove the softmax from attention and the sum over past tokens folds into a fixed-size matrix, so a layer runs as a recurrence with constant memory per token. Plain linear attention can only add to that matrix; the delta rule makes it correct what it stored, and a gate lets it forget. Gated DeltaNet layers built this way, mixed with a few full-attention layers, are the sequence mixer in several 2026 open-weight models. This page checks that the parallel and recurrent forms give the same {{ e.tokens|length }} outputs, writes and overwrites a small associative memory under all three update rules, and counts the cost and memory of a hybrid stack. Every number is computed and every library link is pinned.

Problem

Causal softmax attention compares each token with every earlier one. A prefill of n tokens costs time proportional to n², and each generated token reads a KV cache that grows by one entry per token per layer. At a million tokens of context the cache, not the weights, decides how many requests fit on a GPU.

State-space models solve the memory problem with a fixed-size state, but their state is a vector per channel, updated by a decay and an input. Linear attention reaches the same place from the attention side: it keeps queries, keys and values, and stores the past as a dk × dv matrix. The open problem is what to write into that matrix so it stays useful when the context is far longer than the matrix can hold, and that is what the delta rule and its gate answer.

Intuition

Read attention as a lookup in a key-value memory: the query is compared with every stored key and returns a blend of the matching values. If the comparison is a plain dot product instead of a softmax, the whole memory can be summarised by one matrix S = Σ kjvjT, and reading is STq. With orthonormal keys that read is exact. Storing a pair costs one outer product, whatever the length of the sequence.

The trouble is that adding is the only operation. Store a new value under a key that is already there and the read returns the sum of the old and new values. Schlag, Irie and Schmidhuber (2021) pointed out that this matrix is a "fast weight" memory and borrowed the fix from the Widrow–Hoff delta rule: before writing, read what the memory currently returns for the key, and write only the error. Gated DeltaNet (Yang, Kautz and Hatamizadeh, 2024) adds a decay α that fades the whole memory each step, so it can clear space when the context changes.

The step that matters is reassociation: (qTkj)vj summed over j equals qT times the summed outer products. The softmax's normalisation over all j is what prevents it.

Mechanics

From softmax to a feature map

Causal softmax attention computes oi = Σj≤i sim(qi, kj) vj / Σj≤i sim(qi, kj) with sim = exp(qTk/√d). Katharopoulos, Vyas, Pappas and Fleuret (2020) replace sim with a kernel φ(q)Tφ(k) for a positive feature map φ. Then:

Si = Si−1 + φ(ki)viT,   zi = zi−1 + φ(ki),   oi = SiTφ(qi) / ziTφ(qi)

Their choice is φ(x) = elu(x) + 1, which is positive so the weights stay positive and sum to 1. The paper's title states the result: with this form a Transformer layer is an RNN whose hidden state is (S, z). Training still sees the whole sequence, so it can compute the same outputs with a prefix sum (cumsum) of the outer products, or in chunks: full attention-style matrix products inside each chunk and the recurrence between chunks.

The delta rule

Later linear-attention models drop the normaliser z and the feature map, normalise q and k to unit length instead, and change the write. With state S of shape dk × dv and a write strength βt ∈ (0, 1) from a sigmoid:

v̂t = St−1Tkt,   St = St−1 + βt kt(vt − v̂t)T = (I − βtktktT)St−1 + βtktvtT,   ot = StTqt

v̂ is what the memory currently returns for k. With β = 1 and a unit key, the update replaces it with v exactly and leaves every direction orthogonal to k untouched. It is one step of gradient descent on the loss ½‖STk − v‖² with learning rate β, which is where the Widrow–Hoff name comes from. The transition matrix I − βkkT has eigenvalue 1 − β along k and 1 elsewhere, so with unit keys and β in (0, 1) the state cannot blow up; that is why q and k are L2-normalised.

The product of such matrices is not a simple cumulative sum, so the prefix-sum trick no longer applies. Yang, Wang, Zhang, Shen and Kim (2024) showed that a product of these Householder-like matrices has a compact WY representation, which gives a chunkwise algorithm built from matrix multiplications that trains in parallel over the sequence.

The gated delta rule

Gated DeltaNet multiplies the old state by a data-dependent decay αt = exp(gt) ∈ (0, 1] before the delta write:

St = αt(I − βtktktT)St−1 + βtktvtT

α near 1 keeps everything; α near 0 wipes the memory, which a pure delta rule can only do one key direction at a time. The gate is Mamba-2's scalar decay, so the paper presents the layer as a combination of the two: the delta rule gives precise, targeted edits, and the gate gives fast forgetting. Computed in log space, the decays of a chunk are a cumsum of g values from a logsigmoid or similar.

A Gated DeltaNet block

In the GigaChat 4 technical report's architecture figure, a GDN block projects the input to q, k, v, α and β with linear layers, passes q, k and v through a short causal convolution, L2-normalises q and k, runs the gated delta rule, normalises the output with RMSNorm and multiplies it by a gate computed from the input before the output projection. Several heads run in parallel, each with its own state matrix.

Hybrid stacks

A fixed-size state cannot hold an arbitrary long context exactly, so current large models keep some full-attention layers. GigaChat 4 (2026) has 64 layers: 48 GDN and 16 multi-head latent attention (MLA) layers, a 3:1 schedule, with 256 routed experts (8 active plus 1 shared) in its mixture of experts, about 708B total and 41B active parameters, and a 1,048,576-token context. Only the 16 MLA layers keep a KV cache, and at long context they use DeepSeek Sparse Attention with top-2,048 key selection; the GDN layers are unchanged. Its predecessor GigaChat 3.5 used the same 3:1 ratio over 40 layers (30 GDN, 10 MLA). The Ternary Bonsai 2 whitepaper describes its base model, Qwen3.8-27B, as a similar hybrid of about three-quarters linear-attention layers.

Why does linear attention need a feature map like elu + 1, while the delta rule uses L2-normalised q and k instead?

Linear attention keeps the normaliser z and divides by φ(q)Tz, so the weights must be positive or the denominator can reach zero. The delta rule has no normaliser: it treats S as a regression from keys to values, and what it needs is that I − βkkT does not amplify the state, which unit-length keys guarantee for β in (0, 1).

With orthogonal keys there is no interference between k1 and k2. Real keys are not orthogonal: a dk-dimensional state can hold at most dk independent directions, and every further write disturbs the others a little.

Implementation

PyTorch has no linear-attention module, so both forms are written from primitives: the causal linear attention with cumsum and einsum, and the gated delta rule as the reference loop that fast chunked kernels are tested against. 

import torch
import torch.nn.functional as F

def causal_linear_attention(q, k, v):            # (batch, heads, L, d)
    q, k = F.elu(q) + 1, F.elu(k) + 1
    kv = torch.einsum("bhld,bhle->bhlde", k, v).cumsum(dim=2)   # S_i for every i
    z = k.cumsum(dim=2)                                       # z_i for every i
    num = torch.einsum("bhld,bhlde->bhle", q, kv)
    den = torch.einsum("bhld,bhld->bhl", q, z).unsqueeze(-1)
    return num / den                              # O(L d^2) memory here; chunk it in practice

def gated_delta_rule(q, k, v, beta, g):           # q, k, v: (batch, heads, L, d); beta, g: (batch, heads, L)
    q = F.normalize(q, dim=-1) / q.shape[-1] ** 0.5
    k = F.normalize(k, dim=-1)
    S = q.new_zeros(q.shape[0], q.shape[1], k.shape[-1], v.shape[-1])
    out = []
    for t in range(q.shape[2]):
        S = S * g[:, :, t, None, None].exp()                     # decay: alpha = exp(g)
        recalled = torch.einsum("bhde,bhd->bhe", S, k[:, :, t])  # S^T k
        write = beta[:, :, t, None] * (v[:, :, t] - recalled)    # delta: write the error
        S = S + torch.einsum("bhd,bhe->bhde", k[:, :, t], write)
        out.append(torch.einsum("bhde,bhd->bhe", S, q[:, :, t]))
    return torch.stack(out, dim=2)

# beta = torch.sigmoid(x @ W_beta);  g = F.logsigmoid(x @ W_g)  (one common choice)

The snippet has not been run against PyTorch here; it uses only the calls linked above, and the helpers behind this page compute the same recurrences in plain Python. Scaling q by 1/√dk follows common reference code and is a convention, not part of the rule. The loop is O(L) sequential steps; production kernels split the sequence into chunks of 64 or so, use the WY representation inside each chunk, and pass the state between chunks.

Speculative decoding drafts several tokens and may reject some. Why is that harder with linear-attention layers than with a KV cache?

Rejecting tokens from a KV cache only means truncating it: the entries for rejected positions are dropped. A recurrent state has already absorbed the rejected tokens, and the update cannot be subtracted back out in general. The server must keep the state from before the draft, or enough per-step inputs to replay the accepted ones; the GigaChat 4 report describes replaying compact per-step updates for its GDN layers instead of storing a full state at every draft position.

With β = 1 and a unit key, what does the delta rule do to the value stored under a key orthogonal to k?

Nothing. The update adds k(v − v̂)T, and reading with an orthogonal key u gives uTk = 0 times that change. Only the stored value along k moves, and with β = 1 it moves all the way to v.

Linear attention starts from softmax attention and ends close to state-space models: the gate is Mamba-2's decay, and Mamba-2 itself is a masked linear attention. The memory comparison is with the KV cache, and rolling back recurrent state matters for speculative decoding. The delta rule is one step of gradient descent on a regression loss (see optimizers), the same update as the LMS rule behind linear regression fitted online. Hybrid models built from these layers are trained like any decoder-only LLM and usually use a mixture of experts for the feed-forward part.

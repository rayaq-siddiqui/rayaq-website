Every schema

The two .proto files that define the wire between jj's client-side stores and the commit-cloud server: two services, fifteen RPCs and forty-three messages, each field with the jj-lib type it converts to and from.

In short: BackendService carries the content-addressed objects jj-lib's Backend trait deals in (commits, trees, files, and on paper symlinks), and OpStoreService carries the operation log (operations, views and op heads). Every request names a repository by the UUID the server handed out at registration. On every write, the server computes the object's ID and sends it back. The messages are a trimmed copy of jj's own storage protos: they drop Git refs and tags, and they add the repo ID.

Both files are proto3, in packages commit_cloud.backend and commit_cloud.op_store. For the protos jj itself uses on disk, see /jj/protobufs. That page describes jj's own pinned version, which is newer than the jj-lib {{ upstream.jj_lib_version }} used here.

How the Rust code is generated

The cc-common crate compiles both files at build time. common/build.rs calls tonic_build::configure().compile_protos(&["proto/backend.proto", "proto/op_store.proto"], &["proto"]), which generates prost message structs plus a tonic client and server for each service. common/src/lib.rs includes them as cc_common::backend and cc_common::op_store. That gives types such as cc_common::backend::Commit, the client backend_service_client::BackendServiceClient, and the server trait backend_service_server::BackendService. The object IDs page shows how it does that.

What the wire doesn't carry

Converting jj-lib's types to these messages loses some information. Each item below is visible in the conversion code:

  • Tags, Git refs and Git HEAD. View has no fields for them. view_from_proto fills local_tags and git_refs with empty maps and git_head with an absent target, and view_to_proto never reads a remote's tags (source). The proto comment says the Git fields were omitted on purpose.
  • Operation time zones. Only the millisecond timestamps are sent. Both offsets read back as 0 (source).
  • Commit signatures. Written if present, but always read back as None (source).
  • Copy IDs that aren't 20 bytes long are replaced with zeros on read (source). Copy history itself isn't supported (read_copy, write_copy and get_related_copies return Unsupported).
  • Symlink contents and Git submodules. Symlinks can appear in trees, but their targets can't be stored or read. Submodules are rejected outright.

The client Backend

CommitCloudBackend is jj-lib's commit Backend trait implemented as gRPC calls. Every file, tree and commit read or write becomes one call to the server's BackendService, made on a fresh thread with a fresh runtime and a fresh connection.

In short: the backend holds only the server URL, the repository ID and three fixed IDs (root commit, root change, empty tree). init registers a new repository with the server and writes config.toml. load reads it back. Each trait method converts jj's types to the protobuf messages, runs the RPC through run_async, and converts the answer back. The root commit and the empty tree are answered locally. Symlinks, copy tracking, Git submodules and stored conflict IDs are unsupported. Commit signatures are sent but never read back.

The module is lib/src/cc_backend.rs, re-exported from lib/src/lib.rs. The messages it builds are on protobufs, and the IDs the server returns on object-ids. jj's own view of a backend is on /jj.

Creating and loading

init(store_path, server_url) connects, calls RegisterRepository with name: None, and writes {server_url, repo_id} as pretty TOML to <store>/config.toml. A TODO notes that the optional repository name isn't passed yet. load(store_path) only reads that file, and makes no network call until the first object is read or written.

CommitCloudConfig::load_from_store reads store_path/config.toml if it exists. Otherwise it falls back to store_path/../store/config.toml, so the op store and op heads store, whose paths are .jj/repo/op_store and .jj/repo/op_heads, share the backend's file. A missing file is an error.

The backend is registered under the name commit_cloud by StoreFactoriesExt::add_commit_cloud, which also registers the op store and op heads store under the same name. Load errors become BackendLoadError.

Conversions

Commits

commit_to_proto copies every field: change ID, parents, all root tree terms, description, author, committer, predecessors, conflict labels, and the signature bytes if present. The commit_id is left empty for the server to fill in. commit_from_proto reverses it, rebuilding the tree Merge and the labels. It always sets secure_sig: None, so a signature sent on write is never seen again. Missing signatures and timestamps default to empty or zero (signature helpers).

jj-lib's placeholder copy ID is empty (CopyId::placeholder), so a file written with it reads back with a 20-byte zero copy ID instead. The server never hashes copy_id (see object-ids), so tree IDs don't change.

Sync/async bridging and the tonic channel

run_async(f) spawns a new OS thread, builds a current_thread tokio runtime with all drivers enabled, block_ons the future, and joins the thread. A panic in the thread becomes an error string. Every backend method then calls BackendServiceClient::connect(server_url) inside that future, so each read or write of a single object costs:

  1. a thread spawn and join,
  2. a tokio runtime construction,
  3. a new TCP connection and HTTP/2 handshake to the server,
  4. the RPC itself.

There is no shared channel, connection pool or timeout.

Errors

Read paths map a gRPC NotFound to BackendError::ObjectNotFound with the object type and hex ID. Any other error, whether a connection failure, another status, or a conversion error, becomes BackendError::Other. Write paths make every failure BackendError::Other (read mapping, write mapping). Unsupported features return BackendError::Unsupported before any call is made.

What this backend doesn't do

  • Symlinks can't be read or written, and copy tracking is off entirely.
  • Commit signing is ignored on write, and signatures are dropped on read.
  • write_commit returns the commit unchanged, though the jj-lib contract says it "should contain the data that was actually written" (doc). Since the server's ID covers fewer fields than the commit holds (object-ids), two different commits can come back with the same ID.
  • Whole files are held in memory on both read and write. There is no streaming upload.
  • No connection reuse, no timeouts, no retries, no authentication. concurrency is 1.
  • gc does nothing and get_copy_records is always empty.

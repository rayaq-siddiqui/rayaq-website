Data and metrics

rml/data gets examples into a training loop: datasets, a seeded loader, preprocessing fitted on the training rows and leak-free splits. rml/metrics scores what comes out: hard-label, regression, threshold-free ranking and probability metrics, each checked against scikit-learn's own documented examples.

In short: a Dataset is a list of examples, each a fixed number of tensors, and a DataLoader walks it in batches by stacking each field along a new axis 0. Shuffling draws epoch e's order from Generator(seed, e), so any epoch can be replayed without running the ones before it. Scalers and the imputer work column by column on f32 [N, D] matrices and are fitted on the training split only; splits and k-folds are plain index lists, optionally stratified by class. The metrics copy their inputs into flat vectors of doubles, compute in double, and return a float. They follow scikit-learn's conventions: a zero denominator gives 0, micro-averaged scores equal accuracy, and average precision is the step-wise sum rather than an interpolated area. The thirteen training demos use the dataset and loader; nothing in the library or the examples calls preprocessing, splits or metrics yet.

The concepts are on /ml-models: {{ ml('data-loading-and-batching', 'data loading and batching') }}, {{ ml('preprocessing', 'preprocessing') }}, {{ ml('missing-data', 'missing data') }}, {{ ml('class-imbalance', 'class imbalance') }}, {{ ml('data-splits', 'data splits') }}, {{ ml('cross-validation', 'cross-validation') }}, {{ ml('classification-metrics', 'classification metrics') }}, {{ ml('regression-metrics', 'regression metrics') }} and {{ ml('calibration', 'calibration') }}.

Datasets and the loader

rml::data has three libraries, dataset, preprocessing and split, each depending only on rml/core and, for the two that shuffle, {{ link('random', 'rml/random') }} (BUILD.bazel). The header's usage comment is the whole loop (dataset.h L79–85): construct a loader once, then per epoch call StartEpoch(epoch) and Next(batch) until it returns false.

Why epoch e has its own generator

StartEpoch builds a fresh random::Generator(seed, epoch) and draws random::Permutation(size, gen) from it (dataset.cc L143–153). Philox is counter-based, so the epoch number picks an independent stream instead of continuing one shared stream: epoch 1's order is the same whether or not epoch 0 ran first, and training resumed from a checkpoint replays exactly (dataset.h L7–11). The test ShuffleIsAPermutationFixedPerEpoch checks exactly that with two loaders. How the streams work is on {{ link('random', 'Random numbers') }}.

Each batch is a fresh copy: GatherRows allocates its output, so a batch never aliases the dataset and the model can do anything with it. The training loop that consumes the batch is on {{ link('training', 'Losses and optimizers', '#loop') }}.

Preprocessing

Every transformer checks for an f32 rank-2 matrix and, after Fit, that the column count matches (preprocessing.cc L18–27); calling Transform before Fit dies with "call Fit() first". The scalers are written with the broadcasting ops from {{ link('tensors', 'rml/core', '#ops') }}, so a [D] statistic applies to every row.

Splits and cross-validation

A Split is two index lists, train and test (split.h L19–22). The header's rule is to split before fitting anything, scalers included, since statistics over the test rows leak them into training (L8–9). The indices feed a Subset or GatherRows.

How the metrics read their inputs

rml::metrics has four public libraries and one private helper, inputs, which every metric goes through (inputs.cc L12–34): LabelVector checks for a rank-1 i32 tensor, ValueVector takes every element of an f32 tensor of any shape as a double, and BinaryLabelVector also checks the labels are 0 or 1. So all arithmetic is in double, inputs can be strided views, and the result is converted to float once at the end. Nothing here is differentiable; for training objectives see {{ link('training', 'the losses') }}.

Classification metrics

Everything starts from the confusion matrix C, where C[i][j] counts true class i predicted as j (classification.h L7–13). Precision for class c is C[c][c] over column c's sum, recall is C[c][c] over row c's sum, and any ratio with a zero denominator is 0, as in scikit-learn (SafeRatio, classification.cc L17–19).

Regression metrics

Inputs are f32 tensors of equal shape, of any rank, compared element by element; at least one value is needed (regression.cc L19–23).

With scikit-learn's documentation example y = {3, −0.5, 2, 7}, ŷ = {2.5, 0, 2, 8}, the errors are 0.5, 0.5, 0 and 1: MSE 0.375, MAE 0.5, median absolute error 0.5, R² 0.9486 and explained variance 0.9572 (regression_test.cc L12–26). Shifting every prediction by one, {4, 0.5, 3, 8}, leaves explained variance at exactly 1.

Ranking metrics: ROC and precision-recall

A score can be cut at any threshold t, predicting positive when score ≥ t. Every curve here comes from one sweep (ranking.cc L25–56): stable-sort the scores in decreasing order, start with a point at threshold +∞ where nothing is positive, then walk down counting true and false positives. Tied scores move together, so a point is emitted only after the last of a tie, which is why ties count half in the ROC area.

The precision-recall curve suits rare positives better than ROC, because precision ignores the many easy negatives (ranking.h L7–16). A test computes the ROC AUC as the fraction of winning positive-negative pairs on random data and checks the two agree to 10−6 (MatchesPairwiseRanking).

Probability metrics and calibration

These take i32 labels and probs that are either rank 1, the probability of class 1 for binary labels, or [n, num_classes] rows (calibration.h L14–16). A private Rows helper expands rank-1 input to rows [1 − p, p], so one code path serves both (calibration.cc L16–48).

Who uses it

TensorDataset and DataLoader are used by thirteen training demos in {{ link('examples', 'examples/') }}: cnn, diffusion, diffusion_unet, dpo, encoder, finetune, flow_matching, mlp, rag, rnn, ssm, vae and vit. At the pin no library code and no example includes preprocessing.h, split.h or any rml/metrics header; their tests are their only callers. {{ link('classical', 'The classical models') }} are checked against scikit-learn fixtures with their own assertions rather than through these metrics.

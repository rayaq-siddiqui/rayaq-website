Retrieval

rml/retrieval finds the stored embedding vectors most similar to a query: exactly, by scoring every one, or approximately, by scanning only the few clusters of an inverted-file index that lie closest to the query.

In short: three metrics (inner product, cosine, negated squared L2) are all scored so that higher means more similar, and cosine is turned into an inner product by storing every vector at unit length. A size-k min-heap, internal::TopK, keeps the best results with ties broken towards the lower id. FlatIndex scores every stored vector, O(n·d) per query, and is the exact baseline. IvfIndex trains num_lists centroids with {{ link('classical', 'rml/classical') }}'s k-means, files each added vector under its nearest centroid, and at search time scans only the num_probes lists whose centroids score best; probing every list gives back the exact answer. Both are plain single-threaded C++ over std::vector<float>, and errors come back as Status.

The concepts are on /ml-models: {{ ml('embeddings', 'embeddings') }}, {{ ml('similarity-search', 'similarity search') }}, {{ ml('vector-indexes', 'vector indexes') }}, {{ ml('clustering', 'clustering') }}, {{ ml('two-tower-models', 'two-tower models') }} and {{ ml('retrieval-augmented-generation', 'retrieval-augmented generation') }}. The module is two libraries, similarity and ivf, each with its own test (BUILD.bazel).

Metrics and scores

Every search returns Neighbor{id, score} with a higher score meaning more similar, so one heap and one ordering serve all three metrics (similarity.h L7–12). That is why L2 is negated: the nearest vector has the largest −|q − x|².

A worked example

The metric test scores q = (1, 2, 2) against x = (2, 0, 1) (similarity_test.cc L20–27):

kInnerProduct1·2 + 2·0 + 2·14
kCosine4 / (|q| |x|) = 4 / (3 · √5)≈ 0.596
kL2−((1−2)² + (2−0)² + (2−1)²)−6

Cosine and inner product can disagree on the winner. With stored vectors (1, 0) and (10, 10) and the query (1, 0.1), cosine picks id 0 (almost the same direction) while inner product picks id 1 (much longer) (similarity_test.cc L86–95).

Keeping the k best

internal::TopK is a min-heap of at most k results ordered by Better: higher score first, then lower id (similarity.cc L20–23). Because the heap's comparator is "better", the front of the heap is the worst result kept, so each push is one comparison against it and, if the candidate wins, a pop and a push: O(log k) per scored vector and O(k) memory however many vectors are scored.

FlatIndex: exact search

FlatIndex stores every vector in one row-major std::vector<float>, unit length under cosine, and compares each query with all of them (similarity.h L13–15). It is always exact, and it is what the IVF tests measure recall against.

IvfIndex: the inverted file

An inverted-file index splits the stored vectors into num_lists clusters and, for each query, scores only the vectors in the num_probes clusters whose centroids look best, about num_probes / num_lists of the data. A true neighbour just across a cluster boundary is missed, so recall trades against speed through num_probes (ivf.h L4–16).

How the metric reaches the clusters

Under cosine every vector is unit length before k-means sees it, so the clustering, the assignment and the scan all work on directions (ivf.h L15–16). The centroids are means of unit vectors and are not normalized again; ranking them by inner product still works because the query is unit length (ivf.cc L60–62). ScoringMetric maps cosine to inner product everywhere else (L19–22).

The centroids always come from k-means, which clusters by Euclidean distance, but lists are assigned and probed with the index's own metric. Under kL2 the two agree. Under kInnerProduct a vector goes to the centroid with the largest inner product, which favours long centroids, so the lists need not match k-means' own labels; the parameterized tests show recall still rises with probes for all three metrics.

Recall against probes

ivf_test builds 4,096 points around 32 shared, overlapping centers in 16 dimensions, plus 100 queries from the same distribution, and indexes them with 32 lists (ivf_test.cc L20–38, L52–68). Recall is the share of the exact top 10 that IVF returns. The asserted bounds, for every metric (L92–115):

The scanned shares in the middle column are num_probes / num_lists, which is what the lists average; only the 1/6 bound at 4 probes and the full count at 32 are checked.

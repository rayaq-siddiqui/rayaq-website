Random numbers

rml/random is one generator and the distributions built on it. The generator is Philox4x32-10, a counter-based design: the n-th random word is a pure function of (seed, stream, n), so any part of a stream can be computed on its own and a generator's whole state is three integers.

In short: Generator encrypts a 128-bit counter with a 64-bit key (the seed) through ten Philox rounds and hands out the four 32-bit lanes of each block as words. Skipping ahead is O(1) and so is saving or restoring state. On top of the words sit exact conversions to float and double, unbiased integers by rejection, and Box-Muller normals. distributions.h adds sampled tensors, Fisher-Yates permutations, and normal, Bernoulli and categorical distributions with log-probability, entropy and KL divergence in nats.

The headers link {{ ml('reproducibility', 'reproducibility') }}, {{ ml('probability-and-distributions', 'probability and distributions') }} and {{ ml('entropy-and-kl', 'entropy and KL divergence') }} on /ml-models. Every sampler in rml takes a random::Generator&, so a fixed seed makes a whole run reproducible (who draws from it).

Why a counter-based generator

A conventional generator such as std::mt19937 carries a large state and steps it once per draw, so draw n exists only after draws 0 through n − 1. Philox (Salmon et al., "Parallel Random Numbers: As Easy as 1, 2, 3", SC 2011) is instead a keyed bijection on 128-bit counters (philox.h L4–12). Block i of the stream is Philox(counter = i, key = seed), computed directly with nothing carried over from block i − 1. Three things follow:

  • Any element of a stream can be produced on its own, so Skip costs nothing.
  • Work split across threads can draw the same numbers a serial run would.
  • A generator's entire state is (seed, stream, position): three uint64s, trivially saved in a checkpoint.

Philox4x32-10

Philox4x32 (philox.cc L33–42) runs ten rounds. Each round (L24–29) multiplies two of the four lanes by fixed odd constants, keeps both halves of each 64-bit product, and mixes them with the other two lanes and the key:

Output laneValue
0hi(M1 · c2) ⊕ c1 ⊕ k0
1lo(M1 · c2)
2hi(M0 · c0) ⊕ c3 ⊕ k1
3lo(M0 · c0)

M0 = 0xD2511F53 and M1 = 0xCD9E8D57 (L12–16). Between rounds the key is bumped by two Weyl constants, 0x9E3779B9 (the golden ratio) and 0xBB67AE85 (√3 − 1), each as a 32-bit fraction. The high half of each product depends on every bit of its input lane, which is where the mixing comes from. The implementation is checked against three known-answer vectors from the Random123 reference distribution.

Unbiased integers

Taking x % n of a uniform 64-bit x would make the smallest residues slightly more likely whenever n does not divide 2⁶⁴. UniformInt rejects the bottom 2⁶⁴ mod n values of the range, computed in unsigned arithmetic as -n % n, and redraws. What remains is a whole multiple of n, so every residue is equally likely. For n = 3 the threshold is 1: only x = 0 is rejected, a chance of 1 in 2⁶⁴, so a redraw almost never happens.

Normals

Box-Muller turns two uniforms into a standard normal: z = √(−2 ln u₁) · cos(2π u₂). NextNormal takes u₁ = 1 − NextDouble(), which lies in (0, 1], so the logarithm is always finite. It computes in double and rounds to float. The paired sine value is not kept, so each normal costs two doubles (four words), and a draw never depends on whether an earlier call left a cached value behind.

Categorical sampling

Categorical::Sample (L192–213) inverts the CDF. It draws u = NextDouble() and walks the row, adding probabilities, until u falls below the running sum. Zero-probability categories are skipped, so they can never be chosen. If rounding leaves u above the final sum, the last category with nonzero probability is taken. For the row [0.25, 0.5, 0, 0.25], u = 0.6 passes 0.25, stops at 0.75, and returns index 1.

Entropy and KL edge cases

Two helpers (L23–31) carry the limits that keep entropy and KL finite where they should be. x log x is taken as 0 at x = 0, so a category with probability 0 adds nothing to the entropy. x log(x / y) is 0 when x = 0, and infinity when x > 0 but y = 0. That is, KL(p ‖ q) is infinite when p puts mass where q has none. Both sums are accumulated in double.

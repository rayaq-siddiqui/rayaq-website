The inference stack

rml is becoming a layered, MLIR-style inference stack: models defined in PyTorch, JAX and TensorFlow are exported into rml's own graph IR, checked against each framework, and lowered to kernels that aim to beat the frameworks on CPU. This page walks the levels and marks which exist at this commit.

In short: a model is written once per framework, from shared weights. Offline Python exports it into rml-graph, a JSON op list over mmapped safetensors weights, by two routes: each framework's own traced graph, or the StableHLO its compiler produces. From there rml runs it in C++ with no Python. Below the graph, runs of elementwise nodes fuse into tiled programs, and the remaining ops run on vectorized, threaded kernels and a packed SIMD GEMM. Every model is checked across all three frameworks and both routes, and benchmarked against each framework's eager and compiled modes.

The direction

rml's plan (docs/progress.md L135–146) extends the Python front ends to every neural model on the ML models reference. Three commitments shape it:

  • Three frameworks, one model. Each model is defined in PyTorch, JAX and TensorFlow, exported, checked against the framework, and benchmarked on CPU.
  • Layered like MLIR. Frameworks hand over StableHLO through their own production exporters, which is what an MLIR pipeline consumes. tools/ lowers it to rml-graph, and inside rml, rml-graph lowers to a kernel-level plan that runs fused, threaded kernels.
  • Two routes, cross-checked. The direct per-framework exporters stay as a second way in, and the two routes are checked against each other.

At this commit every item of that plan is checked off except one: keeping small ops on the calling thread (progress.md L157–172). Larger grains for exactly that have landed, but four threads is still slower than one in 38 of 171 rml cells, so the checklist keeps it open and this section treats it as in progress. The last two items are new examples, tiny_net and tiny_models, which run small PyTorch, JAX and TensorFlow models from C++ and compare them bit for bit ({{ link('exporters', 'Exporters and the model zoo', '#tiny-examples') }}).

Why layers

Each level has one job, so each can be tested on its own. The framework-facing work stays in offline Python, where the frameworks live. The format in the middle is small on purpose (graph_ir.md L106–110): exporters lower framework ops onto it, so JAX's dot_general becomes transpose + reshape + matmul, and an op an exporter cannot lower fails the export with the framework's op name. There is no silent fallback. Below the format, optimization happens in rml without touching any exporter: the fusion layer removes the intermediate tensors of a written-out GELU or layer norm "whichever framework the graph came from" (fusion.h L10–12).

StableHLO is the front door the plan names because each framework already produces it with its production tooling, and it is the input an MLIR pipeline expects. Both routes end in the same clean-up passes, and every fixture exists for both, so the two are independent ways into the same IR that the tests hold to the same answer (graph_ir.md L21–25).

What stays out

  • Training. The format is inference only: there is no backward pass (graph_ir.md L6). Training in rml goes through {{ link('autograd', 'Autograd') }}.
  • Classical ML and KV-cache decoding stay out of the graph stack (progress.md L143–146). LLM decoding keeps its own allocation-free loop in rml/llm; the graph executor is a general model runner.
  • Sampling loops stay outside the graph. The exported network is one step, and noise is an input, so a diffusion sampler calls the graph once per step.

Where it stands

The latest benchmark (frameworks.md L5–7: an Intel Xeon at 2.10GHz with 4 logical CPUs, Linux x86_64, torch 2.14.1, jax 0.12.0, tensorflow 2.21.0, rml built with --config=opt) times all 19 models at batch 1, 8 and 64 on 1 and 4 threads. Taking the fastest framework and mode per cell, rml wins 80 of the 114 cells, with a geometric mean of 1.31 against that best (up from 38 and 0.91). On average it is ahead of PyTorch, JAX and TensorFlow in every row, at every batch and thread count (frameworks.md L349–366).

It is strongest on small and medium MLP-shaped models (two_tower at 2.6× the best framework) and still trails the best framework on the LSTM (0.76×, against PyTorch's fused ATen LSTM), the U-Net's convolutions (0.79×), the SSM (0.85×), the CNN (0.89×), and the RNN and GCN (0.93×). Four threads is slower than one in 38 of 171 rml cells, almost all at batch 1. The StableHLO route runs within 4–13% of the direct exporters (frameworks.md L367–377). {{ link('benchmarks', 'Benchmarks against the frameworks', '') }} has the numbers, and {{ link('lowering', 'Lowering and fast CPU', '') }} what each optimization targets.

Apple Silicon numbers (NEON, Accelerate) have not been produced yet (frameworks.md L347), and GitHub CI has failed before any job starts since October 17, so these changes are verified only in rml's Linux container (progress.md L207–209).

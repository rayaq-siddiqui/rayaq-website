How jj sparse reset works

jj sparse reset sets the workspace's sparse patterns back to the single root pattern, so every file in the working-copy commit is checked out again. Commits and the operation log are untouched.

In short: jj loads the workspace, which snapshots it as usual, locks the working copy, and replaces the patterns with [root], shown as .. The working copy writes every file that was outside the old patterns. It saves its state under the same operation ID and prints Added N files, modified 0 files, removed 0 files. It is jj sparse set --clear --add . in one word.

The command is cmd_sparse_reset: three lines that call the shared update_sparse_patterns_with with a closure returning vec![RepoPathBuf::root()] (source). The update step is described on the sparse set page.

1. Command-line surface

No arguments or flags (SparseResetArgs). The help text: "Reset the patterns to include all files in the working copy".

2. Configuration

None. The patterns live in the workspace's working-copy state, the sparse_patterns field of TreeState (see protobufs). The root pattern is also what a missing field means, for working copies older than the field (source), and what a new working copy starts with (source).

5. Transaction and operation

  • Transaction and operation: none; only the working-copy lock (source).
  • Before it: loading may record a snapshot working copy operation, as for any command.
  • Running it twice is harmless: the second time nothing is added, so nothing is printed.
  • jj undo doesn't apply; use jj sparse set to narrow again.

6. Algorithm and invariants

With new patterns [root], TreeState::set_sparse_patterns computes "added" as everything the old prefixes didn't cover and checks it out from the current tree; "removed" is empty, because the root prefix covers every path (PrefixMatcher). A new file's path that is already occupied on disk is skipped and reported.

Invariants: afterwards the patterns are exactly . and every tracked file of the working-copy commit is on disk. No file is deleted. Commits never change.

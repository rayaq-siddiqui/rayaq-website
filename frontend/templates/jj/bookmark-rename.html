How jj bookmark rename works

jj bookmark rename old new moves a local bookmark's target to a new name and carries its remote tracking over. Remote bookmarks themselves are not renamed: the old name becomes a deletion to push, and the new name is ready to be pushed.

In short: jj refuses if old doesn't exist, or if new already exists without --overwrite-existing. In one transaction it points new at old's target and removes old. For every remote where old was tracked, it starts tracking new there, unless an untracked new already exists on that remote. It records rename bookmark old to new, then warns that the old remote bookmarks still need pushing.

The command is cmd_bookmark_rename. Tracking is explained on the bookmark track page and the deletion that follows on bookmark delete.

5. Transaction and operation

  • Transaction: one, after the checks (source).
  • Operation description: rename bookmark <old> to <new> (source).
  • Warnings after the commit: the "not renamed" and "exist" warnings are printed after tx.finish, so they refer to a rename that already happened (source).
  • jj undo restores both names and their tracking state.

6. Algorithm and invariants

Moving the tracking state

For each remote bookmark named old that is tracked, outside the git remote (source):

  • If it's present, remember that tracked remote copies of old exist, for the warning at the end.
  • If new@remote already exists and is untracked, skip it with a warning: tracking it would merge that unrelated remote bookmark into the local one.
  • Otherwise call track_remote_bookmark(new@remote), which merges the remote target into the local bookmark and marks it tracked. When new@remote doesn't exist yet, it's an absent but tracked entry, which makes the next jj git push create new on that remote.

--overwrite-existing

Before moving anything, every tracked remote bookmark of new is untracked so the transfer starts clean (source). Afterwards, for each remote where new was tracked and present but old wasn't tracked, jj warns Tracking of remote bookmark new@remote was dropped. (source).

Invariants: the commit new points to is exactly old's former target. Nothing changes on remotes until you push. The git pseudo-remote is never tracked or untracked here.

8. Worked example

From upstream's test_bookmark_rename. bremote was pushed to origin and is tracked. Then jj bookmark rename bremote bremote2:

Upstream's output (source):

Warning: Tracked remote bookmarks for bookmark bremote were not renamed.
Hint: To rename the bookmark on the remote, you can `jj git push --bookmark bremote` first (to delete it on the remote), and then `jj git push --bookmark bremote2`. `jj git push --all --deleted` would also be sufficient.

Renaming back with jj bookmark rename bremote2 bremote prints Tracked remote bookmarks for bookmark bremote exist. as a warning, not an error. After restoring, jj git push --bookmark bremote2 reports bookmark: bremote2 [add to 1e76d54fcfce] (source).

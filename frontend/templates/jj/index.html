jj architecture

A detailed, source-linked map of how Jujutsu (jj) works inside: its layers, every persisted schema, its core data structures, and how real commands move through them.

The whole system on one page

The left side shows jj's layers, from the command line down to the files under .jj/. The right side shows the data model those layers store, with each arrow labelled by the field that links one object to the next. Every box links to the page that explains it, or to its source until that page exists.

The dashed arrow shows that the repo layer's View wraps and edits the stored view. Persistence follows the store names: the Backend (through Store) holds commits, trees and file contents; the OpStore holds operations and views; the OpHeadsStore records which operations are current heads; the IndexStore keeps a commit-graph index per operation; and the WorkingCopy records what's checked out on disk.

How jj config edit works

jj config edit --user|--repo|--workspace|--file PATH opens one config file in your editor, and reopens it until it parses or you choose to restore the previous contents.

In short: it picks exactly one file the same way config set does, creates it if it does not exist, and runs ui.editor on the file itself, not a copy. Afterwards it re-parses the file as TOML. If that fails, it asks whether to keep editing; answering no writes back the contents it loaded before the editor ran. It never loads the repo and never snapshots.

The command is cmd_config_edit. Its help text: "Start an editor on a jj config file. Creates the file if it doesn't already exist regardless of what the editor does." (source). It is the Edit variant of ConfigCommand, with the visible alias jj config e (source, dispatch).

1. Command-line surface

ArgumentMeaning
--userThe first user config file (test; source).
--repoThe repo's config file, kept outside the repo under the user's config directory (source, test).
--workspaceThe current workspace's config file (source).
--file PATHA file at a location jj recognizes as config; created with missing parents if absent (source).

The command has no other arguments: ConfigEditArgs is just the shared target group, of which exactly one is required (source, group).

The global flags are on the CLI page.

5. What it reads, and snapshotting

It reads the chosen config file, through the config already loaded at startup or from disk, and the edited file again after each editor run (source). It never loads the repo or the working copy, so there is no snapshot. It writes the file when it did not exist, and again only on a restore (source, restore); otherwise the only writer is the editor.

6. Algorithm and invariants

Creating the file first

If the chosen path does not exist, the loaded empty document is saved before the editor starts, so the file exists even if the editor is closed without saving. For --user and --repo, its directory is created too (test, test). The path is printed to stderr as Editing file: PATH (source).

The edit loop

After the editor exits successfully, the file is parsed with ConfigLayer::load_from_file, tagged with the file's source. Only TOML syntax is checked here, not whether the values suit jj's schema. On failure it prints "An error has been found inside the config:" and the error chain, then asks "Do you want to keep editing the file? If not, previous config will be restored." (source). Yes reopens the editor on the same, still-invalid file. No saves the ConfigFile that was loaded before the first editor run, putting back what was there (source).

Without a terminal

When the session cannot prompt, prompt_choice_with picks the default without waiting (source). The default here is yes, so with invalid contents the editor is simply run again.

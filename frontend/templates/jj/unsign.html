How jj unsign works

jj unsign rewrites signed revisions without their cryptographic signature and rebases their descendants. Unlike jj sign, it has no default revset and doesn't need a signing backend.

In short: jj resolves -r (nothing if it's omitted), checks the commits are mutable, and keeps only those that are signed. In one transaction it rewrites them with the sign behavior set to drop and reparents their descendants, which keep or lose signatures according to signing.behavior. It prints Unsigned N commits:, warns about commits authored by someone else, and records unsign commit <id>.

The command is cmd_unsign. It mirrors jj sign step for step; this page focuses on the differences. How commits are stored is on the commits page.

1. Command-line surface

FlagTypeDefaultMeaning
-r, --revision (alias --revisions)revsets, repeatablenoneWhat to unsign (source).

UnsignArgs

Without -r the list is empty, and a union of no revsets is none() (union_all), so the command changes nothing.

2. Configuration

No setting chooses what to unsign. signing.behavior (default keep) still applies to the rebased descendants, and user.email decides the "not authored by you" warning. Because the targets are written with drop, no backend is consulted for them, so jj unsign works even with signing.backend = "none" (write_to_store).

3. End-to-end flow

Filtering to signed commits means unsigned targets aren't rewritten at all and don't appear in the output, and their descendants aren't rebased because of them (source).

4. Core architecture touchpoints

  • Commit writing: Drop makes should_sign false, and the old signature is cleared before writing, so the new Git commit has no signature header (source).
  • Rewrites: each unsigned commit is a rewrite of the signed one; bookmarks follow and the working copy moves if @ was a target. See transactions.
  • Commit model: a commit is signed when its secure_sig is set (is_signed).

5. Transaction and operation

  • Transaction: one.
  • Operation description: unsign commit <id> or unsign commit <first id> and <N> more, with the new IDs (source).
  • Nothing to do: -r 'none()', or only unsigned targets, prints Nothing changed. (test).
  • jj undo brings the signed commits back.

6. Algorithm and invariants

So under the default keep, unsigning one commit in the middle of a signed stack leaves its descendants signed: they are rewritten, but signed again (test). Unsigning doesn't need your key, but re-signing a descendant does, so the backend must still be usable when descendants are signed.

Invariants: afterwards no target is signed. Unsigned targets are untouched. Contents, descriptions and authors don't change.

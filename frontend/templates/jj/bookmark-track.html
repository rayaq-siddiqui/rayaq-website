How jj bookmark track works

jj bookmark track links remote bookmarks to the local bookmark of the same name. The remote target is merged into the local one, creating it if needed, and from then on fetches update the local bookmark and pushes compare against the remote.

In short: jj takes either exact name@remote symbols or name patterns, optionally limited with --remote (default: every remote except the reserved git). It collects the matching remote bookmarks, including not-yet-existing ones for local bookmarks on a remote, and skips those already tracked with a warning. In one transaction it calls track_remote_bookmark on each: a three-way merge of the remote target into the local bookmark, then the state is set to tracked. It records track remote bookmark <symbols> and lists any bookmark left conflicted.

The command is cmd_bookmark_track. Its inverse is jj bookmark untrack. Bookmarks can also become tracked automatically on fetch through remotes.<name>.auto-track-bookmarks (see git fetch). How RemoteRef stores the tracking state is on the view page.

5. Transaction and operation

  • Transaction: always started; when nothing was selected, tx.finish finds no changes and prints Nothing changed. (source, test).
  • Operation description: track remote bookmark <name@remote, …> (source).
  • Commits: none created or rewritten.
  • jj undo restores the previous local target and tracking state.

6. Algorithm and invariants

Selecting remote bookmarks

With name@remote symbols, each is accepted if the remote bookmark exists, or if a local bookmark of that name exists and the remote is known; others are reported with No matching remote bookmarks for names (source). With patterns, jj takes every existing remote bookmark matching both name and remote patterns, plus, for every matching remote, an absent placeholder for each matching local bookmark the remote doesn't have (source). Mixing the two forms is rejected because a --remote or default would apply to only half the arguments (source).

Tracking is a merge

track_remote_bookmark merges with base tracked_target(), which is absent for an untracked ref (source), and other = the remote target. So:

  • No local bookmark: the local bookmark is created at the remote target.
  • Local bookmark at the same commit: unchanged.
  • Local bookmark elsewhere: the result is a conflicted bookmark with both targets, which jj then lists.

Invariants: tracking never moves the remote target. A tracked remote bookmark and the local bookmark of the same name are thereafter treated as one: fetches merge remote changes into the local bookmark, and pushes use the tracked target as the expected remote state.

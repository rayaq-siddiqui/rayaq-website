How jj tag delete works

jj tag delete removes local tags matching name patterns. The commits they pointed to are kept, and become mutable again unless something else keeps them immutable.

In short: jj matches the patterns against local tags, warns about exact names that don't exist, and prints No tags to delete. if nothing matched. Otherwise, in one transaction, it sets each matched tag's target to absent, prints Deleted N tags., and records delete tag <names>.

The command is cmd_tag_delete, also available as jj tag d (source). It is the tag counterpart of jj bookmark delete; to create or move tags, see jj tag set.

2. Configuration

None of its own. Because the default immutable_heads() includes tags(), deleting a tag can make its commit mutable again (source). In a colocated workspace the deletion is exported to Git.

5. Transaction and operation

  • Transaction: one, only when something matched (source).
  • Operation description: delete tag <name1, name2, …> (source).
  • Commits: none created or rewritten.
  • jj undo brings the tags back.

6. Algorithm and invariants

The patterns are unioned and matched against local tags only (source). A tag matched by several patterns is deleted once. The unmatched warning covers only exact names (warn_unmatched_local_tags), so unknown* just prints No tags to delete. Removing a tag goes through set_local_tag_target(name, absent).

Invariants: only local tag entries change; commits and present remote tags are untouched. All matches are deleted, or none.

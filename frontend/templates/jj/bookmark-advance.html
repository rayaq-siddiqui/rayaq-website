How jj bookmark advance works

jj bookmark advance moves the bookmarks closest to a target revision forward onto it. By default that's the nearest bookmarked ancestors of @, moved to @, and both "closest" and the target come from configurable revsets.

In short: jj resolves the target (--to, else revsets.bookmark-advance-to, default @). With bookmark names, it picks the local bookmarks matching them. Without, it evaluates revsets.bookmark-advance-from (default heads(::to & bookmarks())) with to bound to the target, and picks the bookmarks pointing into it. Bookmarks already at the target are dropped; if none remain, No bookmarks to update. Every move must be a fast-forward, and there's no override. In one transaction the bookmarks are pointed at the target, recorded as point bookmark <names> to commit <id>.

The command is cmd_bookmark_advance. Its help text calls jj bookmark advance --to x the equivalent of jj bookmark move --from 'heads(::x & bookmarks())' --to x (source); compare jj bookmark move, which has no configured defaults but allows --allow-backwards. Bookmark storage is on the view page.

5. Transaction and operation

  • Transaction: one, after selection and the checks (source). With nothing to update, no operation is recorded.
  • Operation description: point bookmark <name1, name2, …> to commit <full hex id>, the same text as bookmark move and set (source).
  • Commits created or rewritten: none. The working copy is only snapshotted.

6. Algorithm and invariants

Without names, the from-revset is parsed with a revset parse context whose local variables include to, set to a string node holding the target's full commit ID, so it behaves like a symbol naming that commit (source). Parse warnings are printed under In revsets.bookmark-advance-from. Every local bookmark is then checked: it is selected if any of its present targets is in the evaluated set (source).

With the default heads(::to & bookmarks()), that set is the bookmarked commits among the target's ancestors (including itself) that have no bookmarked descendant in that set. If the target already carries a bookmark, the set is just the target, and every selected bookmark is then dropped as "already there", giving No bookmarks to update. (source).

The fast-forward test is is_fast_forward: some present side of the old target must be an ancestor of the new one. Unlike bookmark move, there is no flag to skip it (source).

Invariants: never creates or deletes bookmarks, never moves one backwards or sideways, never rewrites commits. Either every selected bookmark moves or none does.

How jj workspace forget works

jj workspace forget removes workspaces from the repo's view, so they no longer have a working-copy commit. Their directories on disk are left alone. A working-copy commit that nothing else needs is abandoned.

In short: jj takes the named workspaces (default: the current one), warns about names it doesn't know, and in one transaction removes each from the view, abandoning its working-copy commit if that commit is empty with no description, a head, and not used by a bookmark, tag or other workspace. The operation is forget workspace <name>. Afterwards it disconnects any Git worktree the workspaces had.

The command is cmd_workspace_forget. To also delete the directory, use jj workspace remove. Workspaces are created with jj workspace add.

2. Configuration

None specific. The Git worktree step runs git as a subprocess, so git.executable-path applies (source).

3. End-to-end flow

The workspace store keeps the forgotten workspace's path on purpose: jj undo restores the workspace in the view, and it can only be found on disk again if the path is still recorded. A stale entry is ignored for workspaces not in the view, and overwritten if the name is reused (source).

4. Core architecture touchpoints

  • View: View::remove_workspace drops the workspace's working-copy commit ID and its recorded Git HEAD. See the view page.
  • Abandoning: MutableRepo::remove_workspace first calls maybe_abandon_wc_commit, the same rule jj edit and jj new use when leaving a working-copy commit.
  • Working copy: untouched. If the current workspace is forgotten, jj says so after the transaction (§7).
  • Git: a colocated secondary workspace is a Git worktree; forgetting it unlinks the worktree, but failures are only warnings because the workspace is already gone (unlink_git_worktree).

5. Transaction and operation

  • Transaction: one for all names, so jj undo restores all of them at once (source).
  • Operation description: forget workspace <name>, or forget workspaces <a>, <b> (source).
  • Commits: possibly abandoned working-copy commits. Only heads are abandoned, so nothing needs rebasing.

6. Algorithm and invariants

Workspaces are removed one at a time inside the transaction, so when several workspaces share a working-copy commit and are all forgotten together, the last one removed finds no other workspace using it, and the commit is abandoned (test).

Invariants: nothing on disk changes except Git worktree bookkeeping. Commits with content or a description are never abandoned.

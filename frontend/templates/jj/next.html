How jj next works

jj next moves the working copy forward along the commit graph. By default it starts a new empty working-copy commit on top of a child of @'s parent. With --edit it edits a child of @ directly instead.

In short: jj decides whether to edit (--edit, --no-edit, or ui.movement.edit). In new-commit mode @ must be a head. It builds a target revset: offset generations below the start (@'s parents, excluding @ itself, or @ when editing). With --conflict, it takes the first conflicted commits from there instead. Exactly one target is used directly. Several targets prompt for a choice, and none is an error. Then one transaction either checks out a new commit on the target (next: A -> B) or edits it (next: A -> editing B).

jj next is a thin wrapper: cmd_next calls the shared move_to_commit with Direction::Next. jj prev is the same code going the other way. The two outcomes are the same as jj new and jj edit.

5. Transaction and operation

  • Transaction: one, started after the target is chosen (edit, new).
  • Operation description: next: <old @ short id> -> <target short id>, or next: <old> -> editing <target> in edit mode (source). The second ID is the target commit, not the new working-copy commit.
  • Commits created: one empty working-copy commit in new-commit mode. None in edit mode.
  • Commits abandoned: the old @, if it was discardable and nothing else points at it.

6. Algorithm and invariants

The two modes count from different places (source). In edit mode the start is @, and the target is its descendants exactly offset generations down. In new-commit mode @ is a leaf sitting beside its siblings. The start is @'s parents, the first step is their other children (@ is excluded), and then offset − 1 more generations. So jj next after jj new X lands on top of a child of X.

With --conflict (source), the offset is left at its default of 1, since clap rejects passing both. The result is the roots of the conflicted commits at or below that first step: the nearest conflicts, one per branch.

Ambiguity is resolved by a prompt that lists the candidates numbered from 1, plus q. Without a terminal the prompt fails, and choosing q gives ambiguous target commit (choose_commit).

Invariants: new-commit mode never leaves @ with children, which is why it requires @ to be a head. Edit mode never edits an immutable commit. Neither mode rewrites an existing commit.

8. Worked example

From upstream's test_next_simple. After jj new @--, @ (royxmykx) is an empty child of second, beside third. Then jj next runs:

Upstream's snapshot:

$ jj next
Working copy  (@) now at: vruxwmqv 01f06d39 (empty) (no description set)
Parent commit (@-)      : kkmpptxz 7576de42 (empty) third

The start was @'s parent second. Its children other than @ are just third, and offset − 1 = 0 more steps leaves third. The old @ was empty and unreferenced, so it was abandoned. If second had two other children, jj would have prompted instead, as test_next_fails_on_bookmarking_children_no_stdin shows.

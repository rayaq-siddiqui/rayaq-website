How jj operation show works

jj operation show (alias jj op show) prints one operation, then what it changed in the repository compared to its parent: commits, working copies, bookmarks and tags.

In short: jj resolves the operation (default @), loads the repository at it and at its parent, renders the operation with the templates.op_show template, and hands both repositories to the same show_op_diff that jj operation diff uses. A merge operation, one with several parents, gets the template only and no diff. It never writes a new operation head.

The command is cmd_op_show. The help text: "Show changes to the repository in an operation" (source). It is registered as Show(OperationShowArgs) in the operation group (source, dispatch). In effect it is jj op diff --op OP with the operation's own template printed above the diff instead of the "From operation" and "To operation" lines.

5. What it reads, and snapshotting

It goes through workspace_helper, so the working copy is snapshotted first unless --ignore-working-copy is given (source). A snapshot writes an operation, which is then @, so jj op show right after editing files shows that snapshot. It reads the operation and its parents from the op store, the views and commit indexes of both repositories, and the commits it prints; with a diff format, also their trees and file contents.

Unlike jj op diff, it does not merge one index into the other: the operation's own repository is the one commits are looked up in (source). With a single parent that is enough, since the parent's commits are already in its index. A merge operation is skipped because "Merged repo may have newly rebased commits, which wouldn't exist in the index" (source). Nothing is published; a merged parent operation is written to the op store but is not an op head.

6. Algorithm and invariants

The comparison base

The diff is always against the operation's parents, merged: no parents (the root operation) compares the root with itself and prints nothing after the template; one parent is compared directly; several are merged but then not compared (source, source). To compare any two operations, use jj op diff --from … --to ….

What is printed

First the template output, then show_op_diff's sections, each starting with a blank line and skipped when empty: changed commits, as a graph or with -G flat; changed working copies; local bookmarks and tags; remote bookmarks and tags (source, source). How commits are classified as new, rewritten or abandoned, which commits are elided, and how patches are inter-diffs against the first predecessor, is on the operation diff page.

The template

The built-in template ends with a newline, so a blank line separates it from the diff. A custom template without one runs straight into the diff's own leading newline, which upstream's test shows as "Changed commits:" directly under the template text (test).

How jj debug works

jj debug is a hidden group of low-level commands for inspecting jj's internals: the index, the stores, the working-copy state, and the parsers for revsets, filesets and templates.

In short: one clap enum, hidden from jj --help, dispatching to fifteen small commands. Each picks how much of jj to load. Most go through the normal workspace helper; the index commands and debug object load only the workspace, so they can run when the repo itself would not load.

The group is DebugCommand, help text "Low-level commands not intended for users", marked #[command(hide = true)] (source). It is the Debug variant of the top-level Command enum (source, dispatch), and cmd_debug matches on it.

4. Core architecture touchpoints

PieceRole here
Indexdebug reindex resolves the operation before loading the repo, "The index might have to be rebuilt while loading the repo", then calls reinit and build_index_at_operation on the default index store; any other index type is "Cannot reindex indexes of type '…'" (source, test). debug index prints its stats (test).
Commit store and op storedebug object reads a commit, file, symlink or tree from the store, or an operation or view from the op store, by ID (source).
Revsets, filesets, templatesdebug revset and fileset print each parser's intermediate forms; debug template prints the parsed template tree (source) (fileset test, revset test).
Working copycheck_local_disk_wc downcasts to LocalWorkingCopy, failing with "This command requires a standard local-disk working copy" (source); debug local-working-copy and the watchman queries call it (source, watchman). debug snapshot only warns that it is deprecated and calls the workspace helper, which snapshots; use jj util snapshot (source).
Build featuresdebug watchman fails with "Cannot query Watchman because jj was not compiled with the watchman feature" when that feature is off (source); it is on by default (source).

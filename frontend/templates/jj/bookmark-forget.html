How jj bookmark forget works

jj bookmark forget removes a bookmark locally without scheduling a deletion on any remote. It deletes the local target and untracks the remote bookmarks, or with --include-remotes removes jj's record of them altogether.

In short: jj matches the patterns against every bookmark name, local or remote. In one transaction, for each match it sets the local target to absent. For each of its remote bookmarks it either forgets it (--include-remotes) or marks it untracked, except the special git remote, which is left alone. It prints how many local and remote bookmarks were forgotten and records forget bookmark <names>.

The command is cmd_bookmark_forget. Compare jj bookmark delete, which keeps remote bookmarks tracked so the deletion gets pushed. The help text explains the untracking: it ensures "the forgotten bookmark will not impact remotes on future pushes" (source).

2. Configuration

None of its own. In a Git-backed repo, remote bookmarks under the reserved remote name git (the colocated Git repo's own refs) can't be untracked, so they're skipped unless --include-remotes is given (source, default_ignored_remote_name). remotes.<name>.auto-track-bookmarks matters afterwards: a re-fetched bookmark may be tracked again automatically.

5. Transaction and operation

  • Transaction: one, only when something matched (source).
  • Operation description: forget bookmark <name1, name2, …>, listing every matched name (source).
  • Commits: none created or rewritten.
  • jj undo restores the bookmarks and their tracking state.

6. Algorithm and invariants

find_forgettable_bookmarks iterates view.bookmarks(), which yields each bookmark name with its local target and all its remote refs, and keeps names the pattern matcher accepts. So a bookmark that only exists remotely, or a deleted one, still matches, unlike with delete. The unmatched-name warning counts a name as present if it exists locally or on any remote (source).

For each match (source):

  1. The local target is set to absent; it counts toward "local bookmarks" only if it was present.
  2. With --include-remotes, every remote ref, including git's, is set to absent and counted.
  3. Otherwise refs on the git remote are skipped, and the rest are untracked: their target stays, but their state becomes New, so jj git push no longer pairs them with a local bookmark.

Invariants: forgetting never schedules a push. Without --include-remotes, remote targets are kept, so jj git fetch reports nothing new. With it, a fetch re-creates them as new remote bookmarks.

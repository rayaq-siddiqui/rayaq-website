How jj tag set works

jj tag set creates local tags, or moves existing ones with --allow-move, so they point at one revision. Because tags are in the default immutable set, tagging @ also makes jj start a fresh working-copy commit on top of it.

In short: jj resolves -r (default @). For each name, it refuses if the tag already exists and --allow-move isn't given, and counts new and moved tags. It warns if the target is empty. In one transaction every name is set to point at the target, jj prints Created N tags pointing to … and/or Moved N tags to …, and records set tag <names> to commit <id>. If @ became immutable, the transaction's finish adds a new empty working-copy commit on top.

The command is cmd_tag_set, also available as jj tag s (source). Unlike jj bookmark set, there is no fast-forward rule: an existing tag can be moved anywhere, but only on request. Tags are stored in the view next to bookmarks; see the view page.

2. Configuration

The default immutable_heads() includes tags(), so every tagged commit and its ancestors become immutable (source). That is what produces the new working-copy commit when @ is tagged. In a colocated workspace, the tag is exported to Git when the transaction finishes.

5. Transaction and operation

  • Transaction: one, after every name passed the check (source).
  • Operation description: set tag <name1, name2, …> to commit <id>, listing every name given, including ones that didn't change (source).
  • Commits: none rewritten; possibly one new working-copy commit.
  • jj undo restores the previous tags and working copy.

6. Algorithm and invariants

Every name is checked before anything changes, so one refused name stops the whole command (source). A deleted tag counts as absent here. A source TODO notes that if tracked remote tags gain push support, deleted tags should count as present until pushed, as bookmark set already does. The counts only feed the status lines: a tag already at the target is still "set", but counted as neither new nor moved.

Invariants: after the command every named tag points exactly at the target, as a normal (non-conflicted) ref. Existing tags never move without --allow-move. No commit is rewritten.

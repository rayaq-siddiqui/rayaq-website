How jj file show works

jj file show prints the contents of files in one commit. A single literal path is looked up directly; anything else walks the tree like jj file list. Each file is written to stdout as stored, and a conflicted file is written with conflict markers.

In short: jj resolves -r (default @) and parses the required filesets. If they are one literal path that names a file, it prints just that, and a missing path is an error. Otherwise it iterates tree.entries_matching(matcher) and prints every file under the match, warning about literal paths that named nothing. Before each file it renders -T or templates.file_show, which is empty by default. Nothing is written: no transaction, no operation.

The command is cmd_file_show, and the per-file output is write_tree_entries. The help text: "Print contents of files in a revision. If the given path is a directory, files in the directory will be visited recursively" (source).

The positional arguments go through parse_file_patterns, which unions each argument parsed with parse_maybe_bare (cli_util.rs, fileset.rs), so globs and operators work. Upstream's fileset docs cover the language.

2. Configuration

templates.file_show supplies the template when -T is absent, and the output is labelled file_show for colour rules (source). Its built-in value is the empty string, so by default the contents are printed with nothing before them (templates.toml): 

[templates]
file_show = ''

Setting it to something like '"--- " ++ path ++ "\n"' puts a header line before each file. The keywords are the same six TreeEntry methods jj file list uses, listed on its page.

5. What it reads, and snapshotting

  • No transaction, no operation of its own. The command only reads the repo it loaded (source).
  • Snapshot: workspace_helper snapshots the working copy first (source). If files changed on disk, that snapshot records its own operation.
  • Bytes as stored. A file is copied in 16 KiB chunks from the store's reader to stdout, with no decoding or end-of-line conversion (copy_async_to_sync). Files are concatenated with nothing between them unless the template adds it.
  • jj undo has nothing to revert, except the snapshot if one was taken.

6. Algorithm and invariants

Choosing a path. get_single_path returns a path only when the whole expression is one FilePath or PrefixPath pattern (source, the same split as as_path). On that fast path, the path's merged value decides (source):

  1. Absent: the command fails with No such path. Unlike the slow path, there is no warning-and-continue.
  2. A directory (is_tree: every present term is a tree, source): nothing is printed yet, and the slow path runs with the prefix matcher, which yields every file under it. A bare . at the workspace root takes this route too, since the root path's value is the whole tree.
  3. Anything else, a file, symlink, submodule or conflict: one entry is printed, and the command returns.

The slow path is the same walk as jj file list: depth-first, name order, directories pruned by the matcher, and trees never yielded as entries (details). Afterwards print_unmatched_explicit_paths warns about each literal path that is absent from the tree (source).

A conflict counts as a file conflict when every term is a file or absent; its contents are read and simplified with their labels (source). The merge is attempted again with the store's merge options, so a conflict that now resolves is printed as plain text; otherwise the markers use the configured style, a marker length long enough not to clash with the contents, and the files' own line endings (source). These are the same markers jj writes into the working copy; the conflicts page explains them.

Invariants: nothing is written anywhere but stdout and stderr. Files are printed in depth-first name order. Contents come from the commit's tree, never directly from disk. A missing single path fails before anything is printed; on the slow path the warning comes after all output.

8. Example output

From upstream's test_show. @- has file1 containing a. @ changes it to b and adds dir/file2 (c) and file3 (d): 

$ jj file show file1 -r @-
a

$ jj file show file1
b

$ jj file show dir
c

$ jj file show nonexistent
Error: No such path: nonexistent

A header template, and several files through a directory and a glob:

$ jj file show -T '"--- " ++ path ++ "\n"' .
--- dir/file2
c
--- file1
b
--- file3
d

$ jj file show 'file*'
b
d

$ jj file show file1 non-existent
b
Warning: No matching entries for paths: non-existent

A conflict. A new commit changes file1 to c and is rebased onto the commit where it is a, so the default diff style prints a diff and a snapshot: 

$ jj file show file1
<<<<<<< conflict 1 of 1
%%%%%%% diff from: rlvkpnrz fc7b369e (parents of rebased revision)
\\\\\\\        to: qpvuntsm eb7b8a1f (rebase destination)
-b
+a
+++++++ kmkuslsw f74f80c5 (rebased revision)
c
>>>>>>> conflict 1 of 1 ends

A symlink gets its header but no contents, and a warning on stderr (test_show_symlink): 

$ jj file show -T '"--- " ++ path ++ " [" ++ file_type ++ "]\n"' .
--- dir/file2 [file]
c
--- file1 [file]
a
--- symlink1 [symlink]
Warning: Path 'symlink1' exists but is not a file.

How jj config gc works

jj config gc lists per-repo config directories whose repo no longer exists, and deletes them if you confirm.

In short: repo config lives outside the repo, in one directory per repo under your config directory, next to a metadata file that records the repo's path. When a repo is deleted, its directory is left behind. This command scans those directories, keeps the ones whose recorded path is gone, prints them, and asks before deleting. The answer defaults to no. It never loads a repo and never snapshots.

The command is cmd_config_gc. Its help text: "Find and optionally delete repo-level config directories whose repo path no longer exists." (source). It is the Gc variant of ConfigCommand (source, dispatch).

1. Command-line surface

It takes no arguments of its own: ConfigGcArgs is empty (source). Two limits are recorded upstream as TODOs: workspace-level config directories are not collected, and there is no path argument to restrict which repo paths are considered (source).

The global flags are on the CLI page.

2. Configuration

No config setting changes what it does. The directory it scans is jj/repos under the platform's user config directory (source, source, REPO_CONFIG_DIR), the same place config path --repo points into. If there is no user config directory, the command fails with "No config directory found" (source).

5. What it reads, and snapshotting

It reads the repos config root, each subdirectory's metadata file, and whether each recorded path exists (source). It never loads a repo or a working copy, so there is no snapshot. It writes nothing unless you answer yes, and then only deletes.

6. Algorithm and invariants

Finding missing repos

If the root does not exist, the list is empty (source). Otherwise every entry is checked, and anything uncertain is kept rather than proposed for deletion: entries that are not directories, directories whose metadata cannot be read or decoded, and metadata with no path or a path that cannot be decoded are all skipped (source). A path whose existence cannot be checked, for example because of a permission error, counts as still existing (source). The result is sorted (source).

Confirming

The prompt defaults to no. Without a terminal, the default is taken automatically, so a non-interactive run only reports (source, test).

Deleting

Each directory is removed by deleting its two known files, ignoring either one being absent, and then calling remove_dir, which fails if anything else is left inside. So a file you put there yourself is never deleted; the directory stays, with a warning (source, test). A failure on one directory does not stop the others, and the final count includes only those removed (source).

8. Example output

From upstream's test, after the repo at $TEST_ENV/repo was deleted and y was typed at the prompt (source): 

$ jj config gc
Missing repo configs (repo path no longer exists):
  $TEST_ENV/home/.config/jj/repos/8e4fac809cbb3b162c95
    repo path: $TEST_ENV/repo/.jj/repo
Delete 1 missing repo config directories? (yN): Deleted 1 config directories.

The typed answer comes from stdin, so it does not appear in the captured stderr.

Without a terminal the same run answers n and prints Aborted; nothing was deleted. (test).

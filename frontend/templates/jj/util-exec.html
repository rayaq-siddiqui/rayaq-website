How jj util exec works

jj util exec runs another program and exits with its exit code, so an alias can run any script as a jj subcommand.

In short: it starts the program with the given arguments, adding JJ_WORKSPACE_ROOT to its environment when a workspace was found, waits for it, and exits with the same code. It never loads the repo and never snapshots. Upstream's help warns that it is "a convenient syntax for running arbitrary code on your system" (source).

The command is cmd_util_exec. Its help text: "Execute an external command via jj" (source). It is the Exec variant of UtilCommand (source, dispatch).

1. Command-line surface

ArgumentTypeDefaultMeaning
COMMAND (positional, required)stringnone"External command to execute" (source).
ARGS… (positional)stringsnone"Arguments to pass to the external command" (source).

The intended use is an alias such as my-script = ["util", "exec", "--", "my-jj-script"]; the -- makes jj pass the script's flags through instead of parsing them (source). The global flags are on the CLI page.

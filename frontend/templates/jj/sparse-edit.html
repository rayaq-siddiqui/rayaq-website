How jj sparse edit works

jj sparse edit opens the workspace's sparse patterns in your text editor, one per line, and applies whatever list you save: files under new patterns are checked out, files under dropped ones are deleted from disk. Commits and the operation log are untouched.

In short: jj loads the workspace, which snapshots it as usual, and locks the working copy. It writes the current patterns to a temporary .jjsparse file, runs ui.editor, then parses each non-blank line that doesn't start with JJ: as a workspace-relative path. The result is sorted and de-duplicated. From there it is exactly jj sparse set: update the files, save the working-copy state under the same operation ID, and print the checkout stats.

The command is cmd_sparse_edit; the editing is edit_sparse. The update itself is the shared update_sparse_patterns_with, described in detail on the sparse set page.

1. Command-line surface

No arguments or flags (SparseEditArgs). The global --config ui.editor=… picks the editor for one run.

5. Transaction and operation

  • Transaction and operation: none. The working copy is locked while the editor is open and saved with old_operation_id() (source).
  • Lock held during editing: because the editor runs inside the closure, the working-copy lock is held until you close the editor.
  • On error (bad line, editor failure) nothing is written: the closure returns before set_sparse_patterns runs (source).
  • jj undo doesn't apply. Edit again or run jj sparse reset.

6. Algorithm and invariants

  1. Render. Each stored pattern is turned into a workspace-relative filesystem path and written on its own line. An invalid stored path doesn't block editing, but one that isn't UTF-8 is an internal error (source). Upstream's test shows the root pattern written as . (source).
  2. Edit. TextEditor::edit_str writes the temporary file, runs the editor, and reads it back; errors are labelled sparse patterns (source, edit_str).
  3. Parse. Lines starting with JJ: are dropped, the rest are trimmed and blank ones skipped, and each is parsed with RepoPathBuf::from_relative_path. The first failure aborts with Failed to parse sparse pattern: <line> (source).
  4. Normalize. Sort and remove duplicates (source).
  5. Apply. As in sparse set: check out added prefixes, delete removed ones, store the list.

Invariants: the saved list is sorted and has no duplicates. Saving an empty file leaves no patterns, so every tracked file is removed from disk. Commits never change.

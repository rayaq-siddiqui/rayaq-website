How jj tag list works

jj tag list (alias jj tag l) prints tags and their targets, with the remote tags each local tag tracks below it, filtered by name, revision, remote and state.

In short: it is jj bookmark list over the view's tags. The same collect_items groups each local tag with its tracked remote tags, the same sort orders them, and each entry is rendered with templates.tag_list. Unlike the bookmark command it prints no hints afterwards, and its unmatched-name warning only looks at local tags. It writes nothing.

The command is cmd_tag_list. The help text: "List tags and their targets. By default, a tracked remote tag will be included only if its target is different from the local tag. An untracked remote tag won't be listed" (source). It is registered as List(TagListArgs) with the visible alias l (source, dispatch).

5. What it reads, and snapshotting

It goes through workspace_helper, so the working copy is snapshotted first unless --ignore-working-copy is given (source). It then reads the view's tags, the commits the template prints, the revset evaluation for -r, and, for commit-based sort keys, each group's first target commit (source). It starts no transaction and writes no operation.

6. Algorithm and invariants

Which tags are listed

Names and revisions are OR-ed "like cmd_git_push()"; the revsets are intersected with tags(all()) and matched against local targets only (source). The predicates are set exactly as for bookmarks: local-only tags unless -t or --remote; synced tracked remotes with -t, -a or --remote; untracked remotes with -a or --remote but not -t (source). The full table is on the bookmark list page.

The git pseudo-remote

In a colocated repository each tag also has a ref on the git remote, which is tracked. While it agrees with the local tag it is hidden by default and shown by -a or --remote=git; --tracked alone excludes it, so it printed nothing in upstream's test (test). Remote tags from a real remote are tracked by default; see jj tag track.

What is printed

Each group prints its primary ref and then its tracked remote refs, through the template (source). With the default template a conflicted tag prints (conflicted): with - and + lines for its removed and added targets (source).

7. Errors and edge cases

SituationBehaviour
An exact name with no local tag"Warning: No matching tags for names: …". Only local tags count, unlike jj bookmark list, which also accepts a remote one; glob patterns never warn (source, test).
A conflicted tagListed with its targets, with no hint (test). See jj tag set.
A deleted local tag still tracked on a remoteListed as name (deleted) with its remote below, as for bookmarks, but no hint is printed (source).

8. Example output

Three tags, one of them conflicted by concurrent operations, from upstream's test (source): 

$ jj tag list
conflicted_tag (conflicted):
  - rlvkpnrz 893e67dc (empty) commit1
  + zsuskuln 76abdd20 (empty) commit2
  + royxmykx 13c4e819 (empty) commit3
test_tag: rlvkpnrz 893e67dc (empty) commit1
test_tag2: zsuskuln 76abdd20 (empty) commit2

A revset and a name, which are not intersected (source), and newest first by committer date (source): 

$ jj tag list -r 'subject(commit1)' test_tag2
test_tag: rlvkpnrz 893e67dc (empty) commit1
test_tag2: zsuskuln 76abdd20 (empty) commit2

$ jj tag list --sort=committer-date-,name
conflicted_tag (conflicted):
  - rlvkpnrz 893e67dc (empty) commit1
  + zsuskuln 76abdd20 (empty) commit2
  + royxmykx 13c4e819 (empty) commit3
test_tag2: zsuskuln 76abdd20 (empty) commit2
test_tag: rlvkpnrz 893e67dc (empty) commit1

In a colocated repository, --all-remotes shows the git pseudo-remote (source): 

$ jj tag list --all-remotes
local-only: rlvkpnrz d3e8d245 (empty) local-only
  @git: rlvkpnrz d3e8d245 (empty) local-only

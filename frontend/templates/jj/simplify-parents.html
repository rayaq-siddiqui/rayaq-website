How jj simplify-parents works

jj simplify-parents removes redundant parent edges. If one parent of a merge is already an ancestor of another parent, that edge adds nothing to the history, so jj drops it. Trees are not changed.

In short: jj resolves the commits to simplify: -s sources with their descendants, plus -r revisions, or by default revsets.simplify-parents (reachable(@, mutable())). It checks they are all mutable. In one transform_descendants pass, each selected commit with more than one parent keeps only the parents that are heads of its parent set. Every commit whose parents changed is reparented with its tree unchanged. It reports Removed E edges from S out of N commits. and records simplify N commits.

The command is cmd_simplify_parents. The edge removal itself is CommitRewriter::simplify_ancestor_merge in jj-lib. jj rebase applies the same helper to the rebased commits when given --simplify-parents (source, use).

5. Transaction and operation

  • Transaction: one, after the rewritability check (source).
  • Operation description: simplify <N> commits, where N is the number of selected commits, not the number changed (source).
  • Commits rewritten: merges with a redundant parent, plus every descendant of a rewritten commit.
  • No-op runs: no parents change, so the transaction finishes with Nothing changed. (test).

6. Algorithm and invariants

For a commit A with parents (B, C) where C is an ancestor of B, the edge A→C is redundant: every commit reachable through C is already reachable through B. simplify_ancestor_merge asks the index for the heads of A's parent list and keeps only those, in their original order. If all parents are independent, as in a normal diamond merge, nothing changes (test_simplify_parents_no_change_diamond).

Only commits in the selected set are simplified. Their descendants are visited too, because transform_descendants walks all descendants. Those only get their parent IDs remapped, even if they have redundant edges themselves (source). The parent count used for the statistics is taken from the rewriter's intended new parents, which are already remapped to rewritten IDs (source).

Invariants: the set of ancestors of every commit is unchanged. Trees are unchanged. Only selected commits lose edges. Nothing immutable is touched.

8. Worked example

From upstream's test_simplify_parents_redundant_parent. Commit c (@) has parents a and b, and b is a child of a. Then jj simplify-parents -s @- (or -r @ -r @-) runs:

Upstream's snapshot:

$ jj simplify-parents -s @-
Removed 1 edges from 1 out of 3 commits.
Working copy  (@) now at: royxmykx 265f0407 c | c
Parent commit (@-)      : zsuskuln 123b4d91 b | b

@- is a | b (both parents of c), so -s @- selects a, b and c: "3 commits". Only c is a merge, and heads(a, b) = b, so one edge goes. c gets a new commit ID but the same tree, and the log is now the straight line a → b → c.

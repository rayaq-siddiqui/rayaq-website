How jj show works

jj show prints each revision's metadata with a template, then its diff against its parents. With no arguments it shows @; given a revset, it shows every commit in it, newest first.

In short: jj loads the workspace, which snapshots it, and evaluates the revsets (default @). It picks the template (-T, else templates.show) and the diff formats (the flags, else ui.diff-formatter). For each commit it renders the template, then diffs the merged tree of the commit's parents against the commit's own tree, with copy records from each parent. Nothing is written: no transaction, no operation.

The command is cmd_show. The help text: "Show revision metadata and diff" (source). Unlike jj log, it draws no graph and shows the diff unless --no-patch is given.

5. What it reads, and snapshotting

  • Snapshot: yes. It loads the workspace with workspace_helper (source), which snapshots the working copy first (source), so jj show includes current edits to @. That snapshot may record a snapshot working copy operation; show itself records nothing.
  • Reads: the view at the current (or --at-op) operation, the index, each shown commit and its parents, their trees, file contents for the diff, and copy records.
  • Output: through the pager, requested after evaluation and before the first commit is printed (source). The template output is labelled show commit for colours (source).

6. Algorithm and invariants

Choosing the formats

diff_formats_for reads at most one short and one long format from the flags (source). --tool=:name fills the slot of that built-in's kind; any other --tool fills the long slot with an external tool. If both slots are empty, it uses ui.diff-formatter. So the list is never empty, and --stat --git prints a histogram followed by a Git diff. Each format then makes its own pass over the tree diff, in that order (source).

What a commit is diffed against

show_patch diffs parent_tree() against the commit's tree. If the index's changed-path data says the commit changed nothing, the parent tree is the commit's own tree and the diff is empty at no cost (source). A single parent's tree is used as it is. For a merge, the parents' trees are merged with their merge bases, found recursively (parent_tree, merge_commit_trees_no_resolve_without_repo), and resolved where possible. The diff therefore shows only what the merge commit itself changed, not everything each side brought in.

Copies and renames come from the backend's copy records between each parent and the commit (source), filtered by the matcher, which for show is EverythingMatcher (source). The tree diff pairs them up, so a rename is printed once as file1 => file3 instead of a deletion and an addition.

Order

Commits are streamed in index order, newest first (source), not topologically grouped as in jj log. --reversed has to collect the whole stream first to flip it (source). There is no limit flag.

Invariants: each commit in the set is printed once, header then diff. An empty revset prints nothing and is not an error (test). Nothing in the repository changes.

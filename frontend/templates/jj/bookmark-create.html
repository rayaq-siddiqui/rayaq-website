How jj bookmark create works

jj bookmark create adds one or more new local bookmarks pointing at a commit. It refuses names that already exist, including deleted bookmarks still tied to a remote. It can also start tracking the matching remote bookmarks automatically.

In short: jj resolves the target (default @) and checks every name. A present local bookmark is an error, and so is a name with tracked remote bookmarks. It warns if the target is empty. In one transaction it sets each bookmark to point at the target. For every configured remote whose auto-track pattern matches the name, and which jj knows about, it also tracks name@remote. The operation is create bookmark <names> pointing to commit <id>.

The command is cmd_bookmark_create. It is the strict sibling of jj bookmark set, which creates or moves. To move existing bookmarks by where they point, see jj bookmark move. How bookmarks are stored, including conflicted targets and remote tracking, is on the view page.

5. Transaction and operation

  • Transaction: one, after all names pass their checks (source). Any failing name aborts the whole command before anything is written.
  • Operation description: create bookmark <name1, name2, …> pointing to commit <full hex id> (source). Upstream's duplicate test shows one in an undo message: create bookmark c pointing to commit 387b9287….
  • Commits created or rewritten: none.
  • Working copy: snapshotted at the start, and otherwise untouched.
  • jj undo removes the bookmarks again, and undoes any auto-tracking.

6. Algorithm and invariants

Each name is checked before anything changes (source). A present local bookmark means the name is taken. A deleted local bookmark whose remote bookmarks are still tracked also counts as taken. jj treats re-pointing it as resurrection, which belongs to bookmark set. Untracked remote bookmarks don't block creation. Creation itself is an unconditional overwrite with a single-target RefTarget. No fast-forward rule applies, since there's no previous target.

Auto-tracking runs per name and per remote (source). The per-remote matchers are the union of auto-track-bookmarks and auto-track-created-bookmarks. Remotes without a view in the repository are skipped. track_remote_bookmark merges the remote bookmark's current target into the new local one (source). The merge base is the remote bookmark's tracked target, which is absent for a bookmark that wasn't tracked. So if name@remote already points elsewhere, the new local bookmark can end up conflicted, which is why jj warns first.

Invariants: never overwrites an existing bookmark. Never rewrites a commit. Either every requested bookmark is created, or none is.

From upstream's test_bookmark_multiple_names and test_bookmark_move. In a fresh repository, jj bookmark create -r@ foo bar creates two bookmarks on the empty working-copy commit. Later, after foo was pushed and then deleted locally, jj bookmark create foo is refused:

Upstream's snapshots of the two runs:

Hint: Use `jj bookmark set` to recreate the local bookmark. Run `jj bookmark untrack foo` to disassociate them.

After jj bookmark untrack foo and jj bookmark delete foo, the same create succeeds, and foo@origin stays as an untracked remote bookmark.

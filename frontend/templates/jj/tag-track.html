How jj tag track works

jj tag track links remote tags to the local tag of the same name. The remote target is merged into the local tag, creating it if needed, and later fetches keep the two in step.

In short: it is jj bookmark track for tags. jj takes name@remote symbols or name patterns (with an optional --remote, default every remote except git), skips refs already tracked, and in one transaction calls track_remote_tag on each: a three-way merge of the remote target into the local tag, then the state becomes tracked. It records track remote tag <symbols>. Unlike the bookmark command, it doesn't list conflicted results afterwards.

The command is cmd_tag_track. Remote tags fetched by jj git fetch or jj git clone are tracked by default, as upstream's test shows, so this command is mainly for tags that were untracked (source). Its inverse is jj tag untrack.

5. Transaction and operation

  • Transaction: always started; with nothing new to track, tx.finish prints Nothing changed. (source).
  • Operation description: track remote tag <name@remote, …> (source).
  • Commits: none created or rewritten.
  • jj undo restores the previous local target and tracking state.

6. Algorithm and invariants

Selection mirrors bookmarks exactly: resolve_trackable_remote_tags accepts a symbol if the remote tag exists, or a local tag of that name exists and the remote is known; trackable_remote_tags_matching adds absent placeholders for local tags missing on a matching remote. Tracking then merges with base tracked_target(), absent for an untracked ref, so a missing local tag is created, an equal one is unchanged, and a different one becomes conflicted (source).

Invariants: remote targets never change. Tracked refs are skipped with a warning, never re-merged.

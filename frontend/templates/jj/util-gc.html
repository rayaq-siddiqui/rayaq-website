How jj util gc works

jj util gc deletes operations, views and Git objects that the current operation can no longer reach and that are older than a cutoff.

In short: it refuses to run unless it is at the head operation. It then asks the operation store to delete operation and view files not reachable from the current operation, and, on the Git backend, rewrites jj's refs/jj/keep/* refs to match the commit index's heads and runs git gc. Anything newer than the cutoff (two weeks ago, or now with --expire=now) is kept, so another process's fresh work isn't deleted. It records no operation.

The command is cmd_util_gc. Its help text: "Run backend-dependent garbage collection." To reclaim old operations, upstream says to run jj op abandon ..<some old operation> first (source). It is the Gc variant of UtilCommand (source, dispatch).

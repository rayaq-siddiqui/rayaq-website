Number math

Some problems are arithmetic in disguise: take a number apart digit by digit, put it back together in another order or base, multiply numbers too big to store, or raise something to a huge power. The tools are old and small, divmod by ten, a carry, a bound checked before it is crossed, and squaring instead of repeating, and each one turns a slow or overflowing answer into a fast and exact one.

Problem

These questions hand you a number, or a string of digits, and ask you to transform it: reverse it, test it for symmetry, convert it to or from another notation, add one, multiply two of them, or compute a power. The obvious answers either convert to a string and back (often banned, or hiding the point), loop n times when n is a billion, or quietly overflow a 32-bit integer that the problem says you must respect. The pattern is to treat a number as a sequence of digits in some base, process it from the cheap end (the last digit, the lowest bit), and keep every intermediate value inside its stated range.

Intuition

A number written in base ten is a list of digits wearing a disguise. x % 10 reads the last digit, x // 10 removes it, and r * 10 + d appends d to r. With those three moves you can pop digits off one number and push them onto another, which reverses it, and you never need a string. The only thing to watch is the size of what you are building: in Python integers never overflow, but the problems are set for languages where they do, and the interviewer wants to see you check the bound before the multiply that would break it.

Powers work the same way in base two. Thirteen is 1101 in binary, so x13 = x8 · x4 · x1. The powers x, x2, x4, x8 each come from squaring the one before, so you only need as many squarings as n has bits, and you multiply in the ones whose bit is set.

Mechanics

Peeling and building digits

Invariant for reversing: after k steps, result holds the last k digits of x in reverse order and rest holds the other digits in their original order. Each step moves one digit from the end of rest to the end of result, so after ⌈log10 x⌉ steps rest is empty and result is the full reversal. Work on abs(x) and put the sign back at the end: Python's % and // round toward minus infinity, so -123 % 10 is 7, not −3, which is a classic surprise for people coming from C or Java.

Checking the bound before crossing it

If the answer must fit in [−231, 231 − 1], the step result * 10 + digit overflows exactly when result > INT_MAX // 10, or when result == INT_MAX // 10 and digit > INT_MAX % 10 (which is 7). Testing this before the multiply is what makes the check meaningful in a fixed-width language, where the overflowed value would already be garbage. The same check, with the negative bound's last digit 8, clamps atoi. Python will happily compute the big number, so on these problems you either check the bound explicitly or compare the final value against the range; the first is the answer an interviewer is looking for.

Reversing only half

Palindrome Number has a neater invariant: keep moving digits from rest to half while rest > half. When the loop stops, half has at least as many digits as rest, so it holds the back half reversed. The number is a palindrome when the halves are equal (even length) or equal after dropping the middle digit with half // 10 (odd length). Only half the digits are ever built, so no overflow is possible. Negative numbers and positive numbers ending in 0 are rejected up front: no palindrome starts with a minus sign or a leading zero.

Square-and-multiply

Write n in binary as a sum of distinct powers of two. Then xn is the product of x2k over the set bits k. The loop keeps power = x2k for the current bit and result = the product of the powers for the bits already read. Each iteration multiplies power into result if the bit is set, squares power, and shifts n right. That is at most 2 log2 n multiplications. A negative n means 1 / x−n, so invert x first and use −n; in a fixed-width language take care that −(−231) does not fit, which is why the exponent is widened before negating.

Multiplying digit strings

For digit strings a (length m) and b (length n), the product has at most m + n digits. Index the result slots 0 to m + n − 1 from the left. Digit a[i] stands for a[i] · 10m−1−i and b[j] for b[j] · 10n−1−j, so their product's units digit belongs at power m + n − 2 − i − j, which is slot i + j + 1, and its tens digit at slot i + j. Processing pairs from the right and adding into those two slots keeps every slot except the leftmost touched one below ten, and the last pair settles slot 0. Strip leading zeros at the end, keeping one zero if the product is zero.

Other bases and notations

Converting to base b peels digits with divmod(n, b), most significant last, so reverse at the end. Excel column titles are base 26 with digits A–Z standing for 1–26 and no zero (bijective base 26), so subtract one before each divmod: then the remainder 0 to 25 maps onto A to Z, and Z (26) does not spill into a phantom zero digit. Roman numerals are additive with one rule: a symbol worth less than its right neighbour is subtracted. Greatest Common Divisor of Strings reduces to Euclid on the lengths once you check that the two strings commute, s + t == t + s, which holds exactly when both are repeats of one common block.

Implementation

INT_MAX, INT_MIN = 2**31 - 1, -2**31


def reverse(x):
    sign = -1 if x < 0 else 1
    limit = INT_MAX if sign > 0 else -INT_MIN
    rest, result = abs(x), 0
    while rest:
        rest, digit = divmod(rest, 10)
        if result > limit // 10 or (result == limit // 10 and digit > limit % 10):
            return 0                      # checked before the multiply that would overflow
        result = result * 10 + digit
    return sign * result


def my_pow(x, n):
    if n < 0:
        x, n = 1 / x, -n
    result = 1
    while n:
        if n & 1:
            result *= x
        x *= x
        n >>= 1
    return result

Variations and edge cases

def is_palindrome(x):
    if x < 0 or (x % 10 == 0 and x != 0):
        return False
    half = 0
    while x > half:
        x, digit = divmod(x, 10)
        half = half * 10 + digit
    return x == half or x == half // 10


def multiply(a, b):
    slots = [0] * (len(a) + len(b))
    for i in range(len(a) - 1, -1, -1):
        for j in range(len(b) - 1, -1, -1):
            total = int(a[i]) * int(b[j]) + slots[i + j + 1]
            slots[i + j + 1] = total % 10
            slots[i + j] += total // 10
    return "".join(map(str, slots)).lstrip("0") or "0"


def column_title(n):
    letters = []
    while n:
        n, r = divmod(n - 1, 26)          # bijective base 26: digits are 1..26
        letters.append(chr(ord("A") + r))
    return "".join(reversed(letters))


def plus_one(digits):
    for i in range(len(digits) - 1, -1, -1):
        if digits[i] < 9:
            digits[i] += 1
            return digits
        digits[i] = 0
    return [1] + digits
  • Negative numbers in Python. -7 // 2 is −4 and -7 % 2 is 1. Work on abs(x), or use int(a / b) and math.fmod when you need truncation toward zero.
  • The asymmetric range. −231 fits but 231 does not, so the positive and negative bounds have different last digits (7 and 8). Negating INT_MIN overflows in fixed-width languages.
  • Zero. Reversing 0, multiplying by "0", and a column title for 1 ("A") are the inputs where loops run zero times or strip every digit; return "0" rather than the empty string.
  • Floating point. x ** 0.5 and math.log10 round; use math.isqrt and integer loops when exactness matters, and compare floats with a tolerance.
  • Modular answers. When a problem says "return it modulo 109 + 7", reduce after every addition and multiplication; Python's built-in pow(x, n, m) is square-and-multiply with a modulus.

Complexity and tradeoffs

  • Digit loops (reverse, palindrome, digit sums, base conversion): O(log x) time, one step per digit, and O(1) space. Converting to a string is also O(log x) and is fine unless the problem forbids it.
  • Pow: O(log n) multiplications against n − 1 for the naive loop, which times out at n = 231. The recursive form, xn = (xn/2)2, is the same algorithm with O(log n) stack.
  • Multiply strings: O(m · n) time and O(m + n) space. Karatsuba's divide and conquer is O(n1.585) and FFT-based methods are near-linear, which is what Python uses for huge integers, but nobody expects them in an interview.
  • gcd: O(log min(a, b)) steps; the worst case is consecutive Fibonacci numbers (Lamé's theorem).
  • When it is the wrong tool. Adding numbers stored as linked lists is the same carry loop but belongs to linked lists. Counting lattice paths is a binomial coefficient, but grid DP is the safer derivation. Repeated digit-square sums that may loop forever, as in Happy Number, are a cycle question for fast and slow pointers.

Problems

Start with Palindrome Number and Plus One to get used to digits and carries, then Reverse Integer for the overflow check and Pow(x, n) for square-and-multiply. Multiply Strings is the one most people need to practise twice: derive the i + j + 1 slot rather than memorizing it.

Check yourself

Why does reversing x = 1534236469 return 0, and at which step is that decided?

The reversal 9646324351 exceeds 231 − 1. At the last step the partial result is {{ over.rows[-1].before }}, already greater than INT_MAX // 10 = {{ over.limit // 10 }}, so any further digit would overflow and the check returns 0 before multiplying.

How many multiplications does square-and-multiply use for 313, and why is it at most about 2 log2 n?

{{ pw.multiplications }}. Each of the log2 n bits costs at most one squaring and at most one multiply into the result.

Why does the units digit of a[i] · b[j] go into slot i + j + 1?

a[i] is worth 10m−1−i and b[j] is worth 10n−1−j, so the product is worth 10m+n−2−i−j. In a slot array of length m + n indexed from the left, slot k holds 10m+n−1−k, so k = i + j + 1.

Why does column 26 come out as Z rather than "A@" or "AZ"?

Subtracting one first gives 25 = 26 · 0 + 25, so the only digit is Z and the quotient is 0. Without the shift, 26 = 26 · 1 + 0 would produce a zero digit that the notation does not have.

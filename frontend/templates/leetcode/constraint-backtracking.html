Constrained backtracking

The generate-everything search from the previous page is exponential, and most of it is wasted. If a half-built answer already breaks a rule, no way of finishing it can succeed, so the search should abandon it on the spot. Constrained backtracking is the same choose-explore-unchoose loop with one extra question before each choice: does this still have a chance? Asking it cheaply and early is where all the speed comes from.

Problem

You must find one, all, or the number of arrangements that satisfy rules: numbers that add to a target, queens that do not attack each other, a path of letters through a grid, a string cut into palindromes. Checking a finished answer is easy; the trouble is the astronomical number of candidates. The rules, however, usually become violated early, long before the answer is complete, and that is the opening.

SignalPatternWhy
"Combinations that add up to a target"Sorted candidates, a remaining sum, break when a candidate overshootsEverything after an overshooting candidate in sorted order overshoots too.
"Place pieces so none conflict" (queens, sudoku)Place one piece per step, keep sets of used columns, rows or diagonalsA conflict test in constant time rejects a square before any recursion.
"Does this word exist in the grid"DFS with a visited mark that is undone on returnA cell may be reused by a different path, but never twice in one path.
"Partition so that every piece satisfies a property"Extend a prefix only with a valid next pieceAn invalid piece makes the whole branch dead.
"Split into k groups of equal sum"Fill one bucket at a time, prune on overshoot and on repeated bucket statesMany orderings of the same items lead to the same state.
"Count or optimize, with overlapping subproblems"Dynamic programming or memoizationIf the remaining problem repeats, cache it instead of searching it again.

Intuition

Walking a maze, you do not walk to the end of every corridor to learn it is a dead end. You turn around the moment you see the wall. Backtracking with constraints is the same: you test each next step against the rules, and a step that breaks a rule is never taken, which removes the entire subtree behind it with one comparison.

The power of that cut depends on how early it happens. Rejecting a bad queen on the second row saves every placement of rows three to eight; rejecting a bad grid letter on the first mismatch saves every longer path. So the craft is in ordering the choices and choosing the constraint test so that failures show up as high in the tree as they can.

Mechanics

The invariant

At every call, the path so far satisfies all the rules that can be checked on a partial answer. Each recursive step adds one choice that is validated before it is made, so the invariant holds on entry to the child. When the path is complete, it is therefore a valid answer; when no legal choice remains, the call returns and the loop in the parent tries its next option. Nothing valid is lost, because a rejected choice would have broken a rule that no extension could repair.

That last clause is the correctness condition for any pruning rule: it must only reject a branch when no completion of it is valid. A rule that rejects too much loses answers; a rule that rejects too little is merely slow.

Keeping the check cheap

The test runs at every node, so it must not scan the board. Keep the facts in sets that you update on choose and restore on unchoose:

  • For N-Queens, three sets: used columns, used row - col diagonals and used row + col anti-diagonals. A square is safe if all three miss. One queen per row is guaranteed by recursing one row at a time.
  • For combination sum, the remaining target. Sorting the candidates once means the first candidate that exceeds the remainder ends the loop with a break, not a continue.
  • For word search, the current index into the word, and a visited mark written into the grid itself and restored on the way out.

Where the cuts come from

Three kinds of pruning cover almost every problem. Feasibility: reject a choice that already violates a rule (a queen under attack, a letter that does not match). Bounds: reject when even the best case cannot succeed (the remaining sum is negative, too few items are left). Symmetry and duplicates: do not explore two branches that lead to the same state (a start index so combinations are not reordered, a sort and skip for equal values).

The path may bend but never reuses a cell, so each cell is marked while it is on the path and restored when the search backs out.

Implementation

def combination_sum(candidates, target):
    nums = sorted(candidates)
    results, path = [], []

    def explore(start, remaining):
        if remaining == 0:
            results.append(path[:])
            return
        for i in range(start, len(nums)):
            if nums[i] > remaining:
                break                          # sorted: every later candidate overshoots too
            path.append(nums[i])
            explore(i, remaining - nums[i])    # i, not i + 1: the same item may repeat
            path.pop()

    explore(0, target)
    return results


def solve_n_queens(n):
    cols, diag, anti = set(), set(), set()
    placed, boards = [], []

    def explore(row):
        if row == n:
            boards.append(["." * c + "Q" + "." * (n - c - 1) for c in placed])
            return
        for col in range(n):
            if col in cols or row - col in diag or row + col in anti:
                continue
            cols.add(col); diag.add(row - col); anti.add(row + col)
            placed.append(col)
            explore(row + 1)
            placed.pop()
            cols.remove(col); diag.remove(row - col); anti.remove(row + col)

    explore(0)
    return boards


def exist(board, word):
    rows, cols = len(board), len(board[0])

    def explore(r, c, i):
        if board[r][c] != word[i]:
            return False
        if i == len(word) - 1:
            return True
        saved, board[r][c] = board[r][c], "#"
        found = any(
            0 <= nr < rows and 0 <= nc < cols and explore(nr, nc, i + 1)
            for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1))
        )
        board[r][c] = saved
        return found

    return any(explore(r, c, 0) for r in range(rows) for c in range(cols))

Variations and edge cases

def partition_palindromes(s):
    results, path = [], []

    def explore(start):
        if start == len(s):
            results.append(path[:])
            return
        for end in range(start + 1, len(s) + 1):
            piece = s[start:end]
            if piece == piece[::-1]:
                path.append(piece)
                explore(end)
                path.pop()

    explore(0)
    return results
  • Sudoku. The same template with one set per row, column and box. Always fill the empty cell with the fewest legal digits first; that ordering often turns a hard puzzle into a quick one.
  • Equal-sum partitions (Matchsticks, k equal subsets). Sort descending so big items fail fast, reject early if the total is not divisible by k, and skip trying an empty bucket twice, because two empty buckets are interchangeable.
  • Word Break II. The prefix-extension shape of the palindrome code, with the dictionary lookup as the test. Memoize the answers for each suffix when words overlap heavily, or the search repeats itself.
  • Marks that leak. Restoring the grid cell must happen on every exit path, including the early success return, or later searches see a damaged grid. Using any(...) with a restore after it keeps the exits to one.
  • Break versus continue. break is only right when the candidates are sorted and the failing test is monotonic. Otherwise use continue.
  • Edge cases: a target of zero (the empty combination), no candidate small enough, a 1-cell grid, a word longer than the grid, an N that has no solution (2 and 3 queens) and a string that is already a palindrome.

Complexity and tradeoffs

  • Time: still exponential in the worst case: up to n! for queens and 4L for a word of length L on a grid. Pruning does not change the bound; it shrinks the constant enormously, and the real cost is the number of nodes that survive the checks.
  • Space: O(depth) for the call stack and the path, plus the constraint sets.
  • Baseline. Generate every candidate and filter at the end. For 8 queens that is millions of boards against {{ q8.nodes | length }} nodes.
  • When it fails. If the same subproblem recurs (the same remaining sum with the same suffix of candidates, the same string suffix), memoizing it, or turning the search into a table, beats backtracking. If the question asks for a count or an optimum rather than the arrangements, dynamic programming is usually the intended tool. If a bad ordering makes the first branches hopeless, reorder so the most constrained choice comes first.

Check yourself

Why is break correct in combination sum but wrong if the candidates are not sorted?

With sorted candidates, once nums[i] exceeds the remaining sum, every later candidate is at least as large and also exceeds it. Unsorted, a later candidate could be small enough, so break would lose answers; you would have to continue. Here it cut the candidates examined from {{ cs_raw.tested }} to {{ cs.tested }}.

What do the three sets in N-Queens test?

Whether the column is taken, and whether the two diagonals through the square are taken. Squares on one diagonal share row - col, and on the other share row + col, so each test is a constant-time set lookup. Rows need no set because the recursion places exactly one queen per row.

What goes wrong if word search forgets to restore the cell on a failed path?

The cell stays marked as visited, so another branch that legitimately needs it sees a wall and the search can report "not found" for a word that is in the grid. Every exit must undo the mark.

The 4-queens search built {{ q.nodes | length }} nodes. Why not 256?

256 counts every way to put a queen in each row. The search only builds a node when the new queen is safe, and it never extends a board that already has a conflict, so whole subtrees of the 256 are never visited.

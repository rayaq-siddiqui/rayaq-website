Linear DP

Linear dynamic programming has a one-dimensional state: the answer for the first i items, or for the last i steps. Each entry is a short formula in the one, two or three entries before it. Climbing stairs, robbing houses, decoding digits and multiplying runs are all this one shape with different formulas.

Problem

You are scanning a row (stairs, houses, digits, numbers) and each position offers a small set of choices that depend on only the last few positions. Brute force tries every combination of choices, which grows exponentially with length. A linear DP records, for each prefix, the one number that matters, and builds the next from the previous few.

SignalPatternWhy
"Number of ways to reach / decode / tile length n"dp[i] sums dp[i - k] for each allowed last stepEvery way ends with one last step, and what came before is a smaller instance.
"Cheapest way to reach the end taking one or two steps"dp[i] = min over the last stepOnly the cost of the two previous positions matters.
"Pick items, but no two adjacent"Take-or-skip recurrenceTaking item i forces skipping i - 1, so it extends dp[i - 2]; skipping extends dp[i - 1].

Two players alternate and both play welldp holds the mover's leadThe opponent's best play is the same problem from the next position, subtracted.
The ends touch (a ring)Solve the line twice, with each end removedThe first and last cannot both be used, so one of them is out.

Intuition

Standing on stair 7 you got there from stair 6 or from stair 5, and no other way. So the number of ways to reach 7 is the ways to reach 6 plus the ways to reach 5. Nothing about how you reached 6 changes what you can do next, which is exactly the "sufficient state" test from the fundamentals page. The table for 0 to 7 stairs is {{ stairs | join(", ") }}: each entry is the sum of the two before it, so this is the Fibonacci sequence shifted by one place.

The skill is writing the recurrence from the last decision. Ask: how can the answer for the first i items end? Each different ending is one term, and what precedes it is a smaller instance of the same question, already in the table.

Mechanics

The shape of every linear DP

  1. dp[i] is the answer for the prefix of length i (or position i).
  2. List the ways the prefix can end: the last step, the last item taken or skipped, the last one or two digits used.
  3. Each way contributes dp[i - k] adjusted by that last choice. Combine with sum (counting), min or max (optimizing).
  4. Seed the first one or two entries. Loop left to right. Keep only the last few entries if memory matters.

Take or skip

For the best total of non-adjacent values, best[i] = max(best[i - 1], best[i - 2] + nums[i]). Skipping house i leaves the best of the first i - 1 houses. Taking it means house i - 1 is unavailable, so you add to the best of the first i - 2. There are no other cases, so the maximum of the two is optimal. To recover which houses were taken, walk back: if best[i] equals best[i - 1], house i was skipped, otherwise it was taken and you jump two back.

Digit strings

To count ways to read digits as letters 1 to 26, the last letter is either the final digit (valid if it is not 0), which adds dp[i - 1], or the final two digits as a number from 10 to 26, which adds dp[i - 2]. A zero can never stand alone, so a "0" that cannot pair with the digit before it makes the count 0.

Products with negative numbers

The biggest product of a run ending at i is not determined by the biggest product ending at i - 1, because multiplying by a negative number reverses order. So carry two values: the biggest and the smallest product of runs ending here. For a new value x, both come from the three candidates x alone, biggest times x and smallest times x. The answer is the largest "biggest" seen.

Invariant

After processing position i, the stored value for i equals the true optimum over every choice sequence for the first i + 1 items. The proof is induction: every sequence ends in one of the listed ways, and for each way, the best completion uses an optimal prefix because the prefix and the last choice do not interact beyond the state.

Implementation

def climb_stairs(n):
    prev, cur = 1, 1
    for _ in range(n - 1):
        prev, cur = cur, prev + cur
    return cur


def rob(nums):
    skip = take = 0               # best without / with the previous house
    for value in nums:
        skip, take = max(skip, take), skip + value
    return max(skip, take)


def num_decodings(s):
    prev, cur = 1, 1 if s and s[0] != "0" else 0   # dp[i-2], dp[i-1]
    for i in range(2, len(s) + 1):
        ways = cur if s[i - 1] != "0" else 0
        if 10 <= int(s[i - 2:i]) <= 26:
            ways += prev
        prev, cur = cur, ways
    return cur if s else 0


def max_product(nums):
    high = low = best = nums[0]
    for x in nums[1:]:
        high, low = max(x, high * x, low * x), min(x, high * x, low * x)
        best = max(best, high)
    return best

Variations and edge cases

def rob_ring(nums):
    if len(nums) == 1:
        return nums[0]
    return max(rob(nums[:-1]), rob(nums[1:]))


def min_cost_climbing(cost):
    a = b = 0
    for i in range(2, len(cost) + 1):
        a, b = b, min(b + cost[i - 1], a + cost[i - 2])
    return b


def tribonacci(n):
    a, b, c = 0, 1, 1
    for _ in range(n):
        a, b, c = b, c, a + b + c
    return a


def integer_break(n):
    best = [0, 1] + [0] * (n - 1)
    for i in range(2, n + 1):
        best[i] = max(max(j * (i - j), j * best[i - j]) for j in range(1, i))
    return best[n]


def stone_game_iii(values):
    n = len(values)
    diff = [0] * (n + 1)
    for i in range(n - 1, -1, -1):
        diff[i] = max(sum(values[i:i + k]) - diff[i + k] for k in (1, 2, 3) if i + k <= n)
    return diff[0]
  • Ring. Run the line version twice, once without the first and once without the last; the single-element case needs its own return.
  • Longer steps. If you can climb 1, 2 or 3 stairs, the recurrence sums three previous entries. Tribonacci for 0 to 10 is {{ trib | join(", ") }}.
  • Splitting a number. Breaking 10 into at least two positive parts to maximize the product has table {{ brk.table | join(", ") }} and answer {{ brk.answer }} (3 + 3 + 4). Each part may stay whole or be split again.
  • Game DP. Store the mover's lead. Moving takes some stones and then it is the opponent's turn with their lead subtracted. For the row {{ stones | join(", ") }} the first player's lead is {{ game.lead }}, so the {{ game.result }} player wins.
  • Zeros. In decode ways, a lone 0 contributes nothing and 10 or 20 can only be read as a pair. Handle both before adding.
  • Edge cases: empty input, a single element, all negative numbers (the product answer is the largest single number), and a prefix of length one that needs its own base case.

Complexity and tradeoffs

  • Time: O(n) for a constant number of earlier entries. Integer break and the game with sums are O(n²) as written, since each entry looks at O(n) options.
  • Space: O(n) for a table, O(1) with rolling variables when only the last few entries are read.
  • Baseline. Plain recursion branches by the number of choices at every position: about 1.6 to the n for stairs, 2 to the n for take-or-skip.
  • When it fails. If a choice depends on something not in the prefix index (a remaining budget, a pair of positions) the state needs another dimension: knapsack or grid DP. If a greedy rule is provable, as for maximum subarray sum, a single running value replaces the table.

Problems

Climbing Stairs, Min Cost Climbing Stairs and N-th Tribonacci Number are the pure sum or min of the last one to three entries. House Robber and its ring version use take-or-skip. Decode Ways adds conditional terms. Maximum Product Subarray needs the second, smallest track. Integer Break and Stone Game III show that the same shape covers splitting and two-player questions.

Check yourself

Why does the number of ways to climb 7 stairs equal the Fibonacci sequence's entries?

Every way ends with a one-step or a two-step, so ways(7) = ways(6) + ways(5), the Fibonacci rule. The table is {{ stairs | join(", ") }}, so there are {{ stairs[7] }}.

In House Robber, why does taking house i extend best[i - 2] and not best[i - 1]?

Houses i - 1 and i are adjacent, so taking i rules out i - 1. The best plan using only the first i - 2 houses is the largest total that still leaves house i - 1 untouched. With the example, the plan takes houses {{ rob.chosen | join(" and ") }}.

Why must the maximum product track the smallest product too?

A negative number reverses order, so the smallest (most negative) run can become the biggest after one more negative factor. On {{ prod_in | join(", ") }}, the smallest column reaches {{ prod.rows[-1][2] }} yet the answer is {{ prod.answer }}.

How do you handle a ring of houses?

The first and last cannot both be robbed, so solve the line without the first and the line without the last and take the larger. For {{ ring | join(", ") }} that is {{ ring_run.answer }}.

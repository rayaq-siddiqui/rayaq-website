Grids as graphs

A matrix is a graph that was never drawn. Every cell is a node and its neighbors above, below, left and right are its edges, so no adjacency list is ever built: the shape of the grid is the adjacency structure. Counting islands, filling regions and spreading rot are the same two searches as on any graph, plus a bounds check. The new idea is starting a breadth-first search from many cells at once.

Problem

The input is a rectangular array of cells: land and water, walls and gates, fresh and rotten fruit, heights. You are asked how many connected regions there are, how big the largest is, how far each cell is from something, or which cells can reach somewhere. Moving is allowed between touching cells (four directions unless the statement says otherwise) and blocked by some cell values.

Intuition

Pour a bucket of paint on one square of a floor plan: it spreads to every touching square of the same kind and stops at walls. Flood fill is exactly that, and the paint is the visited mark. Everything you learned about graph search carries over, because "touching" is the only edge rule and the grid gives it for free.

Now pour paint on several squares at the same moment. Each drop spreads outward one ring per tick, and the first ring to reach a square is the nearest drop. That is multi-source BFS: put every source in the queue before the first step. The queue still holds nodes in nondecreasing distance, so the shortest-path argument for ordinary BFS still applies, with a virtual super-source joined to every source by an edge of length zero.

Scanning in reading order, each land cell that has no number yet starts a fill that numbers its whole island. Empty cells are water. The diagram scrolls sideways on a narrow screen.

Mechanics

Neighbors and bounds

Keep a tuple of direction offsets, ((1, 0), (-1, 0), (0, 1), (0, -1)), and for each cell test 0 <= nr < rows and 0 <= nc < cols before reading the neighbor. Eight-direction problems just use eight offsets. Cell (r, c) can be stored as a tuple or as the integer r * cols + c when you need a compact key.

Flood fill and visited marks

Visiting needs a mark so a cell is processed once. Either keep a separate seen set, or, when you may change the input, overwrite the cell (sink the island by writing water into it). The mark goes on when the cell is pushed, as in any graph search. The invariant is: a cell is marked exactly when it has been put on the frontier, and every marked cell has had all its in-bounds, same-kind neighbors marked or queued. When the frontier empties, the region is the set of marked cells, and none of its neighbors of the same kind remain unmarked.

Prefer an explicit stack or queue to recursion: a 300 × 300 grid of land is a path 90,000 deep, far past Python's default limit of about a thousand frames.

Multi-source BFS

Seed the queue with every source, each at distance 0, then run the ordinary loop. All cells at distance d leave the queue before any at d + 1, so a cell's recorded distance is its distance to the nearest source. One search of O(R·C) replaces a search from every cell, which would cost O((R·C)²). When time matters, as in "minutes until everything rots", process the queue one layer at a time and count the layers.

Reverse the search

"Which cells can flow to the ocean" asks about many starting cells and a few targets. Run the search from the targets over the reversed rule (water flows downhill, so search uphill). Two searches, one per ocean, intersect to the answer. The same trick solves "regions not touching the border": mark what touches the border, and everything else is the answer.

All the zeros start in the queue together, so each ring grows from the nearest one. The cell in the bottom-right corner is {{ zd.dist[3][4] }} steps from its nearest zero.

Implementation

from collections import deque

DIRS = ((1, 0), (-1, 0), (0, 1), (0, -1))


def num_islands(grid):
    rows, cols = len(grid), len(grid[0])
    count = 0
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] != "1":
                continue
            count += 1
            grid[r][c] = "0"
            stack = [(r, c)]
            while stack:
                cr, cc = stack.pop()
                for dr, dc in DIRS:
                    nr, nc = cr + dr, cc + dc
                    if 0 <= nr < rows and 0 <= nc < cols and grid[nr][nc] == "1":
                        grid[nr][nc] = "0"
                        stack.append((nr, nc))
    return count


def nearest_zero(mat):
    rows, cols = len(mat), len(mat[0])
    dist = [[-1] * cols for _ in range(rows)]
    queue = deque()
    for r in range(rows):
        for c in range(cols):
            if mat[r][c] == 0:
                dist[r][c] = 0
                queue.append((r, c))
    while queue:
        r, c = queue.popleft()
        for dr, dc in DIRS:
            nr, nc = r + dr, c + dc
            if 0 <= nr < rows and 0 <= nc < cols and dist[nr][nc] == -1:
                dist[nr][nc] = dist[r][c] + 1
                queue.append((nr, nc))
    return dist

Variations and edge cases

def oranges_rotting(grid):
    rows, cols = len(grid), len(grid[0])
    queue = deque((r, c) for r in range(rows) for c in range(cols) if grid[r][c] == 2)
    fresh = sum(row.count(1) for row in grid)
    minutes = 0
    while queue and fresh:
        for _ in range(len(queue)):
            r, c = queue.popleft()
            for dr, dc in DIRS:
                nr, nc = r + dr, c + dc
                if 0 <= nr < rows and 0 <= nc < cols and grid[nr][nc] == 1:
                    grid[nr][nc] = 2
                    fresh -= 1
                    queue.append((nr, nc))
        minutes += 1
    return -1 if fresh else minutes


def solve_surrounded(board):
    rows, cols = len(board), len(board[0])
    stack = [(r, c) for r in range(rows) for c in range(cols)
             if (r in (0, rows - 1) or c in (0, cols - 1)) and board[r][c] == "O"]
    for r, c in stack:
        board[r][c] = "S"
    while stack:
        r, c = stack.pop()
        for dr, dc in DIRS:
            nr, nc = r + dr, c + dc
            if 0 <= nr < rows and 0 <= nc < cols and board[nr][nc] == "O":
                board[nr][nc] = "S"
                stack.append((nr, nc))
    for r in range(rows):
        for c in range(cols):
            board[r][c] = "O" if board[r][c] == "S" else "X"
  • Mutating the input. Overwriting cells is shortest, but only if the caller does not need the grid afterwards. Otherwise keep a seen set of tuples.
  • Counting layers. To count minutes, take len(queue) before each round and process exactly that many cells, as above. A fresh counter detects unreachable cells without a final scan.
  • Seeding the queue. Sources must all be queued before the first pop. Seeding them lazily gives wrong distances.
  • Different neighbor rules. Knight moves, eight directions, wrap-around edges and one-way doors change only the offsets or the test. Keep that rule in one place.
  • Edge cases: an empty grid or an empty first row, a single cell, a grid with no sources (the distance table stays all -1), a start that is already the target, and rows of unequal length when the input is ragged.
  • Backtracking on a grid (Word Search) is not a flood fill: the same cell may be reused on another path, so the mark is undone on the way back. See constraint backtracking.

Complexity and tradeoffs

  • Time: O(R·C). Each cell is marked once and examines a constant number of neighbors (four or eight). Multi-source BFS is also O(R·C), not O(sources × R·C).
  • Space: O(R·C) worst case for the frontier or the seen set; O(min(R, C)) for a BFS ring on a square-ish open grid. Marking in place removes the seen set.
  • Baseline. Running a separate search from every cell to its nearest source is O((R·C)²). The shared queue is what removes the square.
  • DFS or BFS. Regions, areas and border tests: either works, and an explicit stack is the simplest. Distances and "per minute" spreads need BFS.
  • When it fails. Cells with different move costs need Dijkstra (Path With Minimum Effort, Swim in Rising Water). Repeated "add land, then count islands" queries suit union-find. Very large sparse grids should be stored as a set of occupied cells, not a full matrix.

Check yourself

Why does multi-source BFS give each cell its distance to the nearest source?

All sources enter the queue at distance 0, and the queue releases cells in nondecreasing distance. The first time any ring reaches a cell it comes from the closest source, exactly as if a virtual node were joined to every source by a zero-length edge.

The example grid has two lone land cells at (1,3) and (2,2). Are they one island?

No. They touch only at a corner, and under four-direction movement diagonal cells are not neighbors. The fill finds {{ isl.areas | length }} islands in total. An eight-direction rule would merge them.

Why search from the border in Surrounded Regions and Pacific Atlantic?

The border cells are the few known answers, and the interior has many unknown cells. One search from the known side marks everything connected to it; asking the question from every interior cell would repeat that work thousands of times.

Why can a flood fill on a large all-land grid crash a recursive solution?

A fill can walk a path as long as the number of cells, and a 300 × 300 grid is 90,000 deep, past Python's default recursion limit of about a thousand. Use an explicit stack or queue.

String matching

Finding every place a pattern of length m occurs in a text of length n takes O(nm) if you try each start and compare from scratch. Two classic ideas bring it to O(n + m). Knuth–Morris–Pratt (KMP) never moves backwards in the text: after a mismatch it already knows how much of the pattern still lines up. Rabin–Karp hashes each window in O(1) by rolling the hash along, and compares characters only when hashes agree. It rarely comes up in interviews: Python's in and str.find are what you would normally write, and no list problem needs more. It is here for the problems where the pattern itself must be analysed, such as its repeats and its borders.

Problem

The question is always some form of "where does this string occur inside that one?", sometimes disguised: does a string repeat a smaller block, what is the longest prefix that is also a suffix, which substrings appear twice, or how few characters must be added to make a palindrome. A direct comparison at every start costs O(nm) when the text and pattern are full of near-matches, like long runs of one letter. The fix is to reuse what earlier comparisons already proved, either through the pattern's own structure (KMP) or through arithmetic on the window (rolling hash).

Intuition

Slide the pattern {{ pattern }} along the text {{ text }}. At start {{ first_start }}, the first {{ slip.before }} characters match and then position {{ slip.i }} fails. The naive method shifts by one and starts over, re-reading characters it has already seen. But the {{ slip.before }} characters that matched are now known: they are {{ pattern[:slip.before] }}. That text ends in {{ pattern[:slip.fallbacks[0]] }}, which is also how the pattern begins. So the pattern can jump straight to start {{ second_start }}, with its first {{ slip.fallbacks[0] }} characters already matched, and carry on from the same text position.

The amount to keep depends only on the pattern, never on the text, so it can be computed once: for every prefix of the pattern, the longest piece that is both a proper prefix and a suffix of it. That piece is called a border, and the list of border lengths is the failure table.

Rabin–Karp takes a different route. Turn each window of m characters into a number, the way digits make a number, and keep it small with a modulus. Sliding the window one step removes the leading digit and appends a new one, in O(1). Equal strings always have equal hashes, so only windows whose hash equals the pattern's need a real comparison.

Mechanics

The failure table

lps[i] is the length of the longest proper prefix of pattern[:i + 1] that is also its suffix. Build it left to right with a pointer length holding the current border. If the next character extends the border, it grows by one. If not, the next-longest border to try is the border of the border, lps[length − 1], because any border of a string that is shorter than its longest border must also be a border of that longest border. Keep falling back until the character extends one or the length reaches 0.

The search

Keep j, the number of pattern characters matched so far, and read the text once. On a match, j grows. On a mismatch with j > 0, set j = lps[j − 1] and try the same text character again. The invariant: pattern[:j] equals the j text characters just before i, and no occurrence starts at an earlier position not yet ruled out. The fallback keeps it, because the longest border is the largest shift-back that still agrees with the text, and every start in between would contradict the matched characters. When j reaches m, record a match at i − m + 1 and fall back once more so overlapping matches are found.

Why it is linear

Each text character raises j by at most 1, and each fallback lowers it by at least 1. j never goes below 0, so the total number of fallbacks over the whole search is at most n, and the search does at most 2n comparisons. The same argument bounds the table build by 2m.

The rolling hash

Give each letter a value (here a = 1, b = 2, and so on) and read a window as a number in base B, modulo a prime p. Moving the window right one place subtracts the leaving letter times Bm−1, multiplies by B and adds the arriving letter, all mod p. Equal windows always hash equal, so no match is missed; unequal windows can collide, so a hash hit must be confirmed by comparing characters. With a large random prime, collisions are rare and the expected time is O(n + m).

Implementation

def build_lps(pattern):
    lps = [0] * len(pattern)
    length = 0
    for i in range(1, len(pattern)):
        while length and pattern[i] != pattern[length]:
            length = lps[length - 1]
        if pattern[i] == pattern[length]:
            length += 1
        lps[i] = length
    return lps


def kmp_search(text, pattern):
    if not pattern:
        return [0]
    lps = build_lps(pattern)
    matches, j = [], 0
    for i, ch in enumerate(text):
        while j and ch != pattern[j]:
            j = lps[j - 1]
        if ch == pattern[j]:
            j += 1
        if j == len(pattern):
            matches.append(i - j + 1)
            j = lps[j - 1]
    return matches

Variations and edge cases

Rabin–Karp. With a modulus near 261, Python's big integers keep the arithmetic exact, and the slice comparison makes a collision harmless:

def rabin_karp(text, pattern, base=131, mod=(1 << 61) - 1):
    m = len(pattern)
    if m > len(text):
        return []
    high = pow(base, m - 1, mod)
    target = window = 0
    for k in range(m):
        target = (target * base + ord(pattern[k])) % mod
        window = (window * base + ord(text[k])) % mod
    matches = []
    for start in range(len(text) - m + 1):
        if start:
            window = ((window - ord(text[start - 1]) * high) * base + ord(text[start + m - 1])) % mod
        if window == target and text[start:start + m] == pattern:
            matches.append(start)
    return matches

The Z-array. z[i] is the length of the longest substring starting at i that matches a prefix of the string. A window [left, right) remembers the furthest match so far, and positions inside it start from a value already known. Searching is then z_array(pattern + "#" + text) and reporting every i where z[i] == len(pattern), with "#" any character in neither string:

def z_array(s):
    z = [0] * len(s)
    left = right = 0
    for i in range(1, len(s)):
        if i < right:
            z[i] = min(right - i, z[i - left])
        while i + z[i] < len(s) and s[z[i]] == s[i + z[i]]:
            z[i] += 1
        if i + z[i] > right:
            left, right = i, i + z[i]
    return z

Analysing the pattern itself. build_lps(s)[-1] is the longest border of s. If p = n − border divides n, s is a block of length p repeated. And running the table over s + "#" + reversed(s) gives the longest palindromic prefix of s.

  • Empty pattern. By convention it occurs at 0; pattern[j] with an empty pattern would raise, so return early.
  • Overlapping matches. Resetting j to 0 after a match misses aa at 1 in aaa; fall back to lps[m − 1].
  • Negative modulo. Subtracting the leaving letter can go negative. Python's % always returns a non-negative result, but in languages where it does not, add the modulus back.
  • Trusting a hash hit. Skipping the character check turns a collision into a wrong answer. Either compare, or use two independent hashes and accept a tiny risk knowingly.

Complexity and tradeoffs

KMP is O(n + m) time in the worst case and O(m) extra space. Rabin–Karp is O(n + m) expected, O(nm) if every window collides, and O(1) extra space. The Z-array is O(n + m) time and space. The naive method is O(nm) in the worst case, reached when the text is all one letter and the pattern differs only at its end:

  • KMP or Rabin–Karp. KMP has a guarantee and needs no luck. Rabin–Karp generalises: hash every length-L window of one or many strings and compare them through a set, which KMP cannot do.
  • Against the built-in. CPython's str.find and in are written in C and are fast on ordinary text. Reach for these patterns when the problem is about the pattern's structure, or when you need all windows' hashes.
  • Against a trie. Matching many patterns at once is the job of a trie (and the Aho–Corasick automaton, which adds failure links like KMP's to a trie).
  • Against suffix structures. Suffix arrays and suffix automata answer many queries over one fixed text, at a cost no interview expects you to write.

Check yourself

In the example, the mismatch at text position {{ slip.i }} sets j from {{ slip.before }} to {{ slip.fallbacks[0] }}. Why {{ slip.fallbacks[0] }}?

The matched text is {{ pattern[:slip.before] }}, and its longest border is {{ pattern[:slip.fallbacks[0]] }}, so lps[{{ slip.before - 1 }}] = {{ slip.fallbacks[0] }}. Sliding the pattern any less would contradict characters already matched; sliding it more could skip the occurrence that starts at {{ second_start }}.

Why does KMP do at most 2n comparisons, even though a single character can trigger several fallbacks?

j rises by at most one per text character and each fallback lowers it. Since j starts at 0 and never goes negative, all the fallbacks together cannot exceed the n rises.

Rabin–Karp found a hash hit at start {{ rk.collisions | join(", ") }}. Why is that not a mistake in the algorithm?

Many strings share a hash modulo {{ rk_mod }}. A hash hit only says "possibly equal", and the character comparison rejects it. Missing a real match is impossible, because equal strings always hash the same.

How does the failure table tell whether {{ repeated }} is a repeated block?

Its last entry is {{ repeated_border }}, the border {{ repeated[:repeated_border] }}. n − {{ repeated_border }} = {{ repeated | length - repeated_border }} divides {{ repeated | length }}, so the string is {{ repeated[:repeated | length - repeated_border] }} repeated {{ (repeated | length) // (repeated | length - repeated_border) }} times.

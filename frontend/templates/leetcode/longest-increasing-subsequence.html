Longest increasing subsequence

Pick numbers from a sequence, left to right and skipping freely, so that each is bigger than the one before. The longest such pick has a simple quadratic DP, and a clever invariant (the smallest possible tail for each length) turns it into a binary search that runs in n log n.

Problem

A subsequence keeps the order of the original but may skip elements, unlike a substring. You want the longest one that is strictly increasing. Trying every subset is 2n. Two different tables avoid that: one indexed by where a subsequence ends, and one indexed by how long it is.

Intuition

Standing on a number, you ask: what is the longest increasing run that ends here? It is one more than the best run that ends on some earlier, smaller number, or just 1 if there is none. That is the whole quadratic idea.

For the faster version, flip the question. For each length k, what is the smallest number a run of length k can end on? A smaller ending is always at least as good for the future, since anything that can follow a large ending can also follow a small one. Keep these smallest endings in a list. They are always sorted, so a new number either goes after the end (the best run grows by one) or replaces the first ending that is not smaller than it (a run of that length now ends lower). Finding the spot is a binary search.

Mechanics

The O(n²) table

Let length[i] be the longest strictly increasing subsequence that ends exactly at index i. Then length[i] = 1 + max(length[j]) over all j < i with nums[j] < nums[i], or 1 if no such j exists. The answer is the largest entry, not the last one, because the best run need not end at the end. Store the j that gave the max in a parent array to recover an actual subsequence by walking back.

The tails list

Keep tails, where tails[k] is the smallest value that can end a strictly increasing subsequence of length k + 1. The invariant is that tails is strictly increasing. Proof sketch: if a subsequence of length k + 2 ends at v, dropping its last element gives one of length k + 1 ending at something less than v, so tails[k] < tails[k + 1].

Processing a value x: find the first index p where tails[p] >= x (a lower bound). If p is the end, append x; the longest run grew. Otherwise set tails[p] = x, since a run of length p + 1 can now end lower. The length of tails at the end is the answer. The contents of tails are not themselves a subsequence of the input, only a record of the best endings, which is the common mistake in reading it.

Each row is the tails list after reading the number on the left. The blue cell is the one that number wrote, either a new end or a replacement.

Invariant

After reading a prefix, tails[k] is the least possible last element over all strictly increasing subsequences of length k + 1 in that prefix. A new element x can extend the best run ending below x, and its length is the position found by the search, so it can only improve the entry at that position. Entries at other positions are unchanged, so the invariant is preserved.

Implementation

from bisect import bisect_left


def length_of_lis(nums):
    tails = []
    for x in nums:
        i = bisect_left(tails, x)       # first slot not smaller than x
        if i == len(tails):
            tails.append(x)
        else:
            tails[i] = x
    return len(tails)


def length_of_lis_quadratic(nums):
    if not nums:
        return 0
    length = [1] * len(nums)
    for i in range(len(nums)):
        for j in range(i):
            if nums[j] < nums[i]:
                length[i] = max(length[i], length[j] + 1)
    return max(length)

Variations and edge cases

def non_decreasing_length(nums):
    tails = []
    for x in nums:
        i = bisect_right(tails, x)      # ties may extend, so go past equals
        if i == len(tails):
            tails.append(x)
        else:
            tails[i] = x
    return len(tails)


def count_of_lis(nums):
    n = len(nums)
    length, count = [1] * n, [1] * n
    for i in range(n):
        for j in range(i):
            if nums[j] < nums[i]:
                if length[j] + 1 > length[i]:
                    length[i], count[i] = length[j] + 1, count[j]
                elif length[j] + 1 == length[i]:
                    count[i] += count[j]
    best = max(length, default=0)
    return sum(c for l, c in zip(length, count) if l == best)


def russian_doll(envelopes):
    envelopes.sort(key=lambda e: (e[0], -e[1]))   # equal widths: taller first
    return length_of_lis([h for _, h in envelopes])
  • Strict versus non-strict. Strict uses bisect_left and <; non-decreasing uses bisect_right and <=. Mixing them gives off-by-duplicates answers.
  • Answer is the max, not the last entry of the quadratic table.
  • Reading the tails list as the answer sequence. It is not one. To get a real sequence, record for each element the slot it landed in and its predecessor in slot - 1, then walk back.
  • Equal widths in nesting problems. Sort the second key descending within equal first keys, so two with the same width can never both enter a chain.
  • Empty input. Return 0; the quadratic code needs the guard before max.

Complexity and tradeoffs

  • Time: O(n²) for the table, O(n log n) for the tails search.
  • Space: O(n) in both (the tails list is at most n long).
  • Baseline. Enumerating all subsequences is O(2n).
  • Which to use. Start with the table when asked for the sequence itself, a count, or a variation with extra conditions; the table carries extra data easily. Use the tails list when n is large (about 105) and only the length matters.
  • When it fails. The tails trick relies on a total order, so it does not carry over directly to problems with extra constraints between chosen elements (such as a limit on the index gap), which usually need a segment tree or a monotonic deque over the table.

Longest Increasing Subsequence is the one list problem homed here. Its relatives, not on the lists, include counting the longest runs, nesting envelopes and removing the fewest elements to sort an array; the code above handles all of them with small changes.

Check yourself

Why is the answer the maximum entry of the table and not the last?

The best run may end anywhere. For {{ nums | join(", ") }} the table is {{ dp.length | join(", ") }}, and the best is {{ dp.answer }}.

Why is it safe to replace a tail with a smaller value?

A smaller ending allows everything a larger ending allowed, and possibly more. In the example the number {{ pt.rows[6][0] }} replaced {{ pt.rows[6][2] }} in slot {{ pt.rows[6][1] }}, and anything that could follow {{ pt.rows[6][2] }} can follow {{ pt.rows[6][0] }}.

Is the final tails list a valid increasing subsequence of the input?

Not necessarily. Here it is {{ pt.tails | join(", ") }} but 6 appears after 9 in the input. Only its length is meaningful.

What changes for a non-decreasing subsequence?

Use bisect_right in the search and <= in the table, so equal values can extend a run instead of replacing each other.

Tries

A trie (pronounced "try", from retrieval) stores a set of words as a tree of letters, so every word that begins the same way shares the same path from the root. That sharing is the whole point: asking "does anything start with ca?" costs two steps, no matter how many words are stored. Prefix questions, autocomplete, wildcard search and pruning a word search on a grid are all the same walk down the same tree.

Problem

You hold a collection of words and must answer questions about prefixes: is this a stored word, does any word start with this, which words start with this, or which of these many words can be spelled on a board. A hash set answers the first question in O(length) but cannot answer the others without scanning every word, because a hash destroys the order of the characters. A sorted list with binary search can answer prefix queries, but inserting is slow. A trie answers every one of them by following one character at a time.

Intuition

Write the words {{ words | join(", ") | safe }} on a page. Many start the same way: car, card and care share the prefix car, and car and cat share ca. A trie draws each shared prefix once. Starting at an empty root, each edge carries one letter, and a word is the path from the root to a node that is marked "a word ends here". The {{ words | length }} words have {{ lay.letters }} letters in total, but the trie needs only {{ lay.nodes | length - 1 }} letter nodes, because the shared prefixes collapse.

The mark matters. The node for ca exists because car and cat pass through it, but ca is not a stored word. Without the end mark you could not tell a word from a mere prefix. This is the most common bug in a first trie: answering search with "I found the path" instead of "I found the path and the end mark is set".

Mechanics

The invariant

The path from the root to any node spells a prefix of at least one stored word, and every prefix of every stored word has exactly one node. A node's children are keyed by the next letter, so two different words can only share a node if they share the whole path leading to it. An end flag on a node means "the path to here is itself a word".

Insert, search and prefix

Insert walks the word one letter at a time, creating the child when it is missing, and sets the end flag on the last node. Search walks the same way but never creates; it fails if a letter has no child, and otherwise answers with the end flag of the last node. Starts with is search without the final check: reaching the node at all is the answer. All three cost one step per letter, O(L) for a word of length L, independent of how many words are stored.

Correctness follows from the invariant. A word is stored exactly when its path exists and its last node is marked; a prefix is present exactly when its path exists. Because each node has at most one child per letter, the walk is deterministic, with no choices to try.

Wildcards and the board search

A dot that matches any letter turns the deterministic walk into a search: at a dot, try every child and succeed if any branch succeeds. That is a depth-first search on the trie, and its worst case is every node at that depth. For a grid of letters the roles reverse. Instead of testing each word separately, build a trie of all the words and run a depth-first search from each cell that carries the trie node along: step to a neighbour only if the current node has a child for that neighbour's letter. The moment no stored word continues the path, the search backs out, so one walk over the board serves every word at once. Removing a leaf from the trie after its word is found keeps the search from rediscovering the same word and shrinks the work as the board is mined out.

Implementation

class TrieNode:
    __slots__ = ("children", "end")

    def __init__(self):
        self.children = {}          # letter -> TrieNode
        self.end = False


class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word):
        node = self.root
        for ch in word:
            node = node.children.setdefault(ch, TrieNode())
        node.end = True

    def _walk(self, text):
        node = self.root
        for ch in text:
            node = node.children.get(ch)
            if node is None:
                return None
        return node

    def search(self, word):
        node = self._walk(word)
        return node is not None and node.end

    def starts_with(self, prefix):
        return self._walk(prefix) is not None


class WordDictionary:
    def __init__(self):
        self.root = TrieNode()

    def add_word(self, word):
        node = self.root
        for ch in word:
            node = node.children.setdefault(ch, TrieNode())
        node.end = True

    def search(self, pattern):
        def match(node, i):
            if i == len(pattern):
                return node.end
            if pattern[i] == ".":
                return any(match(child, i + 1) for child in node.children.values())
            child = node.children.get(pattern[i])
            return child is not None and match(child, i + 1)

        return match(self.root, 0)


def find_words(board, words):
    root = TrieNode()
    for word in words:
        node = root
        for ch in word:
            node = node.children.setdefault(ch, TrieNode())
        node.end = word                  # store the word itself, so no path rebuilding is needed

    rows, cols = len(board), len(board[0])
    found = []

    def dfs(r, c, parent):
        ch = board[r][c]
        node = parent.children[ch]
        if node.end:
            found.append(node.end)
            node.end = False             # report each word once
        board[r][c] = "#"                # mark visited in place
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            nr, nc = r + dr, c + dc
            if 0 <= nr < rows and 0 <= nc < cols and board[nr][nc] in node.children:
                dfs(nr, nc, node)
        board[r][c] = ch
        if not node.children and not node.end:
            del parent.children[ch]      # prune exhausted branches

    for r in range(rows):
        for c in range(cols):
            if board[r][c] in root.children:
                dfs(r, c, root)
    return found

A dictionary of children is the idiomatic Python choice: it handles any alphabet and only stores the letters that exist. In find_words the end flag holds the word itself, which doubles as the "is a word" test because any non-empty string is truthy.

Variations and edge cases

  • Fixed alphabet. For lowercase letters a list of 26 slots per node is faster than a dictionary but uses 26 pointers per node even when most are empty.
  • Counts per node. Store how many words pass through each node to answer "how many words have this prefix" in O(L), or to delete a word by decrementing.
  • Reversed words. Insert each word backwards to match suffixes; pairs-that-form-a-palindrome problems combine a trie of reversed words with a check on the leftover part.
  • Tokens other than letters. The edges can be directory names, so an in-memory file system is a trie whose nodes hold file contents.
  • Edge cases: the empty string (marks the root, so give the root an end flag if empty words are allowed), a word that is a prefix of another, a word inserted twice, a query longer than every stored word, and a board with repeated letters, where the in-place visited mark keeps a path from reusing a cell.

Complexity and tradeoffs

  • Time: insert, search and prefix are O(L) for a word of length L, independent of the number of stored words. A wildcard query is O(L) in the best case and can visit every node in the worst case, which is why the dots in the example above matter. The board search is O(cells × 4L) in the worst case for a word length L, but the trie prunes almost all of that in practice.
  • Space: at most one node per letter of input, here {{ lay.nodes | length - 1 }} nodes against {{ lay.letters }} letters, and far fewer when prefixes are shared. The cost is the per-node overhead of a dictionary or a 26-slot array, which can exceed the cost of storing the strings directly.
  • Baseline. A hash set answers exact membership in O(L) with less memory. Scanning every word for a prefix is O(words × L). A sorted array with binary search finds a prefix in O(L log n) but cannot take new words cheaply.
  • When it fails. When only exact lookups are needed, a set is simpler and smaller. When the words are few and the prefixes short, the trie's overhead is not paid back. For huge dictionaries a compressed trie or a finite state transducer saves memory by merging single-child chains.

A trie is a tree whose children are keyed by a letter, so the traversals of the depth-first page apply directly, and a dictionary of children is the hash map of the hash-maps page placed at every node. Check yourself

Why does the trie for these words have {{ lay.nodes | length - 1 }} letter nodes and not {{ lay.letters }}?

Words that share a prefix share the nodes of that prefix. car, card and care use one path for car, and cat reuses the nodes for ca; likewise dog reuses do. Only the first occurrence of each prefix creates nodes.

The query ca reaches a node. Why is searching for it still "no"?

The node exists because longer words pass through it, but no word ends there: its end mark is unset. A search must check that mark; a prefix query must not.

Why can the pattern ..g cost more than c.x, even though both have three characters?

A dot tries every child, so dots near the root multiply the branches that must be explored. The example entered {{ dots_far.visited }} nodes for ..g and only {{ dots_none.visited }} for c.x, which dies as soon as c has no child x after one dot.

In the board search, why is one trie of all the words better than a separate search per word?

The trie lets one walk of the board serve every word at once and lets the search stop the instant no stored word continues the current path. A search per word repeats the same board walk for each word, and cannot share work between words with a common prefix.

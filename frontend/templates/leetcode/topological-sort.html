Topological sort

Some things must happen before others: courses before the courses that need them, build steps before the steps that use their output, letters before the letters that follow them in a dictionary. A topological sort lines everything up so that every "before" is respected. It exists exactly when there is no circular dependency, which makes the same algorithm the standard cycle detector for directed graphs.

Problem

The input is a set of items and a set of rules of the form "a must come before b". You are asked for any valid order, for whether one exists, for the earliest round in which each item can happen, or for something that can be derived from the order, such as a hidden alphabet. Sometimes the rules are not given but must be read from the data first.

Intuition

Getting dressed has an order: socks before shoes, trousers before belt. You do not need to plan it all at once. At any moment, pick something that has no unmet requirement, do it, and cross it off every other item's list of requirements. If you can always find such an item, you finish with a valid order. If at some point everything left still has an unmet requirement, you have found a circle (shoes need socks need shoes) and no order exists.

Kahn's algorithm is exactly that. It counts for each node how many prerequisites are unfinished (its in-degree), starts with the nodes that have none, and each time it finishes a node it reduces the count of every node that depended on it. The depth-first version reaches the same set of answers from the other side: the node that finishes last in a depth-first search has nothing after it that is unfinished, so listing nodes in reverse finishing order puts every node before everything it points to.

The small blue dot marks the arrow's head. Every dependency goes from a column on the left to a column on the right, which is what a topological order means. Nodes in one column are independent of each other and could happen in parallel. The diagram scrolls sideways on a narrow screen.

Mechanics

Kahn's algorithm

Compute the in-degree of every node. Put the zero in-degree nodes in a queue. Repeatedly remove a node, append it to the answer, and decrement the in-degree of each node it points to; a node whose count reaches zero joins the queue. Finish when the queue is empty. If the answer has fewer nodes than the graph, the rest are blocked by a cycle.

Why it is correct. A node is queued only when every prerequisite has already been appended, so each edge goes forward in the answer. If the answer is short, every node left over still has an unfinished prerequisite that is itself left over; following those prerequisites backwards can never end, so it must revisit a node, which is a cycle. Conversely a cycle's nodes never reach in-degree zero, so they are always left over.

The depth-first version

Run a DFS with three states (unseen, on the path, finished) and append a node to a list the moment it finishes. An edge into an on-path node is a cycle. Otherwise the reversed list is a topological order, because when a node finishes, everything it points to has already finished and sits earlier in the list.

Rounds and longest chains

Process the queue one layer at a time and count layers. A node lands in round k + 1 where k is the longest chain of prerequisites below it, so the number of rounds is the "minimum semesters" answer when any number of items may proceed together. The same counting yields the longest path in a DAG, a task no ordinary graph can do in linear time.

Deriving the edges

Sometimes the graph is hidden. In a list of words sorted by an unknown alphabet, compare each word with the next: the first position where they differ gives one rule, "this letter comes before that one". Later positions say nothing. If the longer word comes first while the shorter is its prefix, the list cannot be sorted under any alphabet.

With the extra edge, only node 4 has in-degree zero. After it is removed, the others are all still waiting on someone who is waiting on them. Node 0 is not on the cycle but is stuck behind it.

Implementation

from collections import defaultdict, deque


def topological_order(n, prerequisites):
    adj = defaultdict(list)
    indegree = [0] * n
    for course, before in prerequisites:
        adj[before].append(course)
        indegree[course] += 1
    queue = deque(i for i in range(n) if indegree[i] == 0)
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for nxt in adj[node]:
            indegree[nxt] -= 1
            if indegree[nxt] == 0:
                queue.append(nxt)
    return order if len(order) == n else []


def can_finish(n, prerequisites):
    return len(topological_order(n, prerequisites)) == n

Variations and edge cases

def alien_order(words):
    letters = {ch for word in words for ch in word}
    adj = {ch: set() for ch in letters}
    indegree = {ch: 0 for ch in letters}
    for first, second in zip(words, words[1:]):
        for a, b in zip(first, second):
            if a != b:
                if b not in adj[a]:
                    adj[a].add(b)
                    indegree[b] += 1
                break
        else:
            if len(first) > len(second):
                return ""
    queue = deque(ch for ch in letters if indegree[ch] == 0)
    out = []
    while queue:
        ch = queue.popleft()
        out.append(ch)
        for nxt in adj[ch]:
            indegree[nxt] -= 1
            if indegree[nxt] == 0:
                queue.append(nxt)
    return "".join(out) if len(out) == len(letters) else ""


def minimum_height_trees(n, edges):
    if n == 1:
        return [0]
    adj = [set() for _ in range(n)]
    for a, b in edges:
        adj[a].add(b)
        adj[b].add(a)
    leaves = [i for i in range(n) if len(adj[i]) == 1]
    while n > 2:
        n -= len(leaves)
        following = []
        for leaf in leaves:
            neighbor = adj[leaf].pop()
            adj[neighbor].discard(leaf)
            if len(adj[neighbor]) == 1:
                following.append(neighbor)
        leaves = following
    return leaves


def longest_chain(n, edges):
    adj = [[] for _ in range(n)]
    indegree = [0] * n
    for a, b in edges:
        adj[a].append(b)
        indegree[b] += 1
    layer = [i for i in range(n) if indegree[i] == 0]
    depth = 0
    while layer:
        depth += 1
        following = []
        for node in layer:
            for nxt in adj[node]:
                indegree[nxt] -= 1
                if indegree[nxt] == 0:
                    following.append(nxt)
        layer = following
    return depth
  • Edge direction. "Course a requires b" is the edge b→a. Reversing it silently produces a valid but reversed order. Say the direction aloud before coding.
  • Duplicate edges. Counting a repeated edge twice in the in-degree but visiting it once (or the reverse) leaves a node stuck. Deduplicate with a set, or be consistent on both sides.
  • Letters that appear in no rule. In the alien alphabet they must still be in the answer; seed the node set from all letters, not only from edges.
  • Prefix trap. ["abc", "ab"] is invalid even though no letters differ. Check lengths when the comparison loop finds no difference.
  • Several valid orders. If the judge needs a specific one (lexicographically smallest), use a heap in place of the queue.
  • Edge cases: no edges (any order, all nodes), a self-loop (always a cycle), a disconnected graph (Kahn handles it, since all zero in-degree nodes start), and a single node.

Complexity and tradeoffs

  • Time: O(V + E). Each node is queued once and each edge decrements one counter once.
  • Space: O(V + E) for the adjacency list, plus O(V) for in-degrees and the queue.
  • Baseline. Repeatedly scanning for a node with no unfinished prerequisite costs O(V · (V + E)). Keeping a count and a queue is what makes it linear.
  • Kahn or DFS. Kahn is iterative, naturally layered, and detects a cycle by counting. DFS needs recursion (or an explicit stack) but reports the cycle itself and fits problems that already traverse recursively.
  • When it fails. It needs directed edges and no cycle; for "are these connected" with undirected links use union-find. Rules with costs or deadlines on top of the order (critical path with durations) extend the layering into a longest-path dynamic program over the order.

Topological sort is graph traversal with a count of unmet dependencies. The order it produces is what makes dynamic programming on a DAG possible (solve each node after everything it depends on), and the same "remove the nodes with nothing blocking them" loop returns in shortest-path algorithms.

Check yourself

How does Kahn's algorithm tell you there is a cycle?

It finishes with fewer nodes in the answer than in the graph. The nodes on a cycle never reach in-degree zero, and neither do the nodes that depend on them. In the example with the extra edge, {{ kahn_cyc.stuck | length }} of 6 nodes were left over.

Why do Kahn and the DFS method give different orders for the same graph, and are both right?

A DAG with independent nodes has many valid orders; the algorithms break ties differently. Here they gave {{ kahn.order | join(", ") }} and {{ dfs_order | join(", ") }}. Both put every prerequisite first.

In Alien Dictionary, why can a pair of words contribute at most one rule?

Only the first position where two adjacent words differ is decided by the alphabet; everything after it was decided by that earlier difference. Positions before it are equal and say nothing.

Why must Alien Dictionary check for a longer word before its own prefix?

A prefix is always sorted before the longer word, in every alphabet, so "abc" before "ab" cannot happen. The loop that looks for a differing letter finds none, so the length check is the only place this contradiction can be caught.

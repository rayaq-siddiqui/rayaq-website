Two pointers

Two indices walk an array, usually from opposite ends, and every move throws away part of the search space for good. This page explains the argument that makes the discard safe, which is what separates a pattern you understand from a trick you memorised, and applies it to pair sums, containers, triples and palindromes.

Problem

Brute force on "find a pair" or "best pair of positions" checks all O(n²) pairs. When the input has order (sorted values, or a quantity that depends on the distance between positions), you can often prove that a whole row of pairs cannot contain the answer, and skip it. Two pointers are the bookkeeping for that proof.

Intuition

Imagine looking for two numbers that add to 14 in a sorted row, with a finger on each end. If the two numbers are too big, the right-hand finger's number is too big for every partner, because the left finger holds the smallest partner it could have. So that number can be ruled out entirely and the finger steps inward. The symmetric argument discards the left number when the sum is too small. Each step eliminates a whole row or column of the pair table, so n steps cover n² pairs.

Amber cells are the pointers; blue cells are ruled out and never looked at again.

Mechanics

The invariant

For converging pointers left < right, the invariant is: if a solution exists, it lies within [left, right]. Each move must preserve that. In the sorted pair sum, when nums[left] + nums[right] > target, the value at right plus anything at or after left is at least as large, so right belongs to no solution and can be dropped. The mirrored argument covers "too small". The loop ends when the pointers meet, with the window empty, which proves there was no solution.

The same proof for containers

Water held between two walls is min(h[left], h[right]) × (right − left). Say the left wall is the shorter. Any container using this wall and a position inside the window has smaller width and height still capped by this wall, so it cannot beat the current one. The left wall is finished: step it inward. Moving the taller wall instead could only lose width without lifting the cap, so that choice is never needed. This is an exchange argument, and it is what you say aloud in an interview.

Reducing to pairs

For three sum, sort and fix the smallest element at index i. The rest is the converging pair search for the target −nums[i] on the suffix after i. Duplicates are handled by skipping a fixed value equal to the previous fixed value, and by stepping the left pointer past repeats after a hit. Sorting costs O(n log n) and the n pair searches cost O(n²), so the total is O(n²), against O(n³) for brute force.

Green walls are the best pair. Every other pair was discarded by the move rule without being evaluated.

Implementation

def pair_sum_sorted(nums, target):                  # indices, or None
    left, right = 0, len(nums) - 1
    while left < right:
        total = nums[left] + nums[right]
        if total == target:
            return left, right
        if total < target:
            left += 1
        else:
            right -= 1
    return None


def max_area(heights):
    left, right, best = 0, len(heights) - 1, 0
    while left < right:
        best = max(best, min(heights[left], heights[right]) * (right - left))
        if heights[left] <= heights[right]:
            left += 1
        else:
            right -= 1
    return best


def three_sum(nums):
    nums.sort()
    out = []
    for i in range(len(nums) - 2):
        if i and nums[i] == nums[i - 1]:
            continue
        left, right = i + 1, len(nums) - 1
        while left < right:
            total = nums[i] + nums[left] + nums[right]
            if total < 0:
                left += 1
            elif total > 0:
                right -= 1
            else:
                out.append([nums[i], nums[left], nums[right]])
                left += 1
                while left < right and nums[left] == nums[left - 1]:
                    left += 1
    return out


def is_palindrome(text):
    left, right = 0, len(text) - 1
    while left < right:
        if not text[left].isalnum():
            left += 1
        elif not text[right].isalnum():
            right -= 1
        elif text[left].lower() != text[right].lower():
            return False
        else:
            left += 1
            right -= 1
    return True

Variations and edge cases

  • Same-direction pointers. The read and write indices from the previous page are two pointers moving the same way. Merge two sorted lists uses one pointer per list.
  • Almost-palindrome. On the first mismatch, try skipping the left character or the right one and check the rest with the plain palindrome test; at most one skip is allowed.
  • Closest sum. Same converging loop, but track the sum nearest to the target instead of stopping at equality.
  • Four sum and k-sum. Add outer loops (each with duplicate skipping) around the pair search; the cost is O(n^(k−1)).
  • Greedy pairing. Boats and similar problems: sort, then pair the heaviest remaining with the lightest when they fit, otherwise take the heaviest alone.
  • Three-way partition. Keep low, mid, high; swap 0s behind low and 2s ahead of high. Do not advance mid after swapping with high, since the value that arrived is unexamined.
  • Edge cases: fewer than two (or three) elements, all equal values with duplicate skipping, using < versus <= in the loop condition (a pointer must not pair with itself), unsorted input (sort first, and remember the original indices if the answer asks for them), and overflow in other languages.

Complexity and tradeoffs

  • Time: O(n) for a single converging pass; O(n log n) if sorting is needed first; O(n²) for three sum.
  • Space: O(1) beyond the sort (and the output).
  • Baselines. Brute force is O(n²) for pairs. A hash map solves unsorted pair sum in O(n) time and O(n) space and also preserves indices; choose the hash map when the array is unsorted and the answer needs original positions.
  • When it fails. If neither pointer move can be justified by a monotonic argument, the pattern does not apply. Negative numbers break window-style pointers that move in the same direction (see prefix sums), but converging pointers on a sorted array are fine with negatives.

Check yourself

In the pair-sum scan, why can the right pointer be dropped when the sum is too large?

The left value is the smallest partner remaining, so if it already overshoots, every other partner overshoots too. On the example, 1 + 15 = {{ pair.steps[0].sum }} is above 14, so 15 is in no pair.

Why does container most water move the shorter wall?

Any container using the shorter wall and a position inside the window is both narrower and still capped by that wall, so it cannot be larger. The scan evaluated {{ box.steps | length }} containers and found {{ box.best }}.

Why does three sum skip a fixed element equal to the previous one?

Every triple that starts with the earlier copy was already found, including those using the later copy as a middle element, so repeating the fixed value only produces duplicates. The example has three −1 values and still returns {{ three.triples | length }} distinct triples.

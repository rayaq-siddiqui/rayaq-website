Minimum spanning trees

A minimum spanning tree connects every node of a weighted undirected graph using the cheapest possible set of edges. Two greedy algorithms build it: Kruskal's takes the globally cheapest edge that does not close a cycle, and Prim's grows one tree outward from a start node. Both rest on one proof, the cut property.

Problem

You must link every point, city or server so that everything is reachable from everything else, paying for each link, and you want the total cost minimum. The answer has no cycles (a cycle's costliest edge would be wasted) and exactly n - 1 edges. Trying all subsets of edges is exponential; a greedy order is enough.

Intuition

Pretend you are laying cable. Start with the cheapest link you could ever lay, then the next cheapest, skipping any that would join two places that are already connected. That is Kruskal's. Or stand at one place and keep extending to the cheapest neighbor of everything you have wired up so far. That is Prim's. Both feel too naive to be optimal, and both are, for the same reason.

The cut property. Split the nodes into any two groups. The cheapest edge crossing between them belongs to some minimum spanning tree. Why: take any tree that lacks that edge; adding it creates a cycle, and that cycle must cross the split at a second edge that costs at least as much. Swapping that edge out for the cheapest one cannot make the tree more expensive. Kruskal's picks an edge that is the cheapest crossing out of one component, and Prim's picks the cheapest crossing out of the grown tree, so each pick is safe.

Mechanics

Kruskal's algorithm

Sort all edges by weight. Walk them in order; for each, ask union-find whether its endpoints are already in the same component. If not, take the edge and union them; if so, skip it, since it would close a cycle. Stop after n - 1 edges. If fewer than n - 1 were taken, the graph was not connected.

Prim's algorithm

Start at any node and push its edges onto a min-heap. Repeatedly pop the cheapest edge; if its far end is already in the tree, skip it, otherwise add the node and push that node's edges. It is Dijkstra's loop with the key changed from "distance from the start" to "weight of the single connecting edge".

Invariants

After every step the chosen edges are a subset of some minimum spanning tree (by the cut property), and they never form a cycle. When n - 1 edges are taken in a connected graph, the set is a spanning tree and so a minimum one. Ties can make the final tree differ between the two algorithms, but never the total.

Choosing between them

With an explicit edge list, Kruskal's is the shortest to write. With a dense or implicit graph, such as every pair of points, Prim's array version runs in O(n²) without ever listing the edges.

Implementation

def kruskal(n, edges):
    parent = list(range(n))

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    total = used = 0
    for u, v, w in sorted(edges, key=lambda e: e[2]):
        ru, rv = find(u), find(v)
        if ru != rv:
            parent[ru] = rv
            total += w
            used += 1
            if used == n - 1:
                break
    return total if used == n - 1 else -1


import heapq

def prim(n, graph):
    # graph[u] is a list of (weight, v)
    seen = {0}
    heap = list(graph[0])
    heapq.heapify(heap)
    total = 0
    while heap and len(seen) < n:
        w, v = heapq.heappop(heap)
        if v in seen:
            continue
        seen.add(v)
        total += w
        for item in graph[v]:
            if item[1] not in seen:
                heapq.heappush(heap, item)
    return total if len(seen) == n else -1

Variations and edge cases

def min_cost_connect_points(points):
    n = len(points)
    best = [float("inf")] * n
    best[0] = 0
    used = [False] * n
    total = 0
    for _ in range(n):
        u = min((i for i in range(n) if not used[i]), key=best.__getitem__)
        used[u] = True
        total += best[u]
        for v in range(n):
            if not used[v]:
                d = abs(points[u][0] - points[v][0]) + abs(points[u][1] - points[v][1])
                best[v] = min(best[v], d)
    return total
  • Disconnected graph. There is no spanning tree, only a spanning forest. Check the edge count and return the sentinel the problem asks for.
  • Maximum spanning tree. Sort descending (Kruskal) or negate the weights.
  • Ties. Several minimum trees can exist; the total is unique. Only the "critical edge" questions care which one you got.
  • Skip or force an edge. To classify an edge, rerun Kruskal with it removed (a higher total or a disconnection means it is critical) or with it forced in first (the same total means it can appear).
  • Dense graphs. Building all n² point pairs and sorting is O(n² log n); the array form of Prim's above is O(n²).
  • Edge cases: one node (cost 0), duplicate points (zero-cost edges), parallel edges (the cheapest wins), and self-loops (always skipped).

Complexity and tradeoffs

  • Kruskal's: O(E log E) for the sort, plus near-linear union-find work.
  • Prim's with a heap: O(E log V). With an array scan on a dense graph: O(V²).
  • Space: O(V + E) for the edges and heap or union-find.
  • Baseline. Enumerating spanning trees is exponential in general.
  • When it fails. The tree minimizes total weight, not distances between pairs, so use Dijkstra for routes. For directed graphs (minimum arborescence) you need Chu-Liu/Edmonds, which is rare in interviews.

Check yourself

Why can Kruskal's skip an edge whose ends are already connected?

The earlier edges already link them at no greater cost, so the new edge would close a cycle, and the costliest edge of any cycle is never needed. In the example, edge 0-1 at cost 4 is skipped because 0-2 (3) and 1-2 (1) already join them.

Why do Prim's and Kruskal's give different trees but equal totals on the example?

Two edges tie at cost 6 for reaching node 5, and the order in which each algorithm meets them differs. Either choice is a minimum tree of weight {{ kr.total }}; Prim's total is {{ pr.total }}.

How many edges does a spanning tree on n nodes have, and how do you tell the graph was disconnected?

Exactly n - 1. If the algorithm ends with fewer than n - 1 chosen edges (or the heap empties before every node is reached), no spanning tree exists. The helper reports connected as {{ kruskal_trace(3, [(0, 1, 1)]).connected }} for a 3-node graph with one edge.

How do you test whether an edge is in every minimum spanning tree?

Rebuild the tree with that edge removed. If the total rises or the graph disconnects, the edge is critical. If the total is unchanged but forcing the edge in also gives the minimum total, it is pseudo-critical.

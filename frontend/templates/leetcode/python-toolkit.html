The Python toolkit

Most interview solutions in Python are a handful of built-in containers used well. This page lists what list, dict, set, deque, heapq and bisect each cost per operation, shows how a heap and a binary search actually move, and collects the idioms (counting, grouping, sorting by key, default values) that the rest of this reference takes for granted.

Problem

An algorithm's complexity is only as good as the data structure underneath it. The same idea, "remove the oldest item", is O(1) on one container and O(n) on another, and picking the wrong one turns a linear solution into a quadratic one without any visible change in the code. Python also offers shortcuts, such as Counter and sorted(key=...), that replace twenty lines of loop with one.

The signals below tell you which tool to reach for. They also appear later in nearly every pattern page.

Intuition

Every container is a trade. A list is a row of boxes: reaching box k is instant, but squeezing a box in at the front means moving all the others along. A dict or set is a coat check: hand over a ticket (the hash of the key) and the attendant goes straight to the hook, without scanning the rack. A deque is a row you can add to or remove from at either end. A heap is a tournament bracket kept loosely sorted: only the champion is guaranteed to be on top, but keeping that true after every change takes just one walk up or down a tree.

So the skill is not memorizing syntax. It is asking "which operation will my loop repeat n times?" and choosing the container for which that operation is cheap.

The tree is only a way of reading the array. Index i has children 2i + 1 and 2i + 2, so no pointers are stored.

Why hash lookups are O(1)

A dict computes hash(key), turns it into a slot number, and checks that slot. If two keys land in the same slot, it probes nearby slots. As long as the table stays under a load limit and resizes (doubling, which is the amortized argument from the complexity analysis page), the expected number of probes is a constant. The caveat is that this is an average: adversarial keys that all collide would degrade it, which interview inputs don't do.

The heap invariant

A binary min-heap stores a complete binary tree in an array with one rule: every parent is less than or equal to both children. heappush appends to the end and sifts up, swapping with the parent while it is larger. heappop takes the root, moves the last element into the root slot and sifts down, swapping with the smaller child while it is larger than that child. A swap only ever fixes one violated pair and the tree has height ⌊log₂ n⌋, so each operation is O(log n). Python has only a min-heap. For a max-heap, push negated values.

The binary search invariant

bisect_left(a, x) returns the first index where a[index] >= x (or len(a) if there is none). The search keeps the answer inside the half-open range [low, high): if the middle value is smaller than x, everything up to the middle is too small, so low = middle + 1; otherwise the middle may itself be the answer, so high = middle. The range halves each time and ends with low == high, which is the answer. The halving argument bounds this at about log₂ n probes.

Variations and edge cases

  • Top-k with a bounded heap. Keep a min-heap of size k and push each new value, popping when the size exceeds k. The heap holds the k largest, in O(n log k). heapq.nlargest(k, nums) does this for you.
  • Lazy deletion. A heap cannot remove an arbitrary item cheaply. Leave stale entries in and skip them when they reach the top, checking against a dict of current values.
  • Tie-breaking. If two heap tuples have equal first elements, Python compares the second ones. Put an integer counter in the tuple when the second item (such as a node object) isn't orderable.
  • Mutable keys. [1, 2] can't be a dict key or set member; convert with tuple(...). Likewise [[0] * m] * n makes n references to one row: build a grid with [[0] * m for _ in range(n)].
  • Integer division and modulo. // floors toward negative infinity and % of a negative number is non-negative in Python, unlike C or Java. Use int(a / b) or math.trunc when a problem wants truncation toward zero.
  • Edge cases that break naive code: empty input, a single element, heappop on an empty heap (raises IndexError), and bisect_left returning len(a) when x is bigger than everything.

Complexity and tradeoffs

Emptying a list of 8 items with pop(0) moves {{ moves.list }} elements in total, against {{ moves.deque }} for deque.popleft, and the gap grows as n². That is the pattern: the right container turns n repeated O(n) steps into n repeated O(1) steps.

  • Memory. A set of n integers takes several times the memory of a list of them, because of the hash table's spare slots. The trade for O(1) lookup is nearly always worth it, unless the values fit a small integer range, where a plain boolean array is both smaller and faster.
  • Sorting first. If you only need membership, a set (O(n) to build) beats sorting plus binary search (O(n log n) to build). If you need order, ranges or neighbours, the sorted list wins.
  • Heap against sorting. A heap helps when items arrive over time or you only need the top k. When all the data is in hand and you need it all in order, one sort is simpler.
  • No balanced tree. Python has no built-in ordered set or sorted map. A sorted list with bisect gives O(log n) search but O(n) insertion, which is fine up to about 10⁵ elements; beyond that, think about a different pattern.
  • Hash-order assumptions. Dicts preserve insertion order, but sets do not. Never rely on set iteration order in an answer.

Check yourself

You process a queue of up to 10⁵ items by repeatedly calling queue.pop(0) on a list. What is wrong, and what is the fix?

Each pop(0) shifts the remaining elements, so the loop is O(n²) overall. Use collections.deque and popleft(), which is O(1).

After pushing 5, 3, 8, 1, 9, 2, is the heap array sorted? What is guaranteed?

No: it is [{% for v in trace.final %}{{ v }}{% if not loop.last %}, {% endif %}{% endfor %}]. Only the heap order is guaranteed: every parent is at most its children, so index 0 is the minimum.

What does bisect_left(a, x) return when x is larger than every element?

len(a), the position where x would be appended. Check the index against the length before reading a[index].

Why does grid = [[0] * 3] * 3 behave surprisingly when you set grid[0][0] = 1?

The outer multiplication copies a reference to the same inner list, so all three rows are one object. Build each row separately with a list comprehension.

Bellman-Ford and bounded paths

Bellman-Ford finds shortest paths when edges can be negative, and it does so by a plain idea: relax every edge, and repeat. After r rounds every node holds the cheapest cost using at most r edges. That round-by-round meaning is what makes it the right tool whenever a path may use only k edges, as in "at most k stops".

Problem

You want cheapest paths in a weighted graph where Dijkstra's greedy rule is not allowed: some edges are negative, or the question limits how many edges a path may use, or you must notice that costs can fall forever around a loop. The cheapest route may even be a longer one with more edges, which is exactly what the greedy settled-set argument cannot handle.

Intuition

Start with only the source known, at cost 0. A path with one edge from the source is found by looking at each edge once. A path with two edges is found by looking at each edge again, now that the first edge's far end has a cost. So each full pass over the edge list teaches the graph about paths one edge longer. A shortest path that avoids repeating a node has at most n - 1 edges, so n - 1 passes always suffice, and no cleverness about order is needed.

That also tells you how to impose a limit. If the cheapest route using at most 3 edges is what you want, run 3 passes and stop. The only care is to make each pass read the numbers from the end of the previous one, not from a table already updated in this pass, or a path can sneak in extra edges during one pass.

Mechanics

Relaxing an edge

To relax edge (u, v, w): if dist[u] + w < dist[v], set dist[v] to that smaller value. Unreached nodes hold infinity and are skipped. A round relaxes every edge once.

Invariant and proof

After round r, dist[v] is at most the cost of the cheapest path from the source to v that uses at most r edges (and is never below the true shortest distance, since it is always the cost of some real path). Induction on r: the cheapest path with r edges is a cheapest path with r - 1 edges to some node u, plus the edge (u, v); round r relaxes that edge using the round r - 1 value. A simple path has at most n - 1 edges, so after n - 1 rounds all shortest distances are final.

Negative cycles

If a cycle's total cost is negative and the source can reach it, going around again always lowers the cost, so no finite shortest distance exists and rounds never stop improving. Run one more round after n - 1: if any edge still relaxes, a reachable negative cycle exists. To find negative cycles anywhere in the graph, start all distances at 0 instead of only the source.

Bounding the number of edges

For "at most k stops" the path may use k + 1 edges. Run exactly k + 1 rounds, with each round writing to a copy so every edge read sees only paths from the previous round. Reading from the same table you are writing lets one round chain several edges, which breaks the limit.

Implementation

INF = float("inf")

def bellman_ford(n, edges, source):
    dist = [INF] * n
    dist[source] = 0
    for _ in range(n - 1):
        changed = False
        for u, v, w in edges:
            if dist[u] != INF and dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                changed = True
        if not changed:
            break
    for u, v, w in edges:
        if dist[u] != INF and dist[u] + w < dist[v]:
            return None  # a negative cycle is reachable
    return dist


def find_cheapest_price(n, flights, src, dst, k):
    prices = [INF] * n
    prices[src] = 0
    for _ in range(k + 1):
        nxt = prices[:]
        for u, v, w in flights:
            if prices[u] != INF and prices[u] + w < nxt[v]:
                nxt[v] = prices[u] + w
        prices = nxt
    return -1 if prices[dst] == INF else prices[dst]

Variations and edge cases

def has_negative_cycle(n, edges):
    dist = [0] * n
    for _ in range(n):
        changed = False
        for u, v, w in edges:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                changed = True
        if not changed:
            return False
    return True


from collections import deque

def spfa(n, graph, source):
    # queue-based speedup: re-relax only nodes whose distance just dropped
    dist = [INF] * n
    dist[source] = 0
    queue, queued = deque([source]), {source}
    while queue:
        u = queue.popleft()
        queued.discard(u)
        for v, w in graph[u]:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                if v not in queued:
                    queue.append(v)
                    queued.add(v)
    return dist
  • Copy per round for edge limits. Without the copy, one round may chain many edges.
  • Skip unreached nodes. Adding a weight to infinity is harmless in Python floats but guard it anyway so integer sentinels do not overflow.
  • Early exit. If a round changes nothing, later rounds cannot either; stop. Do not use that rule for the exact-k edge case, where fewer rounds is a different question.
  • Stops versus edges. k stops means k + 1 edges (flights). A common off-by-one is running k rounds.
  • Undirected negative edges form a negative cycle immediately (go back and forth), so treat them as directed or reject them.
  • Edge cases: source equals target, unreachable target (return the "not possible" value), k = 0, and parallel edges.

Complexity and tradeoffs

  • Time: O(V · E) for the full run; O(k · E) when limited to k rounds.
  • Space: O(V) for the distance list, plus another O(V) for the per-round copy.
  • Baseline. Enumerating paths is exponential. For non-negative weights Dijkstra is faster; this is the price paid for allowing negative edges and edge limits.
  • Versus Dijkstra with state. Cheapest Flights can also be solved by Dijkstra over states (city, stops used), which can be faster on sparse graphs; Bellman-Ford is shorter to write and clearly correct.
  • When it fails. With a reachable negative cycle there is no shortest path, only a report. All-pairs questions need Floyd-Warshall or Johnson's algorithm.

Problems

Cheapest Flights Within K Stops is the one list problem homed here: the stop limit turns the relaxation round count into the answer. Weighted problems with non-negative costs and no edge limit belong with Dijkstra.

Bellman-Ford is Dijkstra without the greedy assumption, and dynamic programming in disguise: the table after round r is a DP over "best cost with at most r edges". The negative-cycle check is the same idea that powers currency-arbitrage detection.

Check yourself

Why are n - 1 rounds enough when there is no negative cycle?

A cheapest path never repeats a node (repeating means a cycle, which cannot lower the cost), so it has at most n - 1 edges. After round r the table already covers every path of up to r edges. In the example the table stops changing after round {{ hist | length - 2 }}, well within 4 rounds.

Why must each round read from a copy when the path length is limited?

Updating in place lets a single pass chain several edges. In the flights example with one round, the in-place version reports a price of {{ live.history[-1][3] }} for city 3 through three flights, while the copy correctly leaves it unreachable.

How many rounds does "at most 2 stops" need?

Three, because 2 stops means 3 flights. In the example the cheapest price from city 0 to city 3 with 2 stops is {{ cheapest_flights_of(4, flights, 0, 3, 2) }}.

How do you detect a negative cycle?

Run one more round after n - 1. If any edge still relaxes, a negative cycle is reachable. Starting every distance at 0 finds cycles unreachable from one source; the three-node loop above is found: {{ has_negative_cycle_of(3, cyc) }}.

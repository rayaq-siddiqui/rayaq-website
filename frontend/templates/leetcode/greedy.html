Greedy algorithms

A greedy algorithm makes the locally best choice at every step and never looks back. That is fast and simple, and it is only correct when you can prove the local choice is safe. This page is about the two standard proofs, and about the habit of testing a greedy idea against a counterexample before trusting it.

Problem

Many problems ask for the best of an exponential number of arrangements: the fewest jumps, the longest feasible tour, the fewest groups. A greedy algorithm replaces the search by one pass in which each decision is final. It works when the problem has two properties. First, the greedy-choice property: some optimal solution contains the locally best first move. Second, optimal substructure: what remains after that move is a smaller problem of the same kind. When both hold, one pass is enough.

Intuition

Imagine packing for a trip with room for one more bag, and you always add the most useful item left. That is fine until two items turn out to be useful only together. The question is never "is this choice good?" but "can taking it ever stop me from reaching the best outcome?". If you can show it cannot, the choice is safe.

There are two reliable ways to show that. In an exchange argument you take any optimal solution that does something different from the greedy one and swap its first differing step for the greedy step. If the result is still valid and no worse, then the greedy choice is part of some optimal solution, and you repeat on what remains. In a stays-ahead argument you compare the greedy partial solution with any other after each step and show that greedy is never behind on the quantity that matters, such as farthest reach. Both are induction: a statement about the first step, then about the rest.

A greedy idea you cannot prove is only a guess. A good habit is to try to break it on a tiny input, three to five elements, before writing any code. Many wrong greedy ideas die on the first small counterexample.

Mechanics

Jump Game: farthest reach

Scan left to right with reach, the farthest index known to be reachable. At index i, if i > reach you cannot even stand here, so the end is unreachable. Otherwise update reach = max(reach, i + nums[i]). The end is reachable exactly when the scan never gets stuck. The proof is a stays-ahead argument: the set of reachable indices is always an unbroken run from 0 to reach, because any index below the reach can be stepped onto by shortening a jump, so one number describes the whole set.

Jump Game II: levels

To count the fewest jumps, treat each jump as one level of a breadth-first search. Level 0 is index 0. Level k+1 is every index past level k's end and up to the farthest reach of anything in level k. You never need a queue: keep the current level's end, the farthest reach seen, and a counter that increments when the scan reaches the end of the level. This is greedy because you commit to the whole range, not a particular jump, and widening it is always at least as good as any narrower choice.

Gas Station: restart after a failure

Stations on a loop give gas and need fuel to reach the next one. Keep a tank starting at some station. If the tank goes negative on the way to station j, then no station between the start and j can be a better start either: each of them would arrive at j with at most as much fuel as the failed start did, since the failed start had a non-negative tank on arriving at each of them. So restart at j + 1. If the total gas is at least the total cost, the last restart point works; otherwise nothing does. That one pass replaces trying every start, which is quadratic.

Each bar is the tank after that station when the journey began at the last restart. Amber bars are the failures that move the candidate start to the next station. Here the surplus is {{ gs.total }}, so a start exists, and it is station {{ gs.start }}.

Hand of Straights: start from the smallest

Split a hand of cards into groups of consecutive values of a fixed size. The smallest remaining card cannot join a group as anything but its first card, since every group it could be in needs a smaller card that is already gone. So it must start a group, which makes the choice forced, and the only question is whether the next values exist. Count the cards, walk the values in ascending order and, for each unused copy, consume the run of next values. If any is missing, the answer is no. The forced-choice argument is the simplest kind of exchange proof: there is nothing to exchange.

When greedy is wrong

With coins 1, 3 and 4 and a target of 6, taking the biggest coin first gives 4+1+1 (three coins), but 3+3 uses two. Selecting the shortest interval first, instead of the earliest-ending one, can also block two longer, compatible intervals. These are the cases where the local choice destroys something later; the DP pages handle them by trying every option.

Implementation

def can_jump(nums):
    reach = 0
    for i, step in enumerate(nums):
        if i > reach:
            return False
        reach = max(reach, i + step)
    return True


def min_jumps(nums):
    jumps = end = farthest = 0
    for i in range(len(nums) - 1):
        farthest = max(farthest, i + nums[i])
        if i == end:
            jumps += 1
            end = farthest
    return jumps


def can_complete_circuit(gas, cost):
    total = tank = start = 0
    for i in range(len(gas)):
        total += gas[i] - cost[i]
        tank += gas[i] - cost[i]
        if tank < 0:
            tank, start = 0, i + 1
    return start if total >= 0 else -1

Variations and edge cases

from collections import Counter


def is_n_straight_hand(hand, size):
    if len(hand) % size:
        return False
    counts = Counter(hand)
    for card in sorted(counts):
        need = counts[card]
        if need:
            for value in range(card, card + size):
                if counts[value] < need:
                    return False
                counts[value] -= need
    return True


def max_non_overlapping(intervals):
    intervals.sort(key=lambda pair: pair[1])
    kept, last_end = 0, float("-inf")
    for start, end in intervals:
        if start >= last_end:
            kept += 1
            last_end = end
    return kept
  • Unreachable end in Jump Game II. The loop above assumes the end is reachable. If it might not be, check farthest <= i and return early.
  • Single element. One index needs zero jumps and is trivially reachable; the loops handle this because the range is empty.
  • Counting whole runs. In the straights version, subtracting need from every value of the run handles duplicates in one step; subtracting one at a time works too but repeats work.
  • Sorting keys and ties. Sorting by end time needs a decision for equal ends; either order is fine for counting, but check this when you also output the chosen items.
  • Strict versus non-strict. Whether an interval starting exactly where another ends overlaps changes >= to >. Read the statement.
  • Gas total check. Without the total test, the restart point can look valid when the remaining stations were never checked against the earlier surplus.

Complexity and tradeoffs

  • Time: usually O(n) for a single pass, or O(n log n) when a sort comes first, as in interval and scheduling problems.
  • Space: O(1) for the scans above, O(n) for the counters.
  • Baseline. Trying every start or every sequence of jumps is quadratic to exponential, so greedy turns minutes into milliseconds on large inputs.
  • Versus DP. If a counterexample exists, use DP. Jump Game can be written as DP over "can I reach index i", which is O(n²) and always right; the greedy version is the optimisation, justified by the reach being an unbroken run.
  • When it fails. If a local choice can block a better global combination (weighted intervals, coin systems like 1, 3, 4), greedy gives a wrong answer silently. Test on small cases against brute force.

Check yourself

Why is the reachable set in Jump Game an unbroken run from index 0?

If you can reach index j, you can reach any index below j that you jumped over by taking a shorter jump on the last step. So the set has no gaps and one number, the farthest reach, describes it.

Why can no station between a failed start and the failure point be a better start?

The failed start arrived at each of those stations with a non-negative tank. Starting there instead throws that fuel away, so it reaches the failure point with no more fuel than before, and that was already not enough.

Why must the smallest remaining card start a group?

A group of consecutive values containing it as a later card would need a smaller card, but none remain. So it is the smallest value of its group, and the only open question is whether the following values exist. In the example the first group is {{ sg[0] | join(", ") }}.

Give a counterexample to "take the biggest coin first".

With coins 1, 3 and 4 and amount 6, greedy takes 4 then 1 then 1, three coins, while 3 plus 3 needs two. That is why change-making needs DP unless the coin system is known to be canonical.
